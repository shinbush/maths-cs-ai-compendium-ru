# Массивы и хеширование

*Массивы и хеш-таблицы — две наиболее фундаментальные структуры данных в программировании. В этом файле рассказывается, как они работают «под капотом», а затем выстраиваются ключевые шаблоны решения проблем; два указателя, скользящее окно, суммы префиксов и поиск на основе хеша, решение все более сложных задач, с типичными ошибками на каждом этапе.*

- Если вы глубоко разбираетесь в массивах и хэш-картах, вы можете решить около 40% всех проблем на собеседованиях по программированию. Эти две структуры появляются повсюду, потому что они предлагают две вещи, которые нужны алгоритмам больше всего: **быстрый индексированный доступ** (массивы) и **быстрый поиск по ключу** (хеш-карты).

- Этот файл обучает шаблонам, а не решениям. Цель состоит в том, чтобы, увидев новую проблему, вы поняли, какой шаблон применим и почему, а не пытались вспомнить заученное решение.

## Массивы

- **Массив** – это непрерывный блок памяти, элементы которого хранятся с фиксированными смещениями. Доступ к элементу $i$ стоит $O(1)$, поскольку адрес просто `base + i * element_size`. Это самый быстрый доступ к данным, и именно поэтому массивы являются выбором по умолчанию.

- **Динамические массивы** (`list` в Python, `ArrayList` в Java, `vector` в C++) автоматически увеличиваются при заполнении. Стратегия заключается в **амортизированном удвоении**: когда массив заполнен, выделите новый массив удвоенного размера и скопируйте все заново. Копия стоит $O(n)$, но это случается настолько редко (каждая вставка $n$), что амортизированная стоимость каждой вставки равна $O(1)$.

- **Локальность кэша** — вот почему массивы работают быстро на практике, а не только в теории. Поскольку элементы хранятся последовательно, доступ к одному элементу загружает соседние элементы в кэш ЦП (глава 13). Итерация по массиву удобна для кэша; следующих указателей в связанном списке нет. На практике эта разница в постоянных коэффициентах может составлять 10–100 раз.

| Операция | Массив | Динамический массив |
|-----------|-------|---------------|
| Доступ по индексу | $O(1)$ | $O(1)$ |
| Добавить | н/д | $O(1)$ амортизирован |
| Вставьте в позицию $i$ | $O(n)$ | $O(n)$ |
| Удалить в позиции $i$ | $O(n)$ | $O(n)$ |
| Поиск (несортированный) | $O(n)$ | $O(n)$ |

- **Подводная ошибка**: вставка или удаление в середине массива требует $O(n)$, поскольку все последующие элементы должны быть сдвинуты. Если вам нужны частые вставки посередине, рассмотрите связанный список или полностью другой подход.

## Строки

– **строка** – это массив символов. В Python строки неизменяемы: каждая конкатенация создает новую строку. Построение строки посимвольно в цикле — это $O(n^2)$, поскольку каждая конкатенация копирует всю строку.

```python
# BAD: O(n^2) string concatenation
s = ""
for c in characters:
    s += c  # copies entire string each time

# GOOD: O(n) using a list then join
parts = []
for c in characters:
    parts.append(c)
s = "".join(parts)
```

- **Подводный камень**: в Python `s += c` внутри цикла является одной из наиболее распространенных ошибок производительности. Всегда собирайте в список и `.join()`.

- **Кодировка**: ASCII использует 7 бит (128 символов). **UTF-8** имеет переменную длину: символы ASCII используют 1 байт, символы с диакритическими знаками — 2, китайские/японские символы — 3, смайлы — 4. Когда в задаче говорится «строчные английские буквы», размер алфавита равен 26, что означает, что вместо хэш-карты можно использовать массив фиксированного размера.

## Хэш-таблицы

- **хеш-таблица** сопоставляет ключи со значениями с помощью поиска, вставки и удаления $O(1)$ в среднем случае. Он работает путем вычисления **хеш-функции** $h(key)$, которая преобразует ключ в индекс массива.

– Хэш-функция должна быть: **детерминированной** (один и тот же ключ всегда дает один и тот же хэш), **единообразной** (ключи распределяются равномерно по сегментам) и **быстрой** для вычисления.

- **Коллизии** возникают, когда два разных ключа хэшируют один и тот же индекс. Две основные стратегии:

    - **Цепочка**: в каждом сегменте хранится связанный список пар ключ-значение. При столкновении добавить в список. В худшем случае (все ключи хешируются в одном сегменте): $O(n)$. Средний случай с хорошей хэш-функцией: $O(1)$.- **Открытая адресация**: при коллизии искать следующий пустой слот. **Линейное зондирование** проверяет следующий слот, затем следующий и т. д. Он удобен для кэша, но страдает от **кластеризации** (длительного использования занятых слотов). **Хеширование Робин Гуда** уменьшает дисперсию, вытесняя записи, которые «ближе к дому».

- **Коэффициент загрузки** $\alpha = n / m$ (предметы/ковши) определяет производительность. Когда $\alpha$ превышает пороговое значение (обычно 0,75), таблица **перехэшируется**: выделяется таблица большего размера и повторно вставляются все элементы. Это стоит $O(n)$, но случается нечасто.

- **Хеш-карты** (`dict` в Python, `HashMap` в Java) хранят пары ключ-значение. **Наборы хешей** (`set` в Python, `HashSet` в Java) хранят только ключи (используются для быстрого тестирования членства).

| Операция | Средний | Худший случай |
|-----------|---------|------------|
| Поиск | $O(1)$ | $O(n)$ |
| Вставить | $O(1)$ | $O(n)$ |
| Удалить | $O(1)$ | $O(n)$ |

- **Фильтры Блума** представляют собой компактные вероятностные наборы. Они могут сказать вам «определенно не в наборе» или «вероятно в наборе» (с настраиваемой частотой ложных срабатываний). Они используют хеш-функции $k$ и битовый массив. Используется в базах данных (избегайте чтения с диска при отсутствии ключей), веб-кешах и средствах проверки орфографии.

- **Когда брать хэш-карту**: всякий раз, когда вам нужно ответить «видел ли я это раньше?» или «какое количество/индекс/значение связано с этим ключом?» в $O(1)$. Если вы выполняете повторяющиеся линейные сканирования в поисках чего-либо, хеш-карта почти наверняка сделает это быстрее.

## Шаблон: поиск по хеш-карте

- Самый простой шаблон: используйте хэш-карту для замены сканирований $O(n)$ на поиски $O(1)$.

### Легко: две суммы

- **Проблема**: учитывая массив целых чисел и цель, вернуть индексы двух чисел, которые в сумме дают цель.

- **Перебор** $O(n^2)$: проверьте каждую пару.

- **Понимание шаблона**: для каждого числа `num` необходимо, чтобы где-то в массиве существовал `target - num`. Вместо того, чтобы сканировать массив на предмет этого, сохраните ранее увиденные числа в хэш-карте.

```python
def two_sum(nums, target):
    seen = {}  # value -> index
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
```

- **Почему это работает**: один проход по массиву. Для каждого элемента поиск по хеш-карте — $O(1)$. Итого: $O(n)$ время, $O(n)$ пространство.

- **Подводная ошибка**: не добавляйте текущий номер в хеш-карту перед проверкой дополнения, иначе вы можете сопоставить элемент сам с собой. Порядок в приведенном выше коде правильный: сначала проверьте, затем вставьте.

### Средний: групповые анаграммы

- **Задача**: учитывая список строк, сгруппируйте анаграммы вместе. («есть», «чай», «кушать») — одна группа.

- **Понимание шаблонов**: в анаграммах одни и те же символы расположены в разном порядке. Если вы сортируете каждую строку, анаграммы создают один и тот же отсортированный ключ. Используйте этот отсортированный ключ в качестве ключа хэш-карты.

```python
from collections import defaultdict

def group_anagrams(strs):
    groups = defaultdict(list)
    for s in strs:
        key = tuple(sorted(s))  # or use character count tuple
        groups[key].append(s)
    return list(groups.values())
```

- **Оптимизация**: стоимость сортировки каждой строки составляет $O(k \log k)$, где $k$ — длина строки. Для более быстрого ключа подсчитайте частоты символов и используйте кортеж счетчика в качестве ключа:

```python
def group_anagrams_fast(strs):
    groups = defaultdict(list)
    for s in strs:
        count = [0] * 26
        for c in s:
            count[ord(c) - ord('a')] += 1
        groups[tuple(count)].append(s)
    return list(groups.values())
```

- Это $O(k)$ для каждой строки вместо $O(k \log k)$. Кортеж количества символов представляет собой **каноническую форму**: представление, одинаковое для всех членов группы.

- **Подводная ошибка**: в Python списки не хэшируются (не могут быть ключами dict). Вы должны преобразовать в кортеж. Это сбивает людей с толку, когда они пробуют `groups[count].append(s)`.

### Сложно: самая длинная последовательная последовательность

- **Задача**: по несортированному массиву найти длину самой длинной последовательной последовательности (например, [100, 4, 200, 1, 3, 2] → 4, потому что [1, 2, 3, 4]).

- **Грубая сила** $O(n \log n)$: отсортируйте массив, затем просканируйте его на наличие последовательных запусков.

- **Анализ шаблонов**: поместите все числа в хеш-набор для поиска $O(1)$. Для каждого числа проверьте, является ли оно **началом** последовательности (т. е. `num - 1` отсутствует в наборе). Если да, посчитайте, как далеко простирается последовательность.

```python
def longest_consecutive(nums):
    num_set = set(nums)
    best = 0

    for num in num_set:
        # only start counting from the beginning of a sequence
        if num - 1 not in num_set:
            length = 1
            while num + length in num_set:
                length += 1
            best = max(best, length)

    return best
```- **Почему $O(n)$**: внутренний цикл `while` выполняется не более $n$ раз во всех итерациях (каждое число посещается не более двух раз: один раз во внешнем цикле, один раз в расширении `while`). Защита `if num - 1 not in num_set` гарантирует, что мы начнем отсчет только с начала последовательности.

- **Подводная ошибка**: без проверки `if num - 1 not in num_set` вы начнете считать с каждого элемента, в худшем случае это будет $O(n^2)$ (например, [1, 2, 3, ..., n] будет сканировать всю последовательность с каждой начальной точки).

## Узор: два указателя

- В шаблоне **два указателя** используются два индекса, которые перемещаются по массиву, обычно с противоположных концов или с одного и того же конца с разной скоростью. Это работает, когда массив отсортирован или когда вам нужно сравнить пары.

- **Когда использовать**: проблема связана с парами, подмассивами или секционированием, а массив отсортирован (или может быть отсортирован без потери необходимой информации).

### Легко: действительный палиндром

- **Задача**: определить, является ли строка палиндромом, учитывая только буквенно-цифровые символы и игнорируя регистр.

- **Шаблон**: один указатель в начале, один в конце. Переместите их внутрь, сравнивая персонажей.

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1

    while left < right:
        # skip non-alphanumeric characters
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1

        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True
```

- **Подводная ошибка**: игнорирование проверки `left < right` внутри внутренних циклов while. Без него указатель может выйти за пределы строк типа "!!!" (все не буквенно-цифровые).

### Средний: три суммы

- **Задача**: найти в массиве все уникальные тройки, сумма которых равна нулю.

- **Шаблон**: сортировка массива. Исправьте один элемент, затем используйте два указателя на оставшуюся часть, чтобы найти пары, сумма которых равна отрицанию фиксированного элемента.

```python
def three_sum(nums):
    nums.sort()
    result = []

    for i in range(len(nums) - 2):
        # skip duplicate fixed elements
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        left, right = i + 1, len(nums) - 1
        target = -nums[i]

        while left < right:
            total = nums[left] + nums[right]
            if total < target:
                left += 1
            elif total > target:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                # skip duplicates
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1

    return result
```

- **Почему это работает**: сортировка $O(n \log n)$. Для каждого фиксированного элемента сканирование по двум указателям имеет вид $O(n)$. Итого: $O(n^2)$, что оптимально для данной задачи (необходимо учитывать все пары).

- **Подводная ошибка**: обработка дубликатов — самая сложная часть. Без логики пропуска дубликатов (как для фиксированного элемента, так и для результатов с двумя указателями) вы вернете повторяющиеся тройки. Строка `if i > 0 and nums[i] == nums[i-1]: continue` имеет решающее значение.

### Сложно: Удержание дождевой воды

- **Задача**: по карте высот (массив неотрицательных целых чисел) вычислить, сколько воды она может удержать после дождя.

- **Понимание шаблона**: для каждой позиции уровень воды определяется минимумом максимальной высоты слева и максимальной высотой справа от нее за вычетом текущей высоты. Два указателя с обоих концов отслеживают эти текущие максимумы.

```python
def trap(height):
    left, right = 0, len(height) - 1
    left_max, right_max = 0, 0
    water = 0

    while left < right:
        if height[left] < height[right]:
            if height[left] >= left_max:
                left_max = height[left]
            else:
                water += left_max - height[left]
            left += 1
        else:
            if height[right] >= right_max:
                right_max = height[right]
            else:
                water += right_max - height[right]
            right -= 1

    return water
```

- **Почему это работает**: ключевой вывод заключается в том, что если `height[left] < height[right]`, вода в позиции `left` ограничена `left_max` (мы знаем, что с правой стороны есть более высокая полоса, поэтому правая сторона не может быть узким местом). Обрабатываем короткую сторону, гарантируя, что на другой стороне стержень будет повыше.

- **Подводная ошибка**: многие люди пытаются сначала предварительно вычислить массивы `left_max[i]` и `right_max[i]` (это работает, но использует пространство $O(n)$). Двухочковый подход обеспечивает пространство $O(1)$. Кроме того, путаница `>=` с `>` в максимальных обновлениях может привести к отклонению расчетов воды на единицу.

## Узор: раздвижное окно

– Шаблон **скользящего окна** поддерживает окно (непрерывный подмассив), которое расширяется и сжимается по мере итерации. Это работает для задач, задающих вопросы о подмассивах или подстроках, которые удовлетворяют некоторым условиям.

- **Когда использовать**: задача запрашивает самый длинный/самый короткий подмассив или подстроку, удовлетворяющую ограничению, а расширение/сжатие окна является монотонным (добавление элементов может только усложнить/облегчить выполнение ограничения, но не то и другое одновременно).

- **Шаблон**:

```python
def sliding_window(arr):
    left = 0
    state = ...  # window state (counts, sum, etc.)
    best = ...

    for right in range(len(arr)):
        # expand: add arr[right] to the window state
        update_state(state, arr[right])

        # contract: shrink from the left while constraint is violated
        while constraint_violated(state):
            remove_from_state(state, arr[left])
            left += 1

        # update answer
        best = max(best, right - left + 1)  # or min, depending on problem

    return best
```

### Легко: лучшее время для покупки и продажи акций

- **Задача**: учитывая дневные цены, найти максимальную прибыль от одной покупки и одной продажи (покупка перед продажей).

- **Шаблон**: отслеживайте минимальную цену, наблюдаемую на данный момент (левая граница окна), и рассчитывайте прибыль за каждый день.

```python
def max_profit(prices):
    min_price = float('inf')
    max_profit = 0

    for price in prices:
        min_price = min(min_price, price)
        max_profit = max(max_profit, price - min_price)

    return max_profit
```

- Это вырожденное скользящее окно: левый указатель (минимальная цена) перемещается вперед только при обнаружении нового минимума. $O(n)$ время, $O(1)$ пространство.### Средний: самая длинная подстрока без повторяющихся символов

- **Задача**: найти длину самой длинной подстроки без повторяющихся символов.

- **Шаблон**: разверните окно, переместив `right`. Когда дубликат найден, сжимайте слева, пока дубликат не будет удален.

```python
def length_of_longest_substring(s):
    char_index = {}  # character -> its most recent index
    left = 0
    best = 0

    for right, char in enumerate(s):
        if char in char_index and char_index[char] >= left:
            left = char_index[char] + 1  # jump past the duplicate

        char_index[char] = right
        best = max(best, right - left + 1)

    return best
```

- **Почему `char_index[char] >= left`**: персонаж мог находиться на карте еще до запуска текущего окна. Без этой проверки вы могли бы неправильно сжать окно для персонажа, которого на самом деле нет в текущем окне.

- **Подводный камень**: использовать набор и удалять символы по одному слева — это правильно, но медленнее. Подход с использованием хэш-карты сразу переходит в нужную позицию.

### Hard: минимальная подстрока окна

- **Проблема**: по строкам `s` и `t` найти минимальное окно в `s`, содержащее все символы `t`.

- **Шаблон**: разверните окно, чтобы включить все необходимые символы, затем сверните слева, чтобы найти минимальное допустимое окно.

```python
from collections import Counter

def min_window(s, t):
    if not t or not s:
        return ""

    need = Counter(t)       # characters we need and their counts
    have = 0                # how many unique characters we have in sufficient quantity
    required = len(need)    # how many unique characters we need

    left = 0
    best = (float('inf'), 0, 0)  # (length, left, right)

    window_counts = {}

    for right in range(len(s)):
        char = s[right]
        window_counts[char] = window_counts.get(char, 0) + 1

        # check if this character's count now meets the requirement
        if char in need and window_counts[char] == need[char]:
            have += 1

        # contract from the left while the window is valid
        while have == required:
            # update best
            if (right - left + 1) < best[0]:
                best = (right - left + 1, left, right)

            # remove leftmost character
            left_char = s[left]
            window_counts[left_char] -= 1
            if left_char in need and window_counts[left_char] < need[left_char]:
                have -= 1
            left += 1

    length, start, end = best
    return s[start:end + 1] if length != float('inf') else ""
```

- **Подводный камень**: счетчик `have` является решающей оптимизацией. Без него вам пришлось бы сравнивать весь словарь `window_counts` с `need` на каждом шаге, что составляет $O(|\text{unique chars}|)$ на шаг. Счетчик `have` выполняет проверку достоверности $O(1)$.

- **Подводная ошибка**: проверка `window_counts[char] == need[char]` (а не `>=`) гарантирует, что мы увеличим `have` ровно один раз для каждого символа. Если бы мы использовали `>=`, мы бы пересчитали.

## Шаблон: суммы префиксов

- Массив **префиксной суммы** хранит совокупные суммы: `prefix[i] = sum(arr[0:i])`. После создания $O(n)$ любая сумма подмассива может быть вычислена в $O(1)$: `sum(arr[l:r]) = prefix[r] - prefix[l]`.

```python
def build_prefix(arr):
    prefix = [0] * (len(arr) + 1)
    for i in range(len(arr)):
        prefix[i + 1] = prefix[i] + arr[i]
    return prefix

# sum of arr[l:r] (inclusive l, exclusive r)
def range_sum(prefix, l, r):
    return prefix[r] - prefix[l]
```

- **Когда использовать**: проблема связана с несколькими запросами суммы подмассивов или поиском подмассивов с определенной суммой.

### Просто: запрос суммы диапазона

- **Задача**: учитывая массив, ответьте на несколько запросов «Какова сумма от индекса $l$ до $r$?»

- Без префиксных сумм: каждый запрос имеет вид $O(n)$. С префиксными суммами: предварительное вычисление $O(n)$, затем $O(1)$ для каждого запроса.

### Средний: сумма подмассива равна K

- **Проблема**: подсчитать количество смежных подмассивов, сумма которых равна $k$.

- **Понимание шаблона**: сумма подмассива от индекса $l$ до $r$ равна `prefix[r+1] - prefix[l]`. Мы хотим, чтобы это значение было равно $k$, поэтому `prefix[l] = prefix[r+1] - k`. Для каждой позиции подсчитайте, сколько сумм предыдущих префиксов равны `current_prefix - k`, используя хеш-карту.

```python
def subarray_sum(nums, k):
    count = 0
    prefix = 0
    prefix_counts = {0: 1}  # empty prefix sum

    for num in nums:
        prefix += num
        # how many earlier prefix sums equal prefix - k?
        count += prefix_counts.get(prefix - k, 0)
        prefix_counts[prefix] = prefix_counts.get(prefix, 0) + 1

    return count
```

- Это объединяет суммы префиксов с поиском по хеш-карте: время $O(n)$, пространство $O(n)$.

- **Подводная ошибка**: забыть инициализировать `prefix_counts = {0: 1}`. Пустой префикс (перед любым элементом) имеет сумму 0. Без этого вы пропустите подмассивы, начиная с индекса 0.

### Hard: произведение массива, кроме себя

- **Проблема**: учитывая массив, вернуть массив, в котором каждый элемент является произведением всех остальных элементов. Вы не можете использовать деление.

- **Шаблон**: создайте префиксные продукты слева и суффиксные продукты справа. Ответ каждой позиции — `left_product * right_product`.

```python
def product_except_self(nums):
    n = len(nums)
    result = [1] * n

    # left pass: result[i] = product of nums[0..i-1]
    prefix = 1
    for i in range(n):
        result[i] = prefix
        prefix *= nums[i]

    # right pass: multiply by product of nums[i+1..n-1]
    suffix = 1
    for i in range(n - 1, -1, -1):
        result[i] *= suffix
        suffix *= nums[i]

    return result
```

- $O(n)$ время, $O(1)$ дополнительное пространство (выходной массив не учитывается). При этом сам выходной массив используется для хранения продуктов промежуточных префиксов, а затем умножается на продукты суффиксов на втором проходе.

- **Подводная ошибка**: если массив содержит ноль, подходы, основанные на делении, не работают. Этот подход с префиксами и суффиксами правильно обрабатывает нули, поскольку они никогда не делятся.

## Резюме распространенных ошибок| ловушка | Пример | Исправить |
|---------|---------|-----|
| Смещение на единицу по размеру окна | `right - left` против `right - left + 1` | Нарисуйте пример из двух элементов |
| Изменяемое значение по умолчанию в Python | `def f(seen={})` разделяет состояние между вызовами | Используйте `def f(seen=None)` |
