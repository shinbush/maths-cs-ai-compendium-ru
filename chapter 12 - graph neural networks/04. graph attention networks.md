# Сети графического внимания

*Сети внимания к графам заменяют однородное агрегирование соседей изученным, зависящим от данных взвешиванием. В этом файле описаны GAT, внимание к многоголовым графам, GATv2, преобразователи графов, позиционные и структурные кодировки, а также масштабируемость*.

- В GCN (файл 3) каждый узел объединяет характеристики своих соседей, используя фиксированные веса, определяемые структурой графа (нормализованная смежность). Узел с тремя соседями придает каждому соседу примерно одинаковый вес ($\approx 1/3$). Но не все соседи одинаково важны: сообщение от близкого сотрудника должно иметь большее значение, чем сообщение от дальнего знакомого.

- **Сети внимания на графах** решают эту проблему, изучая **каких соседей следует учитывать**, используя тот же механизм внимания, который питает трансформаторы (глава 7). Вместо фиксированных, основанных на структуре весов, каждый узел вычисляет динамические, основанные на содержании оценки внимания к своим соседям.

## GAT: сеть внимания к графам

- **GAT** (Величкович и др., 2018) вычисляет коэффициенты внимания между каждым узлом и его соседями. Для узла $i$ и соседа $j$:

$$e_{ij} = \text{LeakyReLU}\left(\mathbf{a}^T \left[W\mathbf{h}_i \| W\mathbf{h}_j\right]\right)$$

- где $W \in \mathbb{R}^{d' \times d}$ — общее линейное преобразование, $\|$ — конкатенация, а $\mathbf{a} \in \mathbb{R}^{2d'}$ — обучаемый вектор внимания. Оценка $e_{ij}$ показывает, насколько важны функции узла $j$ для узла $i$.

- Необработанные оценки нормализуются по всем соседям с использованием softmax:

$$\alpha_{ij} = \text{softmax}_j(e_{ij}) = \frac{\exp(e_{ij})}{\sum_{k \in \mathcal{N}(i)} \exp(e_{ik})}$$

- Это гарантирует, что сумма весов внимания будет равна 1 в окрестности каждого узла, точно так же, как внимание трансформатора (глава 7). Обновленные функции узла:

$$\mathbf{h}_i' = \sigma\left(\sum_{j \in \mathcal{N}(i)} \alpha_{ij} W\mathbf{h}_j\right)$$

![GCN assigns fixed equal weights to all neighbours; GAT learns data-dependent attention weights](../images/gat_attention_weights.svg)

- Принципиальное отличие от GCN: веса $\alpha_{ij}$ **изучаются из данных**, а не фиксируются структурой графа. Узел может научиться концентрироваться на наиболее информативных соседях, игнорируя шумных или нерелевантных.

- Обратите внимание, что внимание вычисляется только по ребрам (узел $i$ обрабатывает только своих соседей $\mathcal{N}(i)$), а не по всем парам узлов. Это сохраняет вычисления пропорциональными количеству ребер, а не квадрату количества узлов.

## Многоглавый граф Внимание

- Как и в трансформаторах (глава 7), **множественное внимание** параллельно запускает независимые механизмы внимания $K$, каждый со своими параметрами $W^k$ и $\mathbf{a}^k$. Результаты объединяются (в промежуточных слоях) или усредняются (в конечном слое):

$$\mathbf{h}_i' = \Big\|_{k=1}^{K} \sigma\left(\sum_{j \in \mathcal{N}(i)} \alpha_{ij}^k W^k \mathbf{h}_j\right)$$

- Каждый руководитель может заниматься разными аспектами окрестности: один руководитель может сосредоточиться на структурных особенностях, другой – на семантическом сходстве. Это та же мотивация, что и многоголовое внимание у трансформеров: разные головы фиксируют разные типы отношений.

- При использовании головок $K$ и выходного размера $d'$ на головку объединенный выход имеет размер $K \times d'$. Последний слой обычно усредняет, а не объединяет, чтобы получить выходные данные фиксированного размера.

## GATv2: устранение статического внимания

- Оригинальный GAT имеет небольшое ограничение: его функция внимания **статична** (также называемая ранжирующей). Оценка внимания зависит от конкатенации $[W\mathbf{h}_i \| W\mathbf{h}_j]$, но поскольку вектор внимания $\mathbf{a}$ применяется после конкатенации, его можно разложить на два независимых компонента: $\mathbf{a}^T [W\mathbf{h}_i \| W\mathbf{h}_j] = \mathbf{a}_1^T W\mathbf{h}_i + \mathbf{a}_2^T W\mathbf{h}_j$.

- Это означает, что рейтинг соседей для данного узла $i$ полностью определяется характеристиками соседей $\mathbf{h}_j$ (термин $\mathbf{a}_1^T W\mathbf{h}_i$ является постоянным для всех соседей $i$). Рейтинг внимания на самом деле не зависит от особенностей узла запроса. Узел $i$ и узел $k$ будут одинаково ранжировать один и тот же набор соседей, что ограничивает выразительность.

- **GATv2** (Brody et al., 2022) исправляет это, применяя нелинейность перед вектором внимания:

$$e_{ij} = \mathbf{a}^T \text{LeakyReLU}\left(W \left[\mathbf{h}_i \| \mathbf{h}_j\right]\right)$$- Перемещение LeakyReLU внутрь вычислений означает, что оценка внимания является нелинейной функцией функций суставов, не поддающейся разложению на независимые члены. Это делает внимание **динамичным**: рейтинг соседей теперь зависит от конкретного узла запроса. GATv2 более выразителен, чем GAT, и не требует дополнительных вычислительных затрат.

## Трансформаторы графов

- Стандартные GNN для передачи сообщений ограничены топологией графа: узел может обслуживать только своих прямых соседей. После слоев $k$ информация от соседей по переходу $k$ смешивалась на нескольких этапах агрегации, теряя точность. Это локальное узкое место (в сочетании с чрезмерным сглаживанием, файл 3) ограничивает возможность захвата долгосрочных зависимостей.

- **Преобразователи графов** устраняют это узкое место, применяя **глобальное самообслуживание** ко всем парам узлов, независимо от того, имеют ли они общее ребро. Каждый узел может обслуживать любой другой узел на одном уровне, как в стандартном преобразователе (глава 7).

— Основная идея: относиться ко всем узлам как к токенам и применять самообслуживание преобразователя:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

- где $Q = XW_Q$, $K = XW_K$, $V = XW_V$ - проекции запроса, ключа и значения признаков узла $X$ (точно как в главе 7). Это GNN на полносвязном графе (полный граф $K_n$, файл 2).

- Проблема: полностью связный граф игнорирует реальную структуру графа. Краевая информация (кто с кем на самом деле подключен) теряется. Два подхода восстанавливают это:

- **Graphormer** (Ying et al., 2021) вводит структуру графа в преобразователь посредством **членов смещения** в показателях внимания:

$$A_{ij} = \frac{(\mathbf{h}_i W_Q)(W_K^T \mathbf{h}_j^T)}{\sqrt{d_k}} + b_{\text{spatial}}(i, j) + b_{\text{edge}}(i, j)$$

- Пространственное смещение $b_{\text{spatial}}$ кодирует расстояние кратчайшего пути между узлами $i$ и $j$. Смещение ребер $b_{\text{edge}}$ кодирует ребра вдоль кратчайшего пути. Кроме того, Graphormer использует **центральное кодирование**, которое добавляет степень узла к его входному внедрению, предоставляя модели информацию о структурной роли каждого узла.

- **GPS** (General, Powerful, Scalable Graph Transformer, Rampášek et al., 2022) сочетает в себе локальную передачу сообщений с глобальным вниманием на каждом уровне:

$$\mathbf{h}_i' = \text{MLP}\left(\mathbf{h}_i^{\text{MPNN}} + \mathbf{h}_i^{\text{Attention}}\right)$$

- Каждый уровень применяет как стандартную GNN (для локальной структуры), так и преобразователь (для глобального контекста), а затем объединяет результаты. Это берет лучшее из обоих миров: локальную структуру от передачи сообщений и долгосрочные зависимости от внимания.

## Позиционные и структурные кодировки

- Трансформаторы последовательностей используют позиционное кодирование (глава 7) для ввода информации о порядке. Графы не имеют канонического порядка, поэтому необходимы кодировки, специфичные для графов.

- **Кодировки собственных векторов Лапласа** используют собственные векторы лапласиана графа (файл 2) в качестве позиционных признаков. Наименьшие нетривиальные собственные векторы $k$ обеспечивают спектральное вложение графа: узлы, находящиеся «близко» в графе, имеют схожие значения собственных векторов. Они объединены с функциями узла.

- Тонкость: собственные векторы Лапласа имеют неоднозначность знака (если $\mathbf{u}$ является собственным вектором, то же самое относится и к $-\mathbf{u}$). Модель должна быть инвариантной к этим изменениям знака. Решения включают использование случайных переворотов знаков в качестве дополнения данных во время обучения или обучение знаково-инвариантным преобразованиям.

- **Кодировки случайного блуждания** вычисляют вероятность случайного блуждания, начинающегося с узла $i$, и возвращающегося в узел $i$ после шагов $k$ для $k = 1, 2, \ldots, K$. Эти вероятности кодируют локальную структурную информацию: узлы в плотных кластерах имеют высокие вероятности возврата, а узлы в разреженных регионах — низкие. Вероятность приземления $p_{ii}^{(k)} = (A_{\text{rw}}^k)_{ii}$, где $A_{\text{rw}} = D^{-1}A$ — матрица перехода случайного блуждания.

- **Кодирование степеней** просто добавляет степень узла в качестве функции. Это удивительно эффективно, поскольку степень является сильным структурным сигналом: конечные узлы (степень 1), узлы-мосты и узлы-концентраторы ведут себя по-разному.- Эти кодировки предоставляют структурную информацию, которой не хватает ванильным преобразователям, что позволяет преобразователям графов превосходить стандартные GNN для передачи сообщений в задачах, требующих долгосрочного рассуждения.

## Масштабируемость

- Фундаментальная проблема масштабируемости GNN заключается в том, что графы могут иметь миллионы узлов и миллиарды ребер. Обучение GNN на полном графе требует хранения всех функций узла и всей матрицы смежности в памяти, что часто неосуществимо.

- **Мини-пакетное обучение** для GNN более сложное, чем для изображений или последовательностей, поскольку узлы взаимосвязаны. Для простой выборки пакета узлов требуются их соседи (уровень 1), соседи их соседей (уровень 2) и так далее. Этот **взрыв соседства** означает, что пакету из 1000 целевых узлов могут потребоваться миллионы узлов в вычислительном графе.

- **Выборка соседей** (стиль GraphSAGE, файл 3) ограничивает взрыв путем выборки фиксированного количества соседей на узел на уровне. При двух слоях и 15 выборках на слой подграф каждого целевого узла содержит не более узлов $15^2 = 225$, независимо от полного размера графа.

- **Cluster-GCN** (Чианг и др., 2019) разбивает граф на кластеры с помощью алгоритма кластеризации графов (например, METIS), а затем обучает по одному кластеру за раз. Ребра внутри кластера плотные (большинство соседей находятся в одном кластере), поэтому подграф отражает соответствующую структуру. Межкластерные ребра обрабатываются путем периодического включения ребер между кластерами.

- **Масштабируемость Graph Transformer** сложнее, поскольку глобальное внимание $O(n^2)$. Для графов с миллионами узлов полное внимание невозможно. Решения включают в себя:
    - Разреженные шаблоны внимания (обращайтесь только к ближайшим к $k$ узлам графа)
    - Приближения линейного внимания
    - Сочетание локальной передачи сообщений (дешево, $O(|E|)$) с глобальным вниманием на огрубленном графе (меньше узлов)

## Временные и динамические графики

- Графы, которые мы изучали до сих пор, являются **статическими**: узлы, ребра и объекты фиксированы. Но многие реальные графики **эволюционируют со временем**: к социальным сетям присоединяются новые пользователи, финансовые транзакции создают преимущества, структура трафика меняется в течение дня, а молекулярные взаимодействия колеблются.

- **Временный граф** дополняет каждое ребро меткой времени: $(i, j, t)$ означает, что узел $i$ взаимодействовал с узлом $j$ в момент времени $t$. Задача состоит в том, чтобы изучить представления, которые отражают как структуру графа, так и временную динамику.

- Есть две парадигмы:

- **Динамические графики дискретного времени (DTDG)**: график представлен в виде последовательности снимков $G_1, G_2, \ldots, G_T$, по одному на каждый временной шаг. GNN обрабатывает каждый снимок, а RNN или механизм временного внимания фиксирует эволюцию между снимками. Это просто, но теряется детальная информация о времени (теряются события между снимками) и требуется выбор частоты снимков.

- **Динамические графики непрерывного времени (CTDG)**: события моделируются как поток взаимодействий с отметками времени. Каждое событие $(i, j, t)$ обновляет представления узлов $i$ и $j$ в точное время, когда оно происходит. При этом сохраняется вся временная информация.

- **Сеть временных графов (TGN)** (Росси и др., 2020) является ведущей архитектурой CTDG. Каждый узел поддерживает **состояние памяти** $\mathbf{s}_i(t)$, которое обновляется всякий раз, когда узел участвует во взаимодействии:

$$\mathbf{s}_i(t^+) = \text{GRU}\left(\mathbf{s}_i(t^-), \; \mathbf{m}_i(t)\right)$$

- где $\mathbf{m}_i(t)$ — это сообщение, вычисленное в результате взаимодействия (объединяющее функции обоих узлов, граничных функций и временного кодирования). ГРУ (глава 6) избирательно сохраняет и забывает прошлую информацию, позволяя памяти улавливать долгосрочные закономерности и одновременно адаптироваться к недавним событиям.

- **Кодирование времени** представляет собой время, прошедшее с момента последнего взаимодействия, в виде вектора признаков, аналогично позиционному кодированию в преобразователях (глава 7). Общий подход использует обучаемые функции Фурье:

$$\Phi(t) = \left[\cos(\omega_1 t), \sin(\omega_1 t), \ldots, \cos(\omega_d t), \sin(\omega_d t)\right]$$

- Это дает модели богатое представление временных промежутков: «этот пользователь был активен 5 минут назад» и «3 месяца назад» встроены по-разному.- **Внимание к временному графу (TGAT)** применяет самообладание к временному окружению узла: набору недавних взаимодействий, каждое из которых взвешивается как по релевантности функции (например, GAT), так и по временной новизне. Взаимодействия из далекого прошлого, естественно, принижены.

- Приложения включают обнаружение мошенничества (аномальные модели транзакций на финансовых графиках), прогнозирование трафика (предсказание перегрузок на основе исторических моделей потоков), динамику социальных сетей (предсказание распространения вирусного контента) и прогнозирование взаимодействия наркотиков с течением времени.

## Задачи по кодированию (используйте CoLab или блокнот)

1. Реализуйте единую головку внимания GAT с нуля. Вычислите веса внимания между узлом и его соседями и проверьте, что их сумма равна 1.
```python
import jax
import jax.numpy as jnp

rng = jax.random.PRNGKey(0)
k1, k2, k3 = jax.random.split(rng, 3)

n_nodes, d_in, d_out = 5, 4, 3

# Random node features
H = jax.random.normal(k1, (n_nodes, d_in))

# Learnable parameters
W = jax.random.normal(k2, (d_in, d_out)) * 0.5
a = jax.random.normal(k3, (2 * d_out,)) * 0.5

# Adjacency (node 0 connects to 1, 2, 3)
neighbours_of_0 = [1, 2, 3]

# Transform features
Wh = H @ W  # (n_nodes, d_out)

# Compute attention scores for node 0
h_i = Wh[0]
scores = []
for j in neighbours_of_0:
    h_j = Wh[j]
    e_ij = jnp.dot(a, jnp.concatenate([h_i, h_j]))
    e_ij = jax.nn.leaky_relu(e_ij, negative_slope=0.2)
    scores.append(float(e_ij))

scores = jnp.array(scores)
alpha = jax.nn.softmax(scores)

print(f"Raw scores: {scores}")
print(f"Attention weights: {alpha}")
print(f"Sum of weights: {alpha.sum():.4f}")

# Weighted aggregation
h_new = sum(alpha[k] * Wh[neighbours_of_0[k]] for k in range(len(neighbours_of_0)))
print(f"Updated node 0 features: {h_new}")
```

2. Сравните агрегацию GCN (фиксированные веса) и GAT (обученные веса). Покажите, что GAT может присваивать соседям разные веса, в то время как GCN обрабатывает их одинаково.
```python
import jax
import jax.numpy as jnp

# 4 nodes: node 0 connects to 1, 2, 3
A = jnp.array([[0,1,1,1],
               [1,0,0,0],
               [1,0,0,0],
               [1,0,0,0]], dtype=float)

# Features: node 1 is very relevant, node 2 is noise, node 3 is moderate
H = jnp.array([[0.0, 0.0],   # node 0
               [1.0, 0.0],   # node 1 (signal)
               [0.0, 0.0],   # node 2 (noise)
               [0.5, 0.0]])  # node 3 (moderate)

# GCN: normalised adjacency weights
A_hat = A + jnp.eye(4)
D_inv = jnp.diag(1.0 / A_hat.sum(axis=1))
gcn_weights = (D_inv @ A_hat)[0]  # weights for node 0
print(f"GCN weights for node 0: {gcn_weights}")
print("  → All neighbours get roughly equal weight")

# GAT: learned attention (simulated)
# Suppose the attention mechanism learns to focus on node 1
gat_weights = jnp.array([0.1, 0.7, 0.05, 0.15])  # learned
print(f"\nGAT weights for node 0: {gat_weights}")
print("  → Node 1 (informative) gets most attention")

gcn_output = gcn_weights @ H
gat_output = gat_weights @ H
print(f"\nGCN output: {gcn_output}  (diluted by noise)")
```

```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Barbell graph: two cliques connected by a bridge
n = 10
A = jnp.zeros((n, n))
# Clique 1: nodes 0-4
for i in range(5):
    for j in range(i+1, 5):
        A = A.at[i,j].set(1).at[j,i].set(1)
# Clique 2: nodes 5-9
for i in range(5, 10):
    for j in range(i+1, 10):
        A = A.at[i,j].set(1).at[j,i].set(1)
# Bridge
A = A.at[4,5].set(1).at[5,4].set(1)

D = jnp.diag(A.sum(axis=1))
L = D - A
eigenvalues, eigenvectors = jnp.linalg.eigh(L)

# Use first 3 non-trivial eigenvectors as positional encoding
pe = eigenvectors[:, 1:4]

print("Laplacian Positional Encodings:")
for i in range(n):
    group = "Clique 1" if i < 5 else "Clique 2"
    bridge = " (bridge)" if i in [4, 5] else ""
    print(f"  Node {i} ({group}{bridge}): {pe[i]}")

plt.scatter(pe[:5, 0], pe[:5, 1], c="#3498db", s=80, label="Clique 1")
plt.scatter(pe[5:, 0], pe[5:, 1], c="#e74c3c", s=80, label="Clique 2")
plt.scatter(pe[[4,5], 0], pe[[4,5], 1], c="black", s=120, marker="*",
            label="Bridge nodes", zorder=5)
plt.legend(); plt.grid(True)
plt.title("Laplacian Eigenvector Positional Encodings")
plt.xlabel("Eigenvector 1"); plt.ylabel("Eigenvector 2")
```
