# Унифицированные мультимодальные архитектуры

*Унифицированные мультимодальные архитектуры заменяют отдельные специализированные модели единой системой, которая читает, анализирует и генерирует текст, изображения, аудио и видео. В этом файле описаны модели «любой к любому» (CoDi, NExT-GPT), изначально мультимодальные LLM (Gemini, GPT-4o), стратегии мультимодальной токенизации и архитектурные компромиссы унификации.*

## Аргументы в пользу объединения

- Представьте себе переводчика, который говорит на пяти языках и может переключаться между ними в середине предложения, не делая пауз. Ранние мультимодальные системы больше походили на пять отдельных переводчиков, сидящих в разных комнатах, каждый из которых работал на одном языке и передавал заметки через щель в стене. **Единая мультимодальная архитектура** — это единый полиглот: одна модель с общими весами, которая читает, записывает и обрабатывает текст, изображения, аудио, видео и даже действия — и все это за один прямой проход.

- Мотивация как практическая, так и теоретическая. С практической стороны поддержка отдельных специализированных моделей для каждой пары модальностей (текст-изображение, изображение-текст, аудио-текст и т. д.) приводит к комбинаторному взрыву: модальности $k$ требуют до $k(k-1)$ направленных конвейеров. Единая модель объединяет все это в единую систему. С теоретической точки зрения человеческое познание не обрабатывает зрение и язык в изолированных модулях; кросс-модальное связывание происходит на ранней и глубокой стадии, и унификация пытается отразить это.

– Общие веса способствуют **переносу между модальностями**. Трансформатор, который усвоил временные закономерности в тексте (подлежащее перед глаголом, причина перед следствием), может переназначить те же самые цепи внимания для временных закономерностей в видео (объект появляется до того, как он движется) или аудио (начало перед сустейном). Это мультимодальный аналог трансферного обучения, который вы видели в главе 7 с точной настройкой языковой модели и в главе 8 с предварительным обучением ImageNet.

— Формально пусть $\mathcal{M} = \{m_1, m_2, \ldots, m_k\}$ — набор модальностей. Унифицированная модель определяет одну параметризованную функцию $f_\theta$, которая сопоставляет любое подмножество входных модальностей с любым подмножеством выходных модальностей:

$$f_\theta : \mathcal{P}(\mathcal{M}) \rightarrow \mathcal{P}(\mathcal{M})$$

- где $\mathcal{P}(\mathcal{M})$ - набор мощности (все подмножества) модальностей. Ключевым ограничением является то, что $\theta$ в значительной степени является общим; различаются только тонкие, специфичные для модальности переходные слои.

![High-level diagram showing multiple modalities (text, image, audio, video) feeding into a single shared transformer backbone and producing outputs in any modality](../images/unified_multimodal_overview.svg)

- Обещание объединения сопряжено с фундаментальным противоречием: модальности структурно различны. Текст представляет собой одномерную последовательность дискретных токенов. Изображения представляют собой двумерные сетки непрерывных значений пикселей. Аудио — это одномерный непрерывный сигнал, временной масштаб которого сильно отличается от текста. Видео добавляет к изображениям ось времени. Согласование этих разрозненных структур в единую последовательность, которую может переварить трансформатор, является центральной инженерной задачей в этой области.

## Модели «любой к любому»

- Подумайте об универсальном пульте дистанционного управления, с помощью которого можно управлять телевизором, кондиционером и музыкальной системой через один и тот же интерфейс. **Модели «любой к любому»** являются эквивалентом ИИ: они принимают любую комбинацию модальностей в качестве входных данных и создают любую комбинацию в качестве выходных данных.

- **CoDi** (Composable Diffusion) обеспечивает генерацию «любой к любому», обучая модели диффузии, специфичные для модальности, а затем выравнивая их скрытые пространства с помощью общего механизма кондиционирования. Каждая модальность имеет свой собственный процесс распространения (вспомните модели диффузии из файла 04 в этой главе), но сети прогнозирования шума работают на совместном уровне перекрестного внимания, который одновременно видит внедрения всех входных модальностей. Это позволяет CoDi генерировать, скажем, изображение и соответствующий звук из текстовой подсказки за один проход.- **NExT-GPT** использует другой архитектурный подход. Он соединяет магистраль LLM («мозг») с кодировщиками, специфичными для модальности, на входной стороне и декодерами, специфичными для модальности, на выходной стороне через легкие **проекционные слои**. Входные кодеры (например, кодировщик изображения из CLIP, аудиокодер из CLAP) переводят каждую модальность в пространство внедрения LLM. LLM анализирует объединенную последовательность токенов и генерирует специальные «токены сигнала модальности», которые направляют информацию в соответствующий декодер (например, Stable Diffusion для изображений, AudioLDM для аудио). Обучаются только проекционные слои; LLM и специальные кодеры/декодеры остаются замороженными.

- **Gemini** (Google DeepMind) изначально мультимодален благодаря предварительному обучению. В отличие от подхода NExT-GPT «подключи и работай», преобразователь Gemini обучается с нуля на чередующихся последовательностях текстовых, графических, аудио- и видеотокенов. Это означает, что кросс-модальные модели внимания развиваются органично во время предварительной тренировки, а не закрепляются впоследствии. Модель использует токенизатор SentencePiece для текста и изучает визуальный токенизатор, аналогичный подходам VQ, обсуждаемым в файле 03 этой главы.

- **GPT-4o** («o» для «omni») представляет собой еще один шаблон: сквозную модель, в которой все модальности используют один и тот же преобразователь и одну и ту же цель прогнозирования следующего токена. Аудиовход обрабатывается как спектральные токены, изображения как токены патчей, а текст как токены подслов, и все это подается в одну последовательность. Модель генерирует выходные токены, которые декодируются головками, специфичными для модальности. Ключевым нововведением является низкая задержка, обеспечиваемая удалением каскада отдельных моделей ASR, LLM и TTS, от которых полагались более ранние системы, такие как GPT-4V.

![Comparison of architectural patterns for CoDi (aligned diffusion), NExT-GPT (LLM hub with frozen specialists), and Gemini-style (natively interleaved pretraining)](../images/any_to_any_architectures.svg)

- Эти модели имеют разную глубину интеграции:

    - **Поверхностная интеграция** (NExT-GPT): замороженные специалисты соединяются обученными адаптерами. Быстрое создание, ограниченное межмодальное мышление.
    - **Средняя интеграция** (CoDi): общее условие для генераторов, специфичных для конкретной модальности. Лучшее выравнивание, по-прежнему модульное.
    - **Глубокая интеграция** (Gemini, GPT-4o): единая модель, комплексно обученная по всем направлениям. Самое богатое кросс-модальное рассуждение, самое дорогое в обучении.

## Кодеры и декодеры, специфичные для модальности, с общей магистралью

- Представьте себе завод с одной сборочной линией (общая магистраль), но разными погрузочными площадками для сырья (кодировщики) и разными отделами отгрузки готовой продукции (декодеры). Каждый док специализируется на своем грузе, но внутри завода все движется по одному и тому же конвейеру.

- Доминирующий архитектурный шаблон для унифицированных моделей использует эту трехчастную структуру:

    - **Кодеры модальности** $E_m$, которые преобразуют необработанные входные данные из модальности $m$ в последовательность векторов внедрения $\mathbf{h}_1^m, \mathbf{h}_2^m, \ldots, \mathbf{h}_{n_m}^m$, каждый из которых имеет размерность $d$.
    - **Общая магистраль преобразователя** $T_\theta$, которая обрабатывает объединенные или чередующиеся внедрения всех модальностей ввода, используя самообладание.
    - **Декодеры модальности** $D_m$, которые преобразуют выходные встраивания магистрали обратно в собственный формат модальности $m$ (текстовые токены, пиксели изображений, звуковые сигналы).

- Для текста кодировщиком обычно является встраиваемая справочная таблица $E_\text{text}(w) = \mathbf{W}_e[w]$, где $w$ — индекс токена, идентичный тому, что вы видели в главе 7 с преобразователями. Для изображений кодировщиком часто является **Vision Transformer** (ViT), который разбивает изображение на фрагменты и проецирует каждый фрагмент линейно, как описано в главе 8. Для аудио кодировщик вычисляет мел-спектрограмму и обрабатывает ее либо с помощью сверточного интерфейса, либо с помощью преобразователя аудиоспектрограмм (AST), как описано в главе 9.

- Общая магистраль представляет собой стандартный преобразователь с самообслуживанием по всем токенам модальности. Учитывая объединенную входную последовательность $\mathbf{H} = [\mathbf{h}_1^{m_1}, \ldots, \mathbf{h}_{n_1}^{m_1}, \mathbf{h}_1^{m_2}, \ldots, \mathbf{h}_{n_2}^{m_2}]$, самообслуживание позволяет каждому токену обслуживать каждый другой токен независимо от модальности:

$$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}$$— Это та же формула внимания, что и в главе 7, но теперь $\mathbf{Q}$, $\mathbf{K}$ и $\mathbf{V}$ содержат токены из разных модальностей. Токен изображения-патча может обслуживать текстовый токен, обеспечивая кросс-модальное рассуждение без какого-либо отдельного модуля перекрестного внимания.

- **Внедрения модальности** добавляются к каждому токену, поэтому магистральная сеть знает, из какой модальности получен токен. Это аналогично позиционным вложениям, но кодирует идентичность модальности вместо положения последовательности. Обучаемый вектор $\mathbf{e}_m \in \mathbb{R}^d$ добавляется к каждому токену из модальности $m$:

$$\tilde{\mathbf{h}}_i^m = \mathbf{h}_i^m + \mathbf{e}_m + \mathbf{p}_i$$

- где $\mathbf{p}_i$ — позиционное вложение для позиции $i$.

## Мультимодальная токенизация

- Представьте, что вы пишете письмо, которое включает в себя как текст на английском языке, так и нарисованные от руки эскизы. Вы можете написать предложение, набросать диаграмму, написать еще одно предложение со ссылкой на диаграмму, а затем вставить партитуру. Письмо представляет собой единый линейный поток, в котором чередуются разные «модальности». Мультимодальная токенизация делает именно это: она преобразует текст, изображения, аудио и видео в единую плоскую последовательность токенов, которые преобразователь обрабатывает слева направо.

- Для текста токенизация хорошо известна: **кодирование парами байтов** (BPE) или SentencePiece создают словарь токенов подслов, как описано в главе 7. Задача состоит в том, чтобы распространить эту идею на непрерывные модальности.

- В отношении изображений существует два широких подхода. **Дискретный** подход использует VQ-VAE или VQ-GAN (подробно описан в файле 03 этой главы) для сопоставления каждого изображения с последовательностью индексов кодовой книги. Если в кодовой книге есть записи $|\mathcal{C}|$, а изображение закодировано как коды $n$, изображение становится дискретными токенами $n$, взятыми из словаря размера $|\mathcal{C}|$, напрямую совместимым с текстовым словарем. **Непрерывный** подход использует кодер ViT или CNN для создания векторов непрерывного внедрения $n$, которые линейно проецируются во размерность внедрения преобразователя. Gemini и GPT-4o используют варианты непрерывного подхода; авторегрессионные генераторы изображений, такие как Parti и LlamaGen, предпочитают дискретный маршрут.

- Для аудио сигнал обычно преобразуется в мел-спектрограмму, а затем либо дискретизируется с помощью нейронного аудиокодека (например, EnCodec, SoundStream, которые создают иерархические дискретные токены), либо непрерывно проецируется через обученный кодировщик. AudioLM, например, представляет звук как последовательность дискретных токенов из нескольких уровней кодовой книги, а затем моделирует их авторегрессионным способом.

- Для видео токенизация основана на токенизации изображения, но также должна сжимать временное измерение. Общая стратегия использует **3D VQ-VAE** (как в VideoGPT или Cosmos Tokeniser из файла 03), который квантует пространственно-временные патчи в дискретные токены. Фактор временного сжатия имеет решающее значение: необработанное видео со скоростью 24 кадра в секунду производит слишком много токенов в секунду без агрессивного временного понижения разрешения.

- После того как все модальности маркированы, они **перемежаются** в единую последовательность со специальными токенами-разделителями, обозначающими границы модальностей. Типичный формат выглядит так:

```
[TEXT] The cat sits on a mat [/TEXT] [IMAGE] <img_tok_1> <img_tok_2> ... <img_tok_n> [/IMAGE] [AUDIO] <aud_tok_1> ... <aud_tok_m> [/AUDIO]
```

- Затем преобразователь обрабатывает всю эту смешанную последовательность, используя свой стандартный механизм причинного (или двунаправленного) внимания. Токены-разделители модальности выполняют двойную функцию: они информируют модель о границах модальности и действуют как «точки объединения», представления которых суммируют каждый сегмент модальности.

![Interleaved token sequence showing text tokens, discrete image tokens, and audio codec tokens flowing through a single transformer with modality boundary markers](../images/multimodal_tokenisation_sequence.svg)

- Важнейшим выбором дизайна является **бюджет токенов**. Одно изображение, токенизированное в 256 токенов, и текстовая подпись из 50 токенов означает, что изображение занимает в 5 раз больше контекстного окна. Модели должны балансировать разрешение (больше токенов = больше деталей) и длину контекста (больше токенов = больше памяти и затрат на вычисления). Такие методы, как **слияние токенов** (постепенное объединение похожих токенов) и **адаптивная токенизация** (использование меньшего количества токенов для простых регионов и большего количества для сложных), помогают справиться с этим компромиссом.

## Рецепты тренировок: поэтапная предварительная тренировка и совместная отработка- Вы бы не стали учить ребенка счету раньше арифметики. Точно так же вы не можете обучать единую мультимодальную модель всем модальностям одновременно на основе случайной инициализации и ожидать, что она будет хорошо сходиться. Доминирующим подходом является **поэтапное обучение**, при котором модель изучает все более сложные кросс-модальные возможности в тщательно упорядоченных этапах.

- **Этап 1: предварительная унимодальная подготовка.** Каждый кодер модальности обучается независимо на больших унимодальных наборах данных. Текстовая основа предварительно обучается с помощью стандартной задачи моделирования языка (предсказание следующего токена) на триллионах текстовых токенов, точно так же, как в главе 7. Кодер машинного зрения предварительно обучается классификации изображений или целям с самоконтролем (MAE, DINO), как описано в главе 8. Аудиокодер предварительно обучается распознаванию речи или данным классификации аудио, как описано в главе 9. На этом этапе создаются надежные унимодальные экстракторы признаков.

- **Этап 2. Межмодальное выравнивание.** Предварительно обученные кодировщики подключаются к общей магистральной сети, а модель обучается на парных мультимодальных данных (пары изображений-подписей, пары аудио-расшифровок) с контрастной или генеративной целью. На этом этапе веса кодировщика могут быть заморожены (чтобы сохранить унимодальные знания), в то время как обновляются только проекционные слои и магистральная сеть. На этом этапе выравнивание в стиле CLIP (из файла 01 в этой главе) объединяется в единую модель.

- **Этап 3: Совместное мультимодальное предварительное обучение.** Все параметры (или большинство из них) размораживаются, и модель обучается на смеси унимодальных и мультимодальных данных с единой целью прогнозирования следующего токена для всех токенов модальности. Функция потерь:

$$\mathcal{L} = -\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})$$

- где $x_t$ может быть текстовым токеном, графическим токеном или аудиотокеном. Модель должна научиться предсказывать следующий токен независимо от модальности, что заставляет ее развивать подлинное кросс-модальное понимание.

– **Этап 4. Настройка и согласование инструкций.** Предварительно обученная модель дорабатывается на тщательно подобранных наборах данных, следующих за инструкциями и включающих мультимодальные инструкции (например, «Подробно опишите это изображение», «Какой звук издает это видео?», «Создайте изображение X»). На этом этапе часто используется **обучение с подкреплением на основе отзывов людей** (RLHF) или прямая оптимизация предпочтений (DPO) для согласования результатов модели с предпочтениями человека.

- **Разминка, специфичная для модальности** – это метод, используемый поэтапно для предотвращения коллапса модальности. Если одна модальность (обычно текст, который имеет больше всего обучающих данных) доминирует над сигналом градиента, модель может «забыть» более слабые модальности. Стратегии разминки включают в себя:

    - **Балансировка градиента**: масштабирование градиентов каждой модальности таким образом, чтобы они в равной степени вносили вклад в обновление параметров.
    - **Планирование соотношения данных**: постепенное увеличение доли мультимодальных данных по сравнению с унимодальными данными.
    - **Взвешивание потерь**: присвоение весов для конкретных модальностей $\lambda_m$, чтобы общая потеря составляла $\mathcal{L} = \sum_m \lambda_m \mathcal{L}_m$, при этом $\lambda_m$ настроен для балансировки скорости обучения между модальностями.

![Four-stage training pipeline diagram showing unimodal pretraining, cross-modal alignment, joint multimodal pretraining, and instruction tuning, with arrows indicating which parameters are frozen or trainable at each stage](../images/staged_multimodal_training.svg)

- **Почему бы не пропускать этапы?** Совместное обучение всему с нуля заманчиво, но на практике не получается по нескольким причинам. Во-первых, модель должна одновременно изучать функции низкого уровня (обнаружение границ, распознавание фонем) и кросс-модальное мышление высокого уровня, которые имеют очень разную динамику обучения. Во-вторых, распределение данных по модальностям крайне несбалансировано (триллионы текстовых токенов против миллиардов токенов изображений против сотен миллионов аудиоклипов). В-третьих, ландшафт оптимизации крайне невыпуклый, а поэтапное обучение обеспечивает учебную программу, которая ведет модель к лучшему бассейну, аналогично идее учебной программы из главы 6.

## Мультимодальное мышление- Когда вы решаете задачу по геометрии, вы можете нарисовать диаграмму, обозначить углы, написать уравнение, а затем решить его шаг за шагом. Вы не переходите напрямую от постановки проблемы к ответу. **Мультимодальная цепочка мыслей** (CoT) позволяет моделям делать то же самое: генерировать промежуточные этапы рассуждения, которые могут включать текст, визуальные аннотации или даже созданные диаграммы, прежде чем прийти к окончательному ответу.

- В текстовом CoT (как описано в главе 7, где обсуждаются стратегии подсказок), модель генерирует последовательность шагов рассуждения на естественном языке. Мультимодальный CoT расширяет это, позволяя промежуточным шагам ссылаться на визуальный контент или генерировать его. Например, при наличии изображения диаграммы и вопроса «В каком году были самые высокие продажи?» мультимодальная модель CoT может сначала описать диаграмму («На диаграмме показаны продажи с 2018 по 2023 год...»), затем определить соответствующие визуальные особенности («Самая высокая полоса появляется в 2021 году...») и, наконец, вывести ответ («2021»).

- Формально, пусть $\mathbf{x}$ — мультимодальный ввод, а $y$ — целевой ответ. Стандартные модели прогнозирования напрямую $p(y \mid \mathbf{x})$. Цепочка мыслей вводит промежуточные рассуждения $\mathbf{r} = (r_1, r_2, \ldots, r_L)$ и факторизует прогноз как:

$$p(y \mid \mathbf{x}) = \sum_{\mathbf{r}} p(y \mid \mathbf{r}, \mathbf{x}) \cdot p(\mathbf{r} \mid \mathbf{x})$$

- На практике сумма аппроксимируется жадным или лучевым декодированием по цепочкам рассуждений. Шагами рассуждения $r_i$ могут быть текстовые токены, ссылки на области изображения или даже сгенерированные визуальные токены (например, аннотация ограничивающей рамки, наложенная на входное изображение).

- **Обучение мультимодальному ЦТ** обычно включает в себя обработку наборов данных, в которых аннотаторы-люди предоставляют пошаговые трассировки мультимодальных рассуждений, а затем тонкую настройку модели на основе этих трассировок. Некоторые подходы выделяют возможности CoT из более крупных моделей учителей: учитель генерирует трассировки рассуждений для большого набора данных, а меньшая модель ученика обучается как на входных данных, так и на трассах учителя.

– Мультимодальный ЦТ особенно эффективен для задач, требующих **пространственного мышления** (например, «Находится ли красный шар слева от синего куба?»), **математического рассуждения над диаграммами** (например, задачи по геометрии) и **многоэтапного визуального ответа на вопрос**, когда ответ зависит от объединения информации из нескольких областей изображения.

## Мультимодальные агенты

- Представьте себе робота-повара на кухне. Он смотрит на ингредиенты на прилавке (видение), читает рецепт на планшете (текст), слушает звуковой сигнал таймера (аудио), а затем физически берет нож и режет лук (действие). **Мультимодальный агент** — это цифровая версия: модель, которая воспринимает мир через множество модальностей, рассуждает о том, что делать, и предпринимает действия, основанные на ее восприятии.

- Цикл агента следует классическому циклу **наблюдение-обоснование-действие**:

    1. **Наблюдение**. Агент получает мультимодальные входные данные из своей среды (скриншот, устные инструкции пользователя, видеопоток).
    2. **Причина**: унифицированная модель обрабатывает мультимодальные входные данные, возможно, используя цепочку мыслей для планирования последовательности шагов.
    3. **Действие**: модель выводит действие (текстовый ответ, вызов инструмента, щелчок мыши по координатам $(x, y)$, команда роботизированного двигателя).

- **Использование инструментов** — ключевая возможность мультимодальных агентов. Модель обучена распознавать случаи, когда она не может ответить на вопрос напрямую и вместо этого должна вызывать внешний инструмент: калькулятор, интерпретатор кода, веб-браузер или поисковую систему. Модель генерирует структурированный вызов инструмента (например, `search("current weather in London")`) как часть последовательности выходных токенов, система выполняет вызов, а результат возвращается в качестве дополнительных входных токенов для обработки модели.– **Визуальное заземление** связывает язык с определенными участками изображения или видео. Когда агент говорит «нажмите синюю кнопку в правом верхнем углу», он должен привязать фразу «синяя кнопка в правом верхнем углу» к пиксельным координатам. С архитектурной точки зрения это достигается за счет обучения модели выводить координаты ограничивающего прямоугольника в виде специальных токенов или за счет создания модели тепловой карты поверх изображения, указывающей указанную область. Это расширяет работу по обоснованию и перенаправлению, описанную в файле 02 этой главы (Языковые модели видения), на область действий.

– **Веб-агенты**, такие как WebVoyager и SeeAct, демонстрируют мультимодальные агенты, перемещающиеся по веб-сайтам. Агент получает снимок экрана веб-страницы, идентифицирует интерактивные элементы (кнопки, текстовые поля, ссылки) и выводит действия (щелчок, ввод текста, прокрутка) для достижения указанной пользователем цели. Ключевой проблемой является огромное пространство для действий: типичная веб-страница имеет сотни возможных целей клика.

![Observe-reason-act loop of a multimodal agent, showing visual input from a screen, the reasoning process inside the unified model, and output actions like clicking, typing, or calling tools](../images/multimodal_agent_loop.svg)

- **Воплощенные агенты** распространяют это на физическую среду. Робот с камерой и микрофоном получает визуальный и звуковой сигнал, обрабатывает его посредством единой модели и выдает двигательные команды. Такие проекты, как PaLM-E (Google), встраивают данные датчиков робота непосредственно в последовательность токенов языковой модели, позволяя роботу следовать таким инструкциям, как «взять зеленый блок возле миски», обосновывая инструкцию визуальным наблюдением и генерируя последовательность двигательных действий.

- Рецепт обучения агентов добавляет этап **обучения с подкреплением** (RL) поверх стандартной поэтапной предварительной подготовки. Агент взаимодействует со средой (моделируемый рабочий стол, веб-браузер, роботизированный симулятор), получает вознаграждение за выполнение задач и обновляет свою политику, используя такие алгоритмы, как PPO или REINFORCE. Сигнал вознаграждения обычно разреженный (1 в случае успеха задачи, 0 в противном случае), что делает эту оптимизацию сложной задачей и в значительной степени зависит от сильных априорных значений мультимодального предварительного обучения.

## Тесты и оценка

- Оценка модели, которая может видеть, слышать, читать и действовать, требует разнообразного набора тестов. Никакая единая метрика не отражает мультимодальную компетентность, поэтому эта область опирается на набор специализированных оценок.

- **MMLU** (массовое многозадачное понимание языка) проверяет знания по 57 академическим предметам. Хотя изначально она была только текстовой, она служит основой: унифицированная мультимодальная модель не должна терять производительность только для текста, когда она получает визуальные возможности. Падение MMLU после мультимодального обучения сигнализирует о катастрофическом забывании.

- **MMBench** оценивает понимание визуального языка по 20 детальным измерениям способностей, включая распознавание атрибутов, понимание пространственных отношений и оптическое распознавание текста. Каждый вопрос представляет собой изображение и вопрос с несколькими вариантами ответов. Тест систематически проверяет, действительно ли модель понимает изображение или использует только текстовые сочетания клавиш.

- **SEED-Bench** предоставляет 19 000 вопросов с несколькими вариантами ответов, охватывающих 12 параметров оценки для понимания изображений и видео. Он специально проверяет временное понимание (что произошло до/после данного кадра) и композиционное мышление (объединение нескольких визуальных атрибутов).

- **MM-Vet** оценивает интегрированные мультимодальные возможности, требуя от моделей одновременного использования нескольких навыков: распознавание, оптическое распознавание текста, пространственная осведомленность, генерация языка и извлечение знаний - и все это в одном вопросе.

- **MathVista** проверяет математические рассуждения на основе визуальных данных: геометрических диаграмм, статистических диаграмм, графиков функций и научных цифр. Этот тест специально нацелен на возможности мультимодальной цепочки мыслей.

– **Аудиовизуальные тесты**, такие как AVQA (аудиовизуальные ответы на вопросы), проверяют, могут ли модели рассуждать о взаимосвязи между тем, что они видят, и тем, что они слышат. Например: «Человек говорит слева или справа?»- **Бенчмарки агентов**, такие как WebArena, OSWorld и SWE-bench, оценивают выполнение задач в интерактивных средах. Обычно этот показатель представляет собой показатель успешности: какую часть задач агент выполняет правильно? Эти тесты особенно сложны, поскольку требуют долгосрочного планирования и устранения ошибок.

- Системы **холистической оценки**, такие как LMSYS Chatbot Arena, используют суждения о предпочтениях людей в формате личных встреч. Двум моделям показываются одни и те же мультимодальные входные данные, и человек-судья выбирает, какой ответ лучше. Рейтинги Эло рассчитываются на основе тысяч таких сравнений, обеспечивая единый скаляр, который хорошо коррелирует с общим качеством модели.

- Постоянной проблемой мультимодальной оценки является **загрязнение данных**: поскольку эти модели обучаются на данных Интернет-масштаба, в обучающем наборе могут появиться эталонные изображения и вопросы. Тщательная дедупликация и создание отложенных наборов тестов являются важными, но несовершенными гарантиями.

## Модели мира

- Представьте, что вы закрываете глаза и представляете, что произойдет, если вы столкнете стакан с края стола. Вы «видите», как оно падает, «слышите» разбивание и «чувствуете», что это плохая идея. В вашем мозгу работает **модель мира**: внутренняя симуляция физической и причинной структуры окружающей среды, которая может предсказывать будущие состояния в различных модальностях.

- В контексте ИИ модель мира — это изученная функция, которая предсказывает следующее состояние мира с учетом текущего состояния и действия:

$$\hat{s}_{t+1} = g_\phi(s_t, a_t)$$

- где $s_t$ — представление текущего состояния (которое может включать визуальную, слуховую и проприоцептивную информацию), $a_t$ — действие, а $\hat{s}_{t+1}$ — прогнозируемое следующее состояние. Состояние $s_t$ находится в изученном скрытом пространстве, а не в необработанном пространстве пикселей, что делает задачу прогнозирования решаемой.

- **Модели прогнозирования видео**, такие как Sora (OpenAI) и Genie (Google DeepMind), представляют собой важный шаг на пути к мировым моделям. Они учатся генерировать согласованные во времени видеокадры на основе текстовых подсказок и/или последовательностей действий. Хотя их часто называют видеогенераторами, их основные возможности ближе к моделированию мира: модель усвоила достаточно физики (гравитация, столкновение, окклюзия, динамика жидкости) для визуализации правдоподобного будущего.

- Связь с мультимодальными архитектурами глубока. Модель мира, которая предсказывает только пиксели, ограничена; действительно полезная модель мира предсказывает различные модальности. Если вы толкнете стекло, модель мира должна предсказать визуальную траекторию (стекло падает), звуковое событие (стекло разбивается) и семантическое последствие (теперь у вас разбитое стекло на полу). Унифицированные мультимодальные архитектуры являются естественными кандидатами на роль моделей мира, поскольку они уже представляют все модальности в общем пространстве.

- Формально мультимодальная модель мира оптимизирует:

$$\mathcal{L}_\text{world} = \mathbb{E}\left[\sum_{m \in \mathcal{M}} \lambda_m \| s_{t+1}^m - g_\phi^m(s_t, a_t) \|^2 \right]$$

- где $s_{t+1}^m$ — это основное истинное представление следующего состояния в модальности $m$, а $g_\phi^m$ — это глава предсказания модели мира, специфичная для модальности. Общая скрытая динамика $g_\phi$ действует в совместном мультимодальном пространстве, в то время как головки, специфичные для модальности, декодируют предсказания в собственный формат каждой модальности.

![World model diagram showing a latent state being updated by an action, with decoder heads predicting future visual frames, audio waveforms, and semantic descriptions](../images/multimodal_world_model.svg)

- **JEPA** (Joint Embedding Predictive Architecture), предложенная Яном Лекуном, предлагает основу для моделей мира, которая позволяет избежать ошибок прогнозирования на уровне пикселей. Вместо прогнозирования необработанных пикселей (что приводит к потере ресурсов на несущественные детали, такие как точные текстуры), JEPA прогнозирует с помощью встроенного пространства. Модель изучает кодер, который сопоставляет наблюдения с внедрениями, и предиктор, который прогнозирует будущие внедрения:

$$\hat{\mathbf{z}}_{t+1} = h_\psi(\mathbf{z}_t, a_t), \quad \mathbf{z}_t = \text{Enc}(s_t)$$

- При потере сравниваются встраивания, а не необработанные наблюдения, что более устойчиво к перцепционному сглаживанию (много разных конфигураций пикселей могут представлять одно и то же семантическое состояние). Этот подход особенно перспективен для мультимодальных моделей мира, поскольку он естественным образом работает в общем пространстве внедрения, которое уже обеспечивают унифицированные архитектуры.- Модели мира имеют практическое применение, выходящее за рамки академического интереса. При **обучении с подкреплением на основе модели** агент использует свою модель мира, чтобы «представить» последствия действий перед их выполнением, что значительно сокращает количество необходимых реальных взаимодействий (вспомним обсуждение RL на основе модели из главы 11). В режиме **автономного вождения** мировая модель предсказывает, как будет развиваться ситуация в течение следующих нескольких секунд при различных решениях рулевого управления. В **робототехнике** модель мира позволяет роботу мысленно отрепетировать последовательность манипуляций перед ее выполнением.

- Границы исследований моделей мира смещаются в сторону **интерактивных моделей мира**, которые работают в режиме реального времени и реагируют на произвольные действия пользователя, по сути превращаясь в симуляторы общего назначения, полностью обучаемые на основе данных. Genie 2 (Google DeepMind) демонстрирует это для трехмерных сред: по одному изображению он генерирует интерактивный, управляемый трехмерный мир, который пользователь может исследовать. import jax
```python
import jax.numpy as jnp

# Simulate multimodal tokenisation: text tokens + "image patch" tokens
def interleave_modalities(text_tokens, image_patches, embed_dim=32, key=jax.random.PRNGKey(0)):
    """Interleave text and image tokens with learned modality embeddings."""
    k1, k2, k3 = jax.random.split(key, 3)
    n_text = text_tokens.shape[0]
    n_img = image_patches.shape[0]
    # Random projection matrices (stand-ins for real encoders)
    W_text = jax.random.normal(k1, (text_tokens.shape[-1], embed_dim)) * 0.02
    W_img = jax.random.normal(k2, (image_patches.shape[-1], embed_dim)) * 0.02
    # Modality embeddings: one for text, one for image
    mod_emb = jax.random.normal(k3, (2, embed_dim)) * 0.02
    text_embs = text_tokens @ W_text + mod_emb[0]  # (n_text, embed_dim)
    img_embs = image_patches @ W_img + mod_emb[1]   # (n_img, embed_dim)
    # Interleave: [IMG] tokens first, then [TEXT] tokens (like LLaVA)
    combined = jnp.concatenate([img_embs, text_embs], axis=0)
    print(f"Combined sequence: {n_img} image + {n_text} text = {combined.shape[0]} tokens")
    return combined

text = jax.random.normal(jax.random.PRNGKey(1), (5, 16))
```

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

def cross_modal_attention(n_text=6, n_img=4, d=32, key=jax.random.PRNGKey(42)):
    """Compute and visualise attention between text and image tokens."""
    k1, k2, k3 = jax.random.split(key, 3)
    # Simulate token embeddings for two modalities
    text_embs = jax.random.normal(k1, (n_text, d))
    img_embs = jax.random.normal(k2, (n_img, d))
    seq = jnp.concatenate([img_embs, text_embs], axis=0)  # (n_img+n_text, d)
    # Learned Q, K projections
    Wq = jax.random.normal(k3, (d, d)) * 0.1
    Wk = jax.random.normal(jax.random.PRNGKey(99), (d, d)) * 0.1
    Q, K = seq @ Wq, seq @ Wk
    scores = Q @ K.T / jnp.sqrt(d)
    attn = jax.nn.softmax(scores, axis=-1)
    # Plot
    labels = [f"img_{i}" for i in range(n_img)] + [f"txt_{i}" for i in range(n_text)]
    fig, ax = plt.subplots(figsize=(7, 6))
    ax.imshow(attn, cmap="viridis")
    ax.set_xticks(range(len(labels))); ax.set_xticklabels(labels, rotation=45, fontsize=8)
    ax.set_yticks(range(len(labels))); ax.set_yticklabels(labels, fontsize=8)
    ax.set_xlabel("Key (attended to)"); ax.set_ylabel("Query (attending from)")
    ax.set_title("Cross-modal self-attention map")
    plt.colorbar(ax.images[0], ax=ax, shrink=0.8)
    plt.tight_layout(); plt.show()
```

**Задача 3. Имитация поэтапного обучения с помощью взвешивания потерь с учетом модальности**

- Продемонстрируйте, как потеря веса, специфичная для модальности, влияет на игрушечный мультимодальный тренировочный цикл. Обратите внимание, как балансирование потерь предотвращает доминирование одной модальности.

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

def staged_training_sim(steps=200, key=jax.random.PRNGKey(7)):
    """Simulate multimodal training with adjustable modality loss weights."""
    # Two 'modalities' with different loss scales (text loss ~10x larger than image loss)
    losses_text, losses_img = [], []
    param = jnp.array([0.0, 0.0])  # Shared param updated by both modality losses
    lr = 0.05
    # Try changing these weights to see the effect on convergence balance
    lambda_text, lambda_img = 1.0, 5.0  # upweight the weaker modality

    for step in range(steps):
        k1, k2, key = jax.random.split(key, 3)
        noise_t = jax.random.normal(k1, ()) * 0.3
        noise_i = jax.random.normal(k2, ()) * 0.1
        loss_t = (param[0] - 3.0) ** 2 + noise_t  # text target = 3.0
        loss_i = 0.1 * (param[1] - 1.0) ** 2 + noise_i  # image target = 1.0 (smaller scale)
        # Weighted combined gradient
        grad_t = lambda_text * 2 * (param[0] - 3.0)
        grad_i = lambda_img * 0.2 * (param[1] - 1.0)
        param = param - lr * jnp.array([grad_t, grad_i])
        losses_text.append(float(loss_t)); losses_img.append(float(loss_i))

    fig, ax = plt.subplots(figsize=(8, 4))
    ax.plot(losses_text, label=f"Text loss (weight={lambda_text})", alpha=0.7)
    ax.plot(losses_img, label=f"Image loss (weight={lambda_img})", alpha=0.7)
    ax.set_xlabel("Training step"); ax.set_ylabel("Loss"); ax.legend()
    ax.set_title("Modality loss balancing during staged training")
    plt.tight_layout(); plt.show()

staged_training_sim()
# Experiment: set lambda_img=1.0 and watch image loss converge much slower
```
