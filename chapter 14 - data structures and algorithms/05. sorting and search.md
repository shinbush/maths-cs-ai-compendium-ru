*Сортировка и поиск — наиболее фундаментальные алгоритмические операции. В этом файле описаны алгоритмы сортировки, шаблоны двоичного поиска, «разделяй и властвуй», жадные алгоритмы, динамическое программирование и возврат*.

В этом файле описаны **парадигмы проектирования**: стратегии высокого уровня для решения проблем. Как только вы поймете, какая парадигма применима, реализация произойдет естественным образом.

## Алгоритмы сортировки

— Сортировка — наиболее изученная проблема в информатике. Понимание алгоритмов развивает интуицию в области рекурсии, анализа «разделяй и властвуй» и анализа сложности.

| Алгоритм | Лучшее | Средний | Худший | Космос | Стабильный? |
|-----------|------|---------|-------|-------|---------|
| Пузырьковая сортировка | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Да |
| Сортировка вставками | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Да |
| Сортировка слиянием | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | Да |
| Быстрая сортировка | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | Нет |
| Сортировка кучей | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | Нет |
| Подсчет сортировки | $O(n + k)$ | $O(n + k)$ | $O(n + k)$ | $O(k)$ | Да |
| Поразрядная сортировка | $O(d(n + k))$ | $O(d(n + k))$ | $O(d(n + k))$ | $O(n + k)$ | Да |

- **Стабильный** означает, что равные элементы сохраняют свой относительный порядок. Это важно при сортировке по нескольким ключам.

– **Нижняя граница** для сортировки на основе сравнения — $\Omega(n \log n)$. В доказательстве используются деревья решений (глава 13): любой вид сравнения должен различать все перестановки $n!$, требуя как минимум сравнений $\log_2(n!)  = \Omega(n \log n)$. Сортировка по подсчету и поразрядная сортировка решают эту проблему, не сравнивая элементы.

### Сортировка слиянием

- Разделите массив пополам, рекурсивно отсортируйте каждую половину, затем объедините отсортированные половины. $O(n \log n)$ всегда, $O(n)$ дополнительное пространство.

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= for stability
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

- **Подводная ошибка**: использование `<` вместо `<=` при слиянии нарушает стабильность (равные элементы из правой половины будут идти раньше элементов из левой).

### Быстрая сортировка

– Выберите **центральную точку**, разделите элементы на «меньше, чем ось» и «больше, чем ось», рекурсивно отсортируйте каждый раздел. $O(n \log n)$ в среднем, $O(n^2)$ в худшем случае (когда опорной точкой всегда является самый маленький или самый большой элемент).

```python
def quicksort(arr, lo=0, hi=None):
    if hi is None:
        hi = len(arr) - 1
    if lo >= hi:
        return

    pivot_idx = partition(arr, lo, hi)
    quicksort(arr, lo, pivot_idx - 1)
    quicksort(arr, pivot_idx + 1, hi)

def partition(arr, lo, hi):
    pivot = arr[hi]  # Lomuto: pivot is last element
    i = lo
    for j in range(lo, hi):
        if arr[j] < pivot:
            arr[i], arr[j] = arr[j], arr[i]
            i += 1
    arr[i], arr[hi] = arr[hi], arr[i]
    return i
```

- **Стратегии поворота**: последний элемент (простой, не подходит для сортировки входных данных), случайный (ожидается $O(n \log n)$), медиана из трех (практичный выбор). Всегда предпочитайте случайные повороты в интервью, чтобы избежать обсуждения наихудшего случая.

- **Подводная ошибка**: наихудший случай быстрой сортировки $O(n^2)$ возникает в уже отсортированных массивах с первым/последним поворотным элементом. На практике случайный поворот или медиана из трех устраняют это.

### Сортировка по подсчету

- Если значения являются целыми числами в известном диапазоне $[0, k)$, подсчитываются вхождения и восстанавливаются: время $O(n + k)$. Не на основе сравнения, поэтому может превзойти $O(n \log n)$.

```python
def counting_sort(arr, k):
    count = [0] * k
    for x in arr:
        count[x] += 1
    result = []
    for val in range(k):
        result.extend([val] * count[val])
    return result
```

- **Когда использовать**: диапазон $k$ ненамного больше, чем $n$. Если $k = O(n)$, то это $O(n)$. Если $k \gg n$ (например, сортировка 10 чисел в диапазоне $[0, 10^9]$), счетная сортировка тратит память.

## Шаблон: двоичный поиск

- Двоичный поиск находит цель в отсортированном массиве в $O(\log n)$, многократно уполовинивая пространство поиска. Но бинарный поиск — это нечто большее, чем просто «найти число в отсортированном массиве». Общая схема такова: **поиск при монотонном условии**.

- **Шаблон** (тот, который позволяет избежать ошибок на единицу):

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1

    while lo <= hi:
        mid = lo + (hi - lo) // 2  # avoids overflow in other languages
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1

    return -1  # not found
```

- **Нижняя граница** (первый элемент $\geq$, цель):

```python
def lower_bound(arr, target):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo
```- **Подводный камень**: разница между `lo <= hi` и `lo < hi`, а также между `hi = mid` и `hi = mid - 1` определяет, найдете ли вы точное совпадение или границу. Для проверки нарисуйте его с помощью двухэлементного массива.

### Просто: двоичный поиск

- Стандартная проблема. Используйте шаблон выше.

### Medium: поиск в отсортированном массиве

- **Проблема**: отсортированный массив поворачивается в некоторой точке. Найдите цель.

- **Шаблон**: на каждом этапе всегда сортируется одна половина. Определите, какая половина отсортирована, и проверьте, находится ли цель в этой половине.

```python
def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid

        # left half is sorted
        if nums[lo] <= nums[mid]:
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        # right half is sorted
        else:
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1

    return -1
```

- **Подводная ошибка**: `<=` в `nums[lo] <= nums[mid]` (не `<`) имеет решающее значение. Когда `lo == mid` (осталось 2 элемента), мы должны правильно идентифицировать отсортированную половину.

### Hard: Медиана двух отсортированных массивов

- **Задача**: найти медиану двух отсортированных массивов в $O(\log(m + n))$.

- **Шаблон**: двоичный поиск по точке раздела меньшего массива. Раздел разделяет оба массива так, что все элементы слева меньше, чем все элементы справа.

```python
def find_median(nums1, nums2):
    if len(nums1) > len(nums2):
        nums1, nums2 = nums2, nums1  # ensure nums1 is shorter

    m, n = len(nums1), len(nums2)
    lo, hi = 0, m
    half = (m + n + 1) // 2

    while lo <= hi:
        i = (lo + hi) // 2          # partition point in nums1
        j = half - i                 # partition point in nums2

        left1 = nums1[i - 1] if i > 0 else float('-inf')
        right1 = nums1[i] if i < m else float('inf')
        left2 = nums2[j - 1] if j > 0 else float('-inf')
        right2 = nums2[j] if j < n else float('inf')

        if left1 <= right2 and left2 <= right1:
            # correct partition
            if (m + n) % 2 == 1:
                return max(left1, left2)
            return (max(left1, left2) + min(right1, right2)) / 2
        elif left1 > right2:
            hi = i - 1
        else:
            lo = i + 1
```

— Это одна из самых сложных задач двоичного поиска. Ключевой вывод заключается в том, что вы ищете не значение, а **точку разделения**, удовлетворяющую условию.

### Мета-шаблон: двоичный поиск по ответу

- Многие задачи, не похожие на бинарный поиск, можно решить с помощью бинарного поиска по ответу. Если ответом является число и вы можете написать монотонную функцию `is_feasible(x)` (True для всех оптимальных $x \geq$ или False для всех оптимальных $x \geq$), то выполняется двоичный поиск по $x$.

- **Пример**: «Какова минимальная вместимость корабля для доставки всех посылок в течение $d$ дней?» Бинарный поиск по емкости. Для каждой потенциальной мощности жадно проверьте, можно ли доставить все пакеты за $d$ дней.

```python
def ship_within_days(weights, days):
    lo, hi = max(weights), sum(weights)

    while lo < hi:
        mid = (lo + hi) // 2
        # can we ship with capacity mid in <= days?
        current_load, num_days = 0, 1
        for w in weights:
            if current_load + w > mid:
                num_days += 1
                current_load = 0
            current_load += w

        if num_days <= days:
            hi = mid
        else:
            lo = mid + 1

    return lo
```

## Шаблон: жадные алгоритмы

- **Жадный** алгоритм делает локально оптимальный выбор на каждом этапе, надеясь, что это приведет к глобально оптимальному решению. Жадный подход работает, когда задача имеет **свойство жадного выбора** (локальный оптимум приводит к глобальному оптимуму) и **оптимальную подструктуру** (оптимальное решение содержит оптимальные решения подзадач).

### Medium: Игра в прыжки

- **Проблема**: учитывая массив, где `nums[i]` — максимальная длина перехода в позиции $i$, определить, сможете ли вы достичь последнего индекса.

```python
def can_jump(nums):
    max_reach = 0
    for i, jump in enumerate(nums):
        if i > max_reach:
            return False  # cannot reach this position
        max_reach = max(max_reach, i + jump)
    return True
```

- **Почему жадность работает**: нам нужно знать только самую дальнюю достижимую позицию. Если текущая позиция находится за пределами досягаемости, мы застряли. В противном случае мы обновляем самый дальний охват.

### Средний: объединить интервалы

- **Проблема**: объединить перекрывающиеся интервалы.

```python
def merge_intervals(intervals):
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]

    for start, end in intervals[1:]:
        if start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])

    return merged
```

- **Шаблон**: сортировка по времени начала, затем жадное объединение. Если текущий интервал перекрывается с последним объединенным, продлите его. В противном случае начните новый объединенный интервал.

- **Подводная ошибка**: использование `merged[-1][1] = end` вместо `merged[-1][1] = max(merged[-1][1], end)`. Один интервал может полностью находиться внутри другого (например, [1, 10] и [2, 5]).

## Шаблон: динамическое программирование

- **Динамическое программирование (ДП)** решает проблемы, разбивая их на перекрывающиеся подзадачи, решая каждую подзадачу один раз и сохраняя результаты. Это работает, когда проблема имеет **оптимальную подструктуру** и **перекрывающиеся подзадачи**.

- **Два подхода**:
    - **Сверху вниз (мемоизация)**: напишите естественное рекурсивное решение, затем кешируйте результаты в словаре.
    - **Снизу вверх (таблица)**: постройте таблицу от наименьших подзадач вверх.

- **Как определить ДП**: задача требует оптимума (мин/макс), подсчета или существования, а текущее решение зависит от предыдущих решений. Если вы нарисуете дерево рекурсии и увидите повторяющиеся подзадачи, это DP.

### Легко: подъем по лестнице

- **Проблема**: $n$ ступеньки, можно подняться по 1 или 2 за раз. Сколько различных способов?

- Это Фибоначчи: $f(n) = f(n-1) + f(n-2)$.

```python
def climb_stairs(n):
    if n <= 2:
        return n
    a, b = 1, 2
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b
```

- $O(n)$ время, $O(1)$ пространство. Полная таблица запоминания не требуется, поскольку каждое состояние зависит только от двух предыдущих.

### Средний: обмен монет- **Задача**: учитывая номиналы монет и целевую сумму, найти минимально необходимое количество монет.

- **Состояние**: `dp[amount]` = минимальное количество монет для создания `amount`.
- **Переход**: `dp[amount] = min(dp[amount - coin] + 1)` для каждой монеты.
- **Базовый вариант**: `dp[0] = 0`.

```python
def coin_change(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0

    for a in range(1, amount + 1):
        for coin in coins:
            if coin <= a and dp[a - coin] + 1 < dp[a]:
                dp[a] = dp[a - coin] + 1

    return dp[amount] if dp[amount] != float('inf') else -1
```

- **Подводный камень**: инициализация с помощью `float('inf')` (не 0 или -1). Минимальное сравнение работает только в том случае, если недостижимые состояния бесконечны.

### Средний: самая длинная общая подпоследовательность

- **Задача**: по двум строкам найти длину их самой длинной общей подпоследовательности.

- **Состояние**: `dp[i][j]` = LCS для `text1[:i]` и `text2[:j]`.
- **Переход**: если `text1[i-1] == text2[j-1]`, то `dp[i][j] = dp[i-1][j-1] + 1`. В противном случае `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.

```python
def longest_common_subsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[m][n]
```

### Сложный: 0/1 Рюкзак

- **Проблема**: учитывая предметы с весом и ценностью, а также вместимостью $W$, максимизируйте общую стоимость, не превышая $W$.

- **Состояние**: `dp[i][w]` = максимальное значение с использованием первых элементов $i$ с емкостью $w$.
- **Переход**: `dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])` (пропустить или взять элемент $i$).

```python
def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for w in range(capacity + 1):
            dp[i][w] = dp[i - 1][w]  # skip item i
            if weights[i - 1] <= w:
                dp[i][w] = max(dp[i][w],
                               dp[i - 1][w - weights[i - 1]] + values[i - 1])

    return dp[n][capacity]
```

- **Оптимизация пространства**: поскольку каждая строка зависит только от предыдущей строки, используйте одномерный массив и перебирайте $w$ справа налево:

```python
def knapsack_optimised(weights, values, capacity):
    dp = [0] * (capacity + 1)
    for i in range(len(weights)):
        for w in range(capacity, weights[i] - 1, -1):  # right to left!
            dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
    return dp[capacity]
```

- **Подводный камень**: итерация слева направо в 1D-версии позволяет использовать предмет $i$ несколько раз (неограниченный рюкзак). Справа налево гарантирует, что каждый элемент используется не более одного раза.

## Шаблон: возврат

- **Возврат** — это исчерпывающий поиск с сокращением. Создавайте решение постепенно и отказывайтесь от него (отступайте), как только частичное решение не может привести к действительному полному решению.

- **Шаблон**:

```python
def backtrack(candidates, path, result):
    if is_solution(path):
        result.append(path[:])  # copy!
        return

    for candidate in get_candidates(path):
        if is_valid(candidate, path):
            path.append(candidate)     # choose
            backtrack(candidates, path, result)  # explore
            path.pop()                 # unchoose (backtrack)
```

### Средний: подмножества

```python
def subsets(nums):
    result = []
    def backtrack(start, path):
        result.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()
    backtrack(0, [])
    return result
```

### Средний: сумма комбинации

- **Задача**: найти все уникальные комбинации, которые в сумме соответствуют цели (элементы можно использовать повторно).

```python
def combination_sum(candidates, target):
    result = []
    def backtrack(start, path, remaining):
        if remaining == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:
                break  # prune: sorted, so all further candidates are too large
            path.append(candidates[i])
            backtrack(i, path, remaining - candidates[i])  # i, not i+1: reuse allowed
            path.pop()

    candidates.sort()  # sort for pruning
    backtrack(0, [], target)
    return result
```

- **Подводная ошибка**: `backtrack(i, ...)` позволяет повторно использовать один и тот же элемент. `backtrack(i + 1, ...)` перейдет к следующему элементу (без повторного использования). Ошибка в этом — самая распространенная ошибка возврата.

### Сложно: N-Queens

- **Проблема**: разместите ферзей $n$ на доске $n \times n$ так, чтобы никакие два игрока не атаковали друг друга.

```python
def solve_n_queens(n):
    result = []
    cols = set()
    pos_diag = set()  # (row + col) is constant on / diagonals
    neg_diag = set()  # (row - col) is constant on \ diagonals

    board = [['.' ] * n for _ in range(n)]

    def backtrack(row):
        if row == n:
            result.append([''.join(r) for r in board])
            return

        for col in range(n):
            if col in cols or (row + col) in pos_diag or (row - col) in neg_diag:
                continue

            cols.add(col)
            pos_diag.add(row + col)
            neg_diag.add(row - col)
            board[row][col] = 'Q'

            backtrack(row + 1)

            cols.remove(col)
            pos_diag.remove(row + col)
            neg_diag.remove(row - col)
            board[row][col] = '.'

    backtrack(0)
    return result
```

– **Ключевая идея**: диагональное кодирование. Для диагоналей `/` значение `row + col` является постоянным. Для диагоналей `\` значение `row - col` является постоянным. Использование наборов для отслеживания столбцов и диагонали приводит к проверке достоверности $O(1)$.

## Резюме распространенных ошибок

| ловушка | Пример | Исправить |
|---------|---------|-----|
| `lo <= hi` против `lo < hi` в двоичном поиске | Офф-на-один в пределах | Выбирайте в зависимости от того, является ли `hi` включенным или эксклюзивным |
| Рюкзак 1D слева направо | Предметы, используемые многократно | Итерация справа налево для ранца 0/1 |
| Не копировать путь при возврате | `result.append(path)` — все записи указывают на один и тот же список | `result.append(path[:])` или `path.copy()` |
| `backtrack(i)` против `backtrack(i+1)` | Повторное использование и запрет повторного использования элементов | Соответствуйте постановке задачи |
| Отсутствует `break` в отсортированном возврате | Изучение слишком больших кандидатов | Сортировка + разрыв, когда кандидат превышает оставшееся |
| Инициализация DP | `dp[0]` неверно → все последующие значения неверны | Тщательно определите базовый вариант |
| Жадность без доказательств | Жадность не всегда работает | Проверить свойство жадного выбора |
| Нестабильная сортировка для нескольких ключей | Относительный порядок равных элементов потерян | Использовать стабильную сортировку (сортировка слиянием, Python `sorted`) |
