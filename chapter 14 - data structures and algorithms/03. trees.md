# Деревья

*Деревья — это иерархическая структура данных, лежащая в основе файловых систем, баз данных, компиляторов и бесчисленных задач на собеседованиях. В этом файле описаны бинарные деревья, BST, сбалансированные деревья, попытки, деревья сегментов, деревья Фенвика и поиск объединений, а также шаблоны обхода, рекурсивное мышление и все более сложные задачи.*

- **Дерево** — это связный ациклический граф (глава 13). Наиболее важным вариантом является **двоичное дерево**: каждый узел имеет не более двух потомков (левого и правого). Деревья появляются повсюду: деревья синтаксического анализа в компиляторах, деревья DOM в браузерах, деревья решений в машинном обучении и B-деревья в базах данных.

- Ключевое понимание задач о деревьях: **большинство задач о деревьях решаются рекурсивно**. Структура рекурсивная (дерево — это корень с двумя поддеревьями), поэтому и решения должны быть такими же. Освойте шаблон «решить левое поддерево, решить правое поддерево, объединить», и вы сможете решить большинство задач с деревьями.

## Обход двоичного дерева

- Есть четыре стандартных способа посетить каждый узел:

    - **Inorder** (слева, корень, справа): для BST узлы посещаются в отсортированном порядке.
    - **Предварительный заказ** (коренной, левый, правый): полезен для сериализации и копирования деревьев.
    - **Postorder** (слева, справа, корень): полезно для удаления и вычисления размеров.
    - **Порядок уровней** (BFS): посещайте узлы уровень за уровнем, используя очередь.

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(root):
    if not root:
        return []
    return inorder(root.left) + [root.val] + inorder(root.right)

def preorder(root):
    if not root:
        return []
    return [root.val] + preorder(root.left) + preorder(root.right)

def postorder(root):
    if not root:
        return []
    return postorder(root.left) + postorder(root.right) + [root.val]

from collections import deque

def level_order(root):
    if not root:
        return []
    result, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result
```

- **Подводная ошибка**: приведенные выше рекурсивные обходы создают новые списки на каждом этапе (из-за конкатенации `+`), что соответствует $O(n^2)$. Для эффективности передайте список результатов и добавьте его на месте:

```python
def inorder_efficient(root, result=None):
    if result is None:
        result = []
    if root:
        inorder_efficient(root.left, result)
        result.append(root.val)
        inorder_efficient(root.right, result)
    return result
```

### Легко: максимальная глубина двоичного дерева

```python
def max_depth(root):
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

- **Рекурсивный шаблон**: базовый случай (ноль → 0), рекурсия по дочерним элементам, объединение (1 + максимум). Тот же самый шаблон применим к десяткам проблем с деревьями.

### Легко: инвертировать двоичное дерево

```python
def invert_tree(root):
    if not root:
        return None
    root.left, root.right = invert_tree(root.right), invert_tree(root.left)
    return root
```

### Средний: низший общий предок

- **Задача**: найти самый нижний узел, который является предком как $p$, так и $q$.

- **Шаблон**: если $p$ и $q$ находятся в левом поддереве, LCA находится в левом поддереве. Если оба правы, то он прав. Если они разделены (один слева, один справа), текущий узел является LCA.

```python
def lowest_common_ancestor(root, p, q):
    if not root or root == p or root == q:
        return root

    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)

    if left and right:
        return root  # p and q are in different subtrees
    return left if left else right
```

- **Подводная ошибка**: предполагается, что в дереве существуют $p$ и $q$. Если это не так, вам нужны дополнительные проверки.

### Hard: максимальная сумма путей двоичного дерева

- **Задача**: найти путь максимальной суммы между любыми двумя узлами (путь не обязательно должен проходить через корень).

```python
def max_path_sum(root):
    best = [float('-inf')]

    def dfs(node):
        if not node:
            return 0
        left = max(dfs(node.left), 0)   # ignore negative paths
        right = max(dfs(node.right), 0)

        # path through this node (possibly as the "bend")
        best[0] = max(best[0], node.val + left + right)

        # return the max gain this node can contribute to its parent
        return node.val + max(left, right)

    dfs(root)
    return best[0]
```

- **Ключевая идея**: в каждом узле возникает два вопроса: (1) какой лучший путь проходит *через* этот узел (слева + узел + справа)? (2) какой лучший путь этот узел может внести в свой *родитель* (узел + max(left, right), поскольку путь не может разветвляться на двух уровнях)? Спутать эти два понятия — самая распространенная ошибка.

## Двоичные деревья поиска (BST)

- **BST** удовлетворяет требованиям: для каждого узла все значения в левом поддереве меньше, все значения в правом поддереве больше. Это позволяет выполнять поиск, вставку и удаление $O(\log n)$ (при сбалансированности).

```python
def search_bst(root, target):
    if not root:
        return None
    if target < root.val:
        return search_bst(root.left, target)
    elif target > root.val:
        return search_bst(root.right, target)
    else:
        return root

def insert_bst(root, val):
    if not root:
        return TreeNode(val)
    if val < root.val:
        root.left = insert_bst(root.left, val)
    else:
        root.right = insert_bst(root.right, val)
    return root
```

- **Подводная ошибка**: операции BST являются $O(\log n)$ только тогда, когда дерево сбалансировано. BST, построенный из отсортированных вставок, вырождается в связанный список: $O(n)$ для каждой операции. Вот почему существуют сбалансированные BST (AVL, красно-черный).

### Средний: проверка двоичного дерева поиска

```python
def is_valid_bst(root, lo=float('-inf'), hi=float('inf')):
    if not root:
        return True
    if root.val <= lo or root.val >= hi:
        return False
    return (is_valid_bst(root.left, lo, root.val) and
            is_valid_bst(root.right, root.val, hi))
```

- **Подводная ошибка**: проверять только `left.val < root.val < right.val` неправильно. Ограничение состоит в том, что *все* узлы в левом поддереве меньше, а не только непосредственный дочерний элемент. Границы `lo`/`hi` распространяют это ограничение вниз.

### Medium: K-й наименьший элемент в BST

- **Шаблон**: при упорядоченном обходе BST узлы посещаются в отсортированном порядке. Ответом является $k$-й посещенный узел.

```python
def kth_smallest(root, k):
    count = [0]
    result = [None]

    def inorder(node):
        if not node or result[0] is not None:
            return
        inorder(node.left)
        count[0] += 1
        if count[0] == k:
            result[0] = node.val
            return
        inorder(node.right)

    inorder(root)
    return result[0]
```

## Попыток (префиксные деревья)

- **trie** хранит строки посимвольно в дереве. Каждое ребро представляет собой символ, а пути от корня до отмеченных узлов представляют собой сохраненные строки. Пытается включить поиск $O(L)$, где $L$ — длина строки, независимо от того, сколько строк хранится.```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for char in word:
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char]
        node.is_end = True

    def search(self, word):
        node = self.root
        for char in word:
            if char not in node.children:
                return False
            node = node.children[char]
        return node.is_end

    def starts_with(self, prefix):
        node = self.root
        for char in prefix:
            if char not in node.children:
                return False
            node = node.children[char]
        return True
```

- **Когда использовать**: автозаполнение, проверка правописания, словесные игры, таблицы IP-маршрутизации. Всякий раз, когда вам нужны операции на основе префиксов.

### Сложный: Поиск слов II

- **Задача**: по доске символов и списку слов найти все слова, которые можно образовать путем обхода соседних ячеек.

- **Шаблон**: создайте дерево из списка слов, затем DFS из каждой ячейки, используя дерево, чтобы заранее удалить ветки (если ни одно слово не начинается с текущего префикса, остановитесь).

- **Подводный камень**: без trie вы бы использовали DFS для каждого слова отдельно: $O(w \cdot m \cdot n \cdot 4^L)$. В дереве общие вычисления префиксов для всех слов, что значительно сокращает объем работы.

## Union-Find (Объединение непересекающихся наборов)

- **Union-Find** отслеживает коллекцию непересекающихся наборов. Две операции: `find(x)` возвращает представителя набора $x$, а `union(x, y)` объединяет наборы, содержащие $x$ и $y$.

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.count = n  # number of connected components

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # path compression
        return self.parent[x]

    def union(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False  # already connected
        # union by rank
        if self.rank[rx] < self.rank[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        if self.rank[rx] == self.rank[ry]:
            self.rank[rx] += 1
        self.count -= 1
        return True
```

- При сжатии пути и объединении по рангу обе операции выполняются в амортизированном $O(\alpha(n)) \approx O(1)$ (обратном Аккермане, фактически постоянном).

- **Когда использовать**: связанные компоненты, обнаружение циклов в неориентированных графах, MST Крускала, группировка эквивалентных элементов.

### Средний: количество подключенных компонентов

```python
def count_components(n, edges):
    uf = UnionFind(n)
    for u, v in edges:
        uf.union(u, v)
    return uf.count
```

### Средний: резервное соединение

- **Задача**: найти ребро, при удалении которого граф становится деревом (т. е. ребро, создающее цикл).

- **Шаблон**: края обрабатываются один за другим. Первое ребро, где обе конечные точки уже находятся в одном компоненте, создает цикл.

```python
def find_redundant(edges):
    uf = UnionFind(len(edges) + 1)
    for u, v in edges:
        if not uf.union(u, v):
            return [u, v]  # already connected → this edge creates a cycle
```

## Деревья отрезков и деревья Фенвика

- **Деревья сегментов** отвечают на запросы диапазона (сумма, минимум, максимум по подмассиву) и поддерживают обновления точек, как в $O(\log n)$.

- **Деревья Фенвика** (двоичные индексированные деревья) — более простая и быстрая альтернатива для запросов суммы префиксов и обновления точек. Они используют хитрый трюк с битовыми манипуляциями: каждая позиция хранит частичную сумму, охватывающую диапазон, определяемый младшим установленным битом.

```python
class FenwickTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, i, delta):
        i += 1  # 1-indexed
        while i <= self.n:
            self.tree[i] += delta
            i += i & (-i)  # add lowest set bit

    def prefix_sum(self, i):
        i += 1
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= i & (-i)  # remove lowest set bit
        return total

    def range_sum(self, l, r):
        return self.prefix_sum(r) - (self.prefix_sum(l - 1) if l > 0 else 0)
```

- **Когда использовать**: проблемы, требующие повторных запросов диапазона с обновлениями. Деревья Фенвика предпочтительнее, когда вам нужны только суммы префиксов; сегментируйте деревья, когда вам нужны произвольные операции с диапазоном (мин, максимум, НОД).

## Резюме распространенных ошибок

| ловушка | Пример | Исправить |
|---------|---------|-----|
| Проверка только прямых дочерних элементов на BST | `left.val < root.val` не замечает более глубоких нарушений | Пройти границы `lo`/`hi` |
| $O(n^2)$ Объединение списков в рекурсии | `inorder(left) + [val] + inorder(right)` | Добавить в общий список |
| Забывая о базовом случае | Бесконечная рекурсия на пустом дереве | `if not root: return` |
| Сбивающий с толку сквозной путь и путь к родителю | Максимальная сумма путей: разветвление на два уровня | Вернуть одну ветку родительскому элементу, отслеживать две ветки отдельно |
| Фенвик с 1 индексом и 0 индексом | По одному в древовидном массиве | Всегда `i += 1` при входе |
| Union-Find без сжатия пути | $O(n)$ за находку в худшем случае | `self.parent[x] = self.find(self.parent[x])` |
