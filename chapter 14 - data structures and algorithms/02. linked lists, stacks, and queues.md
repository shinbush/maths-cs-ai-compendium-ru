# Связанные списки, стеки и очереди

*Связанные списки, стеки и очереди являются строительными блоками более сложных структур данных. Этот файл описывает их механику, а затем создает ключевые шаблоны; быстрые/медленные указатели, монотонные стеки и очереди с приоритетами на основе кучи, решение все более сложных задач с типичными ошибками на каждом этапе.*

- Массивы обеспечивают быстрый произвольный доступ, но дорогостоящие вставки. **Связанные списки** позволяют быстро вставлять данные, но не допускают произвольного доступа. **Стеки** и **очереди** ограничивают доступ к одному или двум концам, и именно это ограничение делает их мощными: ограничивая то, что вы можете сделать, они упрощают то, о чем вам нужно думать.

## Связанные списки

– **Односвязный список** – это цепочка узлов. Каждый узел хранит значение и указатель на следующий узел. Последний узел указывает на `null`.

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

- **Преимущества перед массивами**: вставка или удаление в известной позиции осуществляется $O(1)$ (просто переназначьте указатели). Не нужно перемещать элементы.

- **Недостатки**: доступ к элементу $i$ требует обхода $O(i)$ (без произвольного доступа). Плохая локальность кэша (узлы разбросаны по памяти).

- **Двухсвязные списки** добавляют указатель `prev`, позволяющий обратный обход. Используется в кэшах LRU (постоянное удаление любого узла) и истории браузера (назад/вперед).

| Операция | По отдельности | Вдвойне |
|-----------|--------|--------|
| Доступ по индексу | $O(n)$ | $O(n)$ |
| Вставка в голове | $O(1)$ | $O(1)$ |
| Вставка в хвосте | $O(n)$ или $O(1)$* | $O(1)$ |
| Удалить данный узел | $O(n)$** | $O(1)$ |
| Поиск | $O(n)$ | $O(n)$ |

*с хвостовым указателем. **нужен предшественник, который требует обхода.

- **Стражные узлы** (фиктивные голова/хвост) упрощают крайние случаи. Без фиктивной головки для вставки или удаления головки требуется специальный код. При использовании манекена каждый реальный узел имеет предшественника.

```python
# Without dummy: special case for head deletion
def delete_head(head):
    if not head:
        return None
    return head.next

# With dummy: uniform logic
dummy = ListNode(0)
dummy.next = head
# now every deletion is: prev.next = prev.next.next
```

- **Подводная ошибка**: забывают обработать пустой список (`head is None`) или список, состоящий из одного элемента. Всегда проверяйте эти крайние случаи.

## Шаблон: быстрые и медленные указатели (Флойда)

- Используйте два указателя, движущиеся с разной скоростью, для определения свойств связанных списков. Указатель **медленно** перемещается шаг за шагом; указатель **fast** перемещается на два шага.

### Легко: цикл связанных списков

- **Проблема**: определить, есть ли в связанном списке цикл.

- **Шаблон**: если есть цикл, быстрый указатель в конечном итоге пересечет медленный указатель (они встретятся). Если цикла нет, быстрый указатель достигает `null`.

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            return True
    return False
```

- **Почему это работает**: если цикл имеет длину $c$, быстрый указатель закрывает разрыв на 1 узел за шаг. Они должны встретиться в пределах $c$ шагов медленного указателя, входящего в цикл.

- **Подводная ошибка**: проверка `fast and fast.next` (а не только `fast.next`). Если `fast` — это `None`, вызов `fast.next` завершается сбоем.

### Средний: найти середину связанного списка

- **Проблема**: вернуть средний узел.

- **Шаблон**: когда быстрый указатель достигает конца, медленный указатель оказывается в середине.

```python
def find_middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow  # slow is at the middle (or second middle if even length)
```

### Средний: цикл связанных списков II (найти начало цикла)

- **Проблема**: вернуть узел, с которого начинается цикл.

- **Шаблон**: после быстрой и медленной встречи сбросьте один указатель на голову. Двигайтесь оба со скоростью 1. Они встречаются в начале цикла.

```python
def detect_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            # reset one pointer to head
            slow = head
            while slow != fast:
                slow = slow.next
                fast = fast.next
            return slow
    return None
```

- **Почему это работает**: пусть расстояние от головы до начала цикла будет $a$, а расстояние от начала цикла до точки встречи будет $b$. Медленный указатель перемещался $a + b$. Быстрый указатель пролетел $2(a + b)$. Разница составляет один полный цикл: $a + b = c$ (длина цикла). Итак, $a = c - b$: расстояние от головы до начала цикла равно расстоянию от точки встречи до начала цикла (вперед по циклу).

### Сложный: обратносвязный список в группах по K

- **Проблема**: перевернуть все последовательные узлы $k$ в связанном списке.

```python
def reverse_k_group(head, k):
    # check if we have k nodes left
    node = head
    for _ in range(k):
        if not node:
            return head
        node = node.next

    # reverse k nodes
    prev, curr = None, head
    for _ in range(k):
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt

    # head is now the tail of the reversed group
    # recursively process the rest
    head.next = reverse_k_group(curr, k)
    return prev  # prev is the new head of this group
```- **Подводный камень**: стоит запомнить разворотную модель на месте (`prev, curr, nxt`). Нарисуйте это: на каждом шаге вы указываете `curr.next` назад на `prev`, а затем перемещаете все три указателя. Неправильный порядок портит список.

## Стеки

- **стек** — это LIFO (последний вошел, первый вышел): первым удаляется самый последний добавленный элемент. Представьте себе стопку тарелок.

- Операции: `push(x)` добавляет вверху, `pop()` удаляет сверху, `peek()` смотрит вверху, не удаляя. Все $O(1)$.

– Стеки — это неявная структура, лежащая в основе **рекурсии** (стек вызовов), **вычисления выражений** (преобразование инфикса в постфикс) и **операций отмены** (каждое действие отправляется, отмена выталкивает последнее).

### Легко: допустимые круглые скобки

- **Задача**: по строке скобок `()[]{}` определить, сбалансированы ли они.

- **Шаблон**: вставьте открывающиеся скобки в стек. Когда вы увидите закрывающуюся скобку, убедитесь, что вершина стопки соответствует соответствующей открывающей скобке.

```python
def is_valid(s):
    stack = []
    matching = {')': '(', ']': '[', '}': '{'}

    for char in s:
        if char in matching:
            if not stack or stack[-1] != matching[char]:
                return False
            stack.pop()
        else:
            stack.append(char)

    return len(stack) == 0
```

- **Подводная ошибка**: забыть `len(stack) == 0` в конце. Строка "(((" не имеет несоответствий, но недопустима, поскольку остаются незакрытые скобки.

## Шаблон: монотонный стек

- **Монотонный стек** сохраняет элементы в отсортированном порядке (по возрастанию или убыванию). Когда новый элемент нарушает порядок, вы перемещаете элементы до тех пор, пока порядок не будет восстановлен.

- **Когда использовать**: проблемы с вопросом «для каждого элемента найти следующий/предыдущий больший/меньший элемент». Стек дает общее количество $O(n)$, поскольку каждый элемент помещается и извлекается не более одного раза.

### Средняя: дневная температура

- **Задача**: учитывая дневную температуру, для каждого дня найти, сколько дней осталось до потепления.

- **Шаблон**: используйте стек индексов. Когда текущая температура выше верхней точки стопки, поднимите и запишите расстояние.

```python
def daily_temperatures(temperatures):
    n = len(temperatures)
    result = [0] * n
    stack = []  # stack of indices, temperatures in decreasing order

    for i in range(n):
        while stack and temperatures[i] > temperatures[stack[-1]]:
            prev = stack.pop()
            result[prev] = i - prev
        stack.append(i)

    return result
```

- Каждый элемент нажимается один раз и выдвигается не более одного раза: всего $O(n)$.

- **Подводная ошибка**: хранение в стеке индексов (а не значений). Вам нужен индекс для вычисления расстояния.

### Hard: самый большой прямоугольник на гистограмме

- **Задача**: по массиву высот стержней найти площадь наибольшего прямоугольника.

- **Шаблон**: для каждого стержня определите, насколько далеко он может простираться влево и вправо (т. е. ближайший более короткий стержень с каждой стороны). Монотонно возрастающий стек эффективно отслеживает это.

```python
def largest_rectangle(heights):
    stack = []  # stack of indices, heights in increasing order
    max_area = 0
    heights.append(0)  # sentinel to flush the stack at the end

    for i, h in enumerate(heights):
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            max_area = max(max_area, height * (i - idx))
            start = idx  # this bar can extend back to where the popped bar started
        stack.append((start, h))

    heights.pop()  # remove sentinel
    return max_area
```

- **Подводный камень**: линия `start = idx` незаметна. Когда мы выдвигаем полосу, которая выше текущей, текущая полоса может простираться назад до того места, где начиналась выдвижная полоса (поскольку все промежуточные полосы были по крайней мере такой же высоты, как и выдвинутая полоса). Отсутствие этой строки дает неправильные области.

- **Подводная ошибка**: сигнализатор `heights.append(0)` гарантирует обработку всех оставшихся баров в стеке. Без этого такты, которые никогда не встречаются с более короткими барами справа, будут пропущены.

## Очереди

- **Очередь** — это FIFO (первым вошел, первым обслужен): элементы добавляются сзади и удаляются спереди. Представьте себе очередь в магазине.

- **deque** (двусторонняя очередь) поддерживает вставку и удаление $O(1)$ на обоих концах. `collections.deque` Python является стандартной реализацией.

– Очереди — это структура, лежащая в основе **BFS** (поиск в ширину, глава 14, файл 4), **планирования задач** и **передачи сообщений**.

### Просто: реализация очереди с использованием стеков

- **Проблема**: реализовать очередь, используя только два стека.

- **Шаблон**: используйте один стек для нажатия и один для выталкивания. Когда стек pop станет пустым, перенесите все элементы из стека push (обратный порядок).

```python
class MyQueue:
    def __init__(self):
        self.push_stack = []
        self.pop_stack = []

    def push(self, x):
        self.push_stack.append(x)

    def pop(self):
        if not self.pop_stack:
            while self.push_stack:
                self.pop_stack.append(self.push_stack.pop())
        return self.pop_stack.pop()

    def peek(self):
        if not self.pop_stack:
            while self.push_stack:
                self.pop_stack.append(self.push_stack.pop())
        return self.pop_stack[-1]

    def empty(self):
        return not self.push_stack and not self.pop_stack
```

- Амортизированный $O(1)$ для каждой операции: каждый элемент перемещается между стопками не более одного раза.

## Приоритетные очереди и кучи

– **очередь с приоритетом** сначала возвращает наименьший (или наибольший) элемент, независимо от порядка вставки. Стандартная реализация — это **двоичная куча**.

- **min-heap** — это полное двоичное дерево, в котором каждый родительский элемент меньше своих дочерних элементов. Минимум всегда находится в корне. Хранится в виде массива: дочерние элементы узла $i$ находятся в позициях $2i + 1$ и $2i + 2$.| Операция | Время |
|-----------|------|
| Вставить | $O(\log n)$ |
| Получить мин | $O(1)$ |
| Извлечь мин | $O(\log n)$ |
| Построить кучу из массива | $O(n)$ |

— Модуль Python `heapq` предоставляет минимальную кучу. Для максимальной кучи отмените значения.

```python
import heapq

# Min-heap
h = []
heapq.heappush(h, 5)
heapq.heappush(h, 2)
heapq.heappush(h, 8)
print(heapq.heappop(h))  # 2 (smallest)

# Max-heap trick: negate values
heapq.heappush(h, -10)
print(-heapq.heappop(h))  # 10 (largest)
```

### Medium: K-й самый большой элемент массива

- **Задача**: найти k-й по величине элемент.

- **Шаблон**: поддерживать минимальную кучу размером $k$. Корень кучи является k-м по величине. Если в куче есть элементы $k$ и новый элемент больше корня, замените корень.

```python
import heapq

def find_kth_largest(nums, k):
    heap = nums[:k]
    heapq.heapify(heap)  # O(k)

    for num in nums[k:]:
        if num > heap[0]:
            heapq.heapreplace(heap, num)  # pop min, push num: O(log k)

    return heap[0]
```

- $O(n \log k)$ время, $O(k)$ пространство. Гораздо лучше, чем сортировка ($O(n \log n)$), когда $k \ll n$.

- **Подводная ошибка**: использование максимальной кучи размером $n$ и выталкивание $k$ раз также работает, но медленнее: $O(n + k \log n)$. Минимальная куча размером $k$ является оптимальным подходом.

### Сложный: объединить K отсортированных списков

- **Проблема**: объединить отсортированные по $k$ связанные списки в один отсортированный список.

- **Шаблон**: используйте минимальную кучу, содержащую заголовок каждого списка. Извлеките самый маленький узел, добавьте его к результату и поместите следующий узел в кучу.

```python
import heapq

def merge_k_lists(lists):
    heap = []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(heap, (lst.val, i, lst))

    dummy = ListNode(0)
    curr = dummy

    while heap:
        val, i, node = heapq.heappop(heap)
        curr.next = node
        curr = curr.next
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))

    return dummy.next
```

- $O(n \log k)$, где $n$ — общее количество узлов. Куча всегда содержит не более элементов $k$.

- **Подводная ошибка**: `i` (индекс) в кортеже кучи является тай-брейкером. Без него Python пытается сравнить объекты `ListNode`, когда значения равны, что приводит к сбою, поскольку `ListNode` не поддерживает `<`. Индекс обеспечивает корректное сравнение.

## Резюме распространенных ошибок

| ловушка | Пример | Исправить |
|---------|---------|-----|
| Нулевой указатель на `fast.next` | Обнаружение цикла с помощью `while fast.next` | Проверьте `fast and fast.next` |
| Не обрабатывать пустой список | Реверс `None` | Добавить `if not head` охранник |
| Опустошение стека | Выскакивание из пустой стопки | Проверьте `len(stack) > 0` или `if stack` |
| Забыв стража | Гистограмма пропускает последние бары | Добавьте 0, чтобы очистить стек |
| Отсутствует тай-брейк в куче | Сравнение несравнимых предметов | Добавить индекс в кортеж кучи |
| Изменение списка во время итерации | Удаление узлов при перемещении | Использовать шаблон «предыдущий/текущий» или фиктивный заголовок |
