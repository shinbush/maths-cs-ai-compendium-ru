## Почему шаблоны, а не запоминание

- На LeetCode, NeetCode и HackerRank существуют тысячи проблем с кодированием. Никто не может запомнить их все, и попытка сделать это — проигрышная стратегия. Интервьюеры не выбирают проблемы из фиксированного списка, они модифицируют, комбинируют и маскируют их. Заученное решение «Две суммы» не поможет вам, когда интервьюер задаст вариант, которого вы никогда не видели.

- Хорошая новость: существует всего около **15-20 основных шаблонов** (два указателя, скользящее окно, BFS/DFS, DP, возврат и т. д.). Любая проблема, какой бы новой она ни выглядела на первый взгляд, сводится к одной из этих закономерностей или их комбинации. Собеседование не проверяет, сталкивались ли вы раньше с этой конкретной проблемой. Он проверяет, можете ли вы **очистить контекст**, историю, конкретные типы данных, крайние случаи и распознать лежащий в их основе шаблон.

- Рассмотрим эти три проблемы:
    - «Найдите два числа в массиве, сумма которых равна целевому значению».
    - «Найдите две молекулы, сумма энергий связи которых равна порогу».
    - «Имея список остатков на счетах, найдите два счета, совокупная стоимость которых равна долгу».

- Они выглядят по-другому. Это одна и та же проблема: **Две суммы**. Контекст (числа, молекулы, счета) не имеет значения. Структура такая: поиск дополнения в коллекции → поиск по хеш-карте.

- Вот почему в этой главе изучаются **шаблоны, основанные на интуиции**, а не решения, основанные на повторении. По каждому шаблону поясняем:
    - **Какое структурное свойство** проблемы сигнализирует об этом шаблоне (отсортированный ввод → два указателя; ограничение подмассива → скользящее окно; оптимальная подструктура + перекрывающиеся подзадачи → DP).
    - **Почему шаблон работает** — математические или логические рассуждения, а не просто «он дает правильный ответ».
    – **Как адаптировать** — показывая простые, средние и сложные варианты, в которых одна и та же основная идея применяется в разных контекстах.

- Когда вы глубоко поймете, *почему* работает скользящее окно (монотонность ограничения означает, что расширения/сжатия достаточно), вы сможете применить его к любой проблеме с этой структурой, даже к той, которую вы никогда не видели. Если вы запомните только код «Самая длинная подстрока без повторяющихся символов», вы застрянете в тот момент, когда проблема изменится.

- Практическая стратегия:
    1. **Изучите шаблон** (эта глава).
    2. **Практикуйте распознавание** в замаскированных проблемах (описания NeetCode в конце каждого файла).
    3. **Практикуйте реализацию** в условиях нехватки времени.
    4. На собеседовании: прочитайте проблему → очистите контекст → определите закономерность → реализуйте.

## Обозначение Big O

— Когда мы говорим, что алгоритм «быстрый» или «медленный», нам нужен точный способ его измерения. **Обозначение Big O** описывает, как время выполнения алгоритма (или использование пространства) увеличивается по мере увеличения входного размера $n$, игнорируя постоянные коэффициенты и члены младшего порядка.

- Формальное определение: $f(n) = O(g(n))$ означает, что существуют константы $c > 0$ и $n_0$ такие, что $f(n) \leq c \cdot g(n)$ для всех $n \geq n_0$. Говоря простым языком: $f$ растет не быстрее, чем $g$, для больших входных данных.

- Зачем игнорировать константы? Потому что алгоритм $2n$ и алгоритм $5n$ являются $O(n)$: они масштабируются одинаково. На более быстром компьютере константы меняются, а масштабирование — нет. Big O отражает **внутреннюю** сложность проблемы, независимую от аппаратного обеспечения.

### Иерархия темпов роста

- От самого быстрого к самому медленному:| Большой О | Имя | Пример | $n = 10^6$ операции |
|-------|------|---------|----------------------|
| $O(1)$ | Константа | Доступ к массиву, поиск по хешу | 1 |
| $O(\log n)$ | Логарифмический | Бинарный поиск | 20 |
| $O(n)$ | Линейный | Линейное сканирование, одноконтурное | $10^6$ |
| $O(n \log n)$ | Линеарифмический | Сортировка слиянием, эффективная сортировка | $2 \times 10^7$ |
| $O(n^2)$ | Квадратичный | Вложенные циклы, пары перебора | $10^{12}$ (слишком медленно) |
| $O(n^3)$ | Кубический | Тройные вложенные циклы, умножение матрицы | $10^{18}$ (слишком медленно) |
| $O(2^n)$ | Экспоненциальный | Все подмножества, обратный перебор | $10^{301030}$ (невозможно) |
| $O(n!)$ | Факториал | Все перестановки | абсурд |

- **Практическое правило**: современные компьютеры выполняют примерно $10^8$–$10^9$ простых операций в секунду. Для ограничения времени в 1 секунду:
    - $O(n)$ работает для $n \leq 10^8$
    - $O(n \log n)$ работает для $n \leq 10^7$
    - $O(n^2)$ работает для $n \leq 10^4$
    - $O(2^n)$ работает для $n \leq 25$

- Эта таблица сразу скажет вам, достаточно ли быстр ваш подход. Если $n = 10^5$ и ваше решение — $O(n^2)$, это будут операции $10^{10}$ — слишком медленно. Вам нужен лучший алгоритм.

### Как анализировать большое О

- **Один контур** по элементам $n$: $O(n)$.

```python
total = 0
for x in arr:   # n iterations
    total += x   # O(1) per iteration
# Total: O(n)
```

- **Вложенные циклы**: умножайте количество итераций.

```python
for i in range(n):       # n iterations
    for j in range(n):   # n iterations each
        process(i, j)    # O(1)
# Total: O(n^2)
```

- **Петля с делением пополам**: $O(\log n)$. Каждая итерация уменьшает размер задачи вдвое, поэтому требуется $\log_2 n$ итераций.

```python
i = n
while i > 0:
    process(i)
    i //= 2
# Total: O(log n)
```

- **Вложенный цикл, где внутреннее зависит от внешнего**:

```python
for i in range(n):
    for j in range(i):   # j goes from 0 to i-1
        process(i, j)
# Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n^2)
```

- **Рекурсивный**: напишите рекуррентное соотношение и решите его (глава 13 посвящена Главной теореме). Например, сортировка слиянием: $T(n) = 2T(n/2) + O(n) = O(n \log n)$.

### Распространенные ловушки

- **Скрытые циклы**: `x in list` — это $O(n)$ в Python (линейное сканирование), а `x in set` — это $O(1)$. Использование `in` в списке внутри цикла дает $O(n^2)$, а не $O(n)$.

```python
# BAD: O(n^2) — "in" on a list is O(n)
for x in arr:
    if x in another_list:
        process(x)

# GOOD: O(n) — convert to set first
another_set = set(another_list)
for x in arr:
    if x in another_set:
        process(x)
```

- **Объединение строк**: `s += c` в Python каждый раз копирует всю строку. Внутри цикла $n$ итераций: $O(1 + 2 + \cdots + n) = O(n^2)$.

- **Доминирование сортировки**: если ваш алгоритм сортирует ($O(n \log n)$), а затем выполняет линейное сканирование ($O(n)$), общая сумма равна $O(n \log n)$ — сортировка доминирует.

- **Амортизированная сложность**: некоторые операции иногда бывают дорогостоящими, но в среднем дешевыми. Добавление динамического массива $O(1)$ амортизировано, поскольку редкое изменение размера $O(n)$ распространяется на дешевые добавления $n$. Не путайте амортизированный $O(1)$ с наихудшим $O(1)$.

### Космическая сложность

- Пространственная сложность подчиняется тем же правилам Big O, которые применяются к использованию памяти, а не времени.

- Алгоритмы **на месте** используют дополнительное пространство $O(1)$ (не считая входных данных). Быстрая сортировка — это пространство $O(\log n)$ (глубина стека рекурсии). Сортировка слиянием — $O(n)$ (временные массивы для слияния).

- **Стек рекурсии**: каждый рекурсивный вызов использует пространство стека. На глубоких уровнях рекурсии $n$ используется пространство $O(n)$, даже если каждый вызов не выделяет дополнительную память. Вот почему рекурсивная DFS на графе с узлами $n$ использует пространство $O(n)$.

- При проведении интервью всегда указывайте временную и пространственную сложность. Время $O(n)$, пространственное решение $O(n)$ часто приемлемо, но лучше использовать пространственное решение $O(n)$, $O(1)$. Интервьюер может попросить вас оптимизировать то или иное.

## Рекурсия

- **Рекурсия** — это когда функция вызывает саму себя для решения меньшего экземпляра той же проблемы. Это наиболее естественный подход для задач с рекурсивной структурой: деревьями, вложенными структурами, принципами «разделяй и властвуй» и математическими последовательностями.- Каждая рекурсивная функция состоит из двух частей:
    1. **Базовый случай**: наименьший экземпляр, который можно решить напрямую (без рекурсии). Это то, что останавливает рекурсию.
    2. **Рекурсивный случай**: разбейте задачу на более мелкие подзадачи, решите их рекурсивно и объедините результаты.

### Пример: факториал

```python
def factorial(n):
    if n <= 1:        # base case
        return 1
    return n * factorial(n - 1)  # recursive case
```

- Как это работает для `factorial(4)`:
    - `factorial(4)` вызывает `factorial(3)`
    - `factorial(3)` звонит `factorial(2)`
    - `factorial(2)` звонит `factorial(1)`
    - `factorial(1)` возвращает `1` (базовый случай)
    - `factorial(2)` возвращает `2 * 1 = 2`
    - `factorial(3)` возвращает `3 * 2 = 6`
    - `factorial(4)` возвращает `4 * 6 = 24`

- Каждый вызов помещается в **стек вызовов**. Стек растет до тех пор, пока не будет достигнут базовый случай, а затем сокращается при каждом возврате вызова. Если рекурсия слишком глубокая (например, `factorial(1000000)` в Python), стек переполняется (`RecursionError`). Предел рекурсии Python по умолчанию равен 1000.

### Как мыслить рекурсивно

- Ключевой сдвиг в сознании: **доверьтесь рекурсии**. При написании рекурсивной функции предположите, что рекурсивный вызов возвращает правильный ответ на меньшую подзадачу. Ваша работа заключается только в том, чтобы:
    1. Разберитесь с базовым случаем.
    2. Разбейте проблему на более мелкие части.
    3. Объедините результаты.

- Вам не нужно отслеживать в голове каждый рекурсивный вызов. Это похоже на попытку понять цикл, мысленно выполняя каждую итерацию. Вместо этого проверьте: «если рекурсивный вызов дает мне правильный ответ для меньшего ввода, дает ли мой шаг комбинации правильный ответ для полного ввода?»

### Пример: рекурсия в связанном списке

- Рекурсивно перевернуть связанный список:

```python
def reverse(head):
    if not head or not head.next:   # base case: 0 or 1 nodes
        return head

    new_head = reverse(head.next)   # reverse the rest
    head.next.next = head           # point the next node back to me
    head.next = None                # I am now the tail
    return new_head
```

- **Доверяйте рекурсии**: `reverse(head.next)` правильно переворачивает остальную часть списка и возвращает новую голову. Нам просто нужно прикрепить текущий узел в конце.

### Пример: рекурсия по дереву

- Вычислить высоту двоичного дерева:

```python
def height(root):
    if not root:           # base case: empty tree has height 0
        return 0
    left_h = height(root.left)    # height of left subtree
    right_h = height(root.right)  # height of right subtree
    return 1 + max(left_h, right_h)  # this node adds 1 level
```

— Этот шаблон — «рекурсия слева, рекурсия справа, объединение» — решает подавляющее большинство проблем с деревьями (см. файл 03).

### Рекурсия против итерации

- Любой рекурсивный алгоритм можно преобразовать в итеративный (с использованием явного стека или цикла). Итерация позволяет избежать накладных расходов на стек вызовов и риска переполнения стека.

- **Когда лучше использовать рекурсию**: задача имеет естественную рекурсивную структуру (деревья, вложенные данные, принцип «разделяй и властвуй»). Рекурсивное решение чище и его легче рассуждать.

- **Когда предпочтительнее итерация**: глубина рекурсии может быть очень большой (например, обработка связанного списка узлов $10^6$). Итеративное решение позволяет избежать переполнения стека.

- **Хвостовая рекурсия**: рекурсивный вызов является «хвостовой рекурсией», если это последняя операция в функции (после возврата из рекурсивного вызова никакая работа не выполняется). Некоторые языки (Scheme, Scala) оптимизируют хвостовые вызовы, чтобы использовать постоянное пространство стека. Python **не** оптимизирует хвостовые вызовы, поэтому хвостовая рекурсия в Python по-прежнему использует стековое пространство $O(n)$.

### Распространенные ошибки

| ловушка | Пример | Исправить |
|---------|---------|-----|
| Отсутствует базовый вариант | Бесконечная рекурсия → переполнение стека | Всегда определяйте, когда остановиться |
| Неправильный базовый регистр | Off-by-one в рекурсивном разложении | Тест с наименьшими входными данными (0, 1, 2) |
| Не уменьшая проблему | `f(n)` вызывает `f(n)` вместо `f(n-1)` | Убедитесь, что подзадача строго меньше |
| Избыточные вычисления | Фибоначчи: `f(n) = f(n-1) + f(n-2)` пересчитывает экспоненциально | Используйте мемоизацию (→ DP) |
| Предел рекурсии Python | `factorial(10000)` вылетает | Используйте `sys.setrecursionlimit` или преобразуйте в итерацию |

## Возврат

- **Возврат** – это систематический способ исследовать все возможные решения, постепенно выстраивая их и отказываясь от частичных решений, которые не могут привести к правильному ответу.

- Думайте об этом как о перемещении по лабиринту. На каждом перекрестке вы выбираете путь. Если вы зашли в тупик, вы вернетесь к последнему перекрестку и попробуете другой путь. Вы не начинаете все сначала — вы **возвращаетесь** к самой последней точке принятия решения.### Три шага

Каждый алгоритм обратного отслеживания следует одной и той же схеме:

1. **Выбрать**: выберите кандидата для расширения текущего частичного решения.
2. **Исследовать**: рекурсивно попытаться построить полное решение на основе этого кандидата.
3. **Отменить выбор**: отменить выбор (возврат) и попробовать следующий кандидат.

```python
def backtrack(state, choices, result):
    if is_complete(state):
        result.append(state.copy())
        return

    for choice in choices:
        if is_valid(choice, state):
            state.add(choice)           # 1. choose
            backtrack(state, choices, result)  # 2. explore
            state.remove(choice)        # 3. unchoose (backtrack)
```

– Шаг **отменить выбор** — это то, что отличает возврат с возвратом от простой рекурсии. Без этого государство аккумулирует все варианты выбора, и вы не сможете исследовать альтернативные пути.

### Когда использовать возврат

- Задача требует **перечислить все допустимые конфигурации**: все перестановки, все подмножества, все допустимые расположения (например, N-ферзей).
- Задача требует **найти любую допустимую конфигурацию**: решение судоку, поиск пути в лабиринте.
- Пространство поиска велико, но его можно **ограничить**: большинство частичных решений можно отклонить на ранней стадии, не исследовав их полностью.

### Как обрезка ускоряет процесс

- Без сокращения при возврате исследуются все возможные комбинации — экспоненциальное время. **Обрезка** рано обрезает ветки:

```python
for choice in choices:
    if not is_valid(choice, state):
        continue  # PRUNE: skip this entire subtree

    state.add(choice)
    backtrack(state, choices, result)
    state.remove(choice)
```

- В N-Queens (файл 05) проверка конфликтов столбцов и диагоналей перед размещением ферзя сокращает дерево поиска с $n^n$ до примерно $n!$ кандидатов. Для $n = 8$ это 16 миллионов → 40 000. Хорошее сокращение делает экспоненциальные алгоритмы практичными для умеренных $n$.

### Генерация всех подмножеств (простейший возврат)

```python
def subsets(nums):
    result = []

    def backtrack(start, path):
        result.append(path[:])  # every partial solution is a valid subset

        for i in range(start, len(nums)):
            path.append(nums[i])        # choose
            backtrack(i + 1, path)       # explore (i+1: no reuse)
            path.pop()                   # unchoose

    backtrack(0, [])
    return result
```

- Для `[1, 2, 3]` дерево рекурсии:
    - `[]` → `[1]` → `[1,2]` → `[1,2,3]` (возврат) → `[1,3]` (возврат) → `[2]` → `[2,3]` (возврат) → `[3]`

— Каждый узел в дереве — это один вызов `backtrack`. Каждый лист (и промежуточный узел) создает подмножество. Всего подмножеств: $2^n$.

### Генерация всех перестановок

```python
def permutations(nums):
    result = []

    def backtrack(path, remaining):
        if not remaining:
            result.append(path[:])
            return

        for i in range(len(remaining)):
            path.append(remaining[i])                    # choose
            backtrack(path, remaining[:i] + remaining[i+1:])  # explore
            path.pop()                                   # unchoose

    backtrack([], nums)
    return result
```

- Всего перестановок: $n!$. Для создания каждого из них требуется $O(n)$ работы `remaining`, поэтому общая сумма равна $O(n \cdot n!)$.

### Распространенные ошибки

| ловушка | Пример | Исправить |
|---------|---------|-----|
| Забыл скопировать путь | `result.append(path)` — все записи находятся в одном списке | `result.append(path[:])` или `path.copy()` |
| Не отступать (отменить выбор) | Штат продолжает расти, последующие кандидаты видят устаревшее состояние | Всегда `path.pop()` или `state.remove()` после рекурсивного вызова |
| Неправильный старт цикла | Подмножества с дубликатами или перестановки с нежелательным повторным использованием | Используйте параметр `start`, чтобы избежать повторного обращения к предыдущим индексам |
| Пропуск обрезки | Исследование заведомо недействительных ветвей | Добавьте `if not is_valid: continue` перед рекурсивным вызовом |

## Динамическое программирование

- **Динамическое программирование (ДП)** — это метод оптимизации задач, в которых одни и те же подзадачи решаются неоднократно. Вместо повторных вычислений DP решает каждую подзадачу один раз и сохраняет результат.

- ДП применяется, когда проблема имеет два свойства:
    1. **Оптимальная подструктура**: оптимальное решение может быть построено из оптимальных решений подзадач.
    2. **Перекрывающиеся подзадачи**: одни и те же подзадачи появляются в рекурсии несколько раз.

### Мотивация Фибоначчи

- Наивный рекурсивный Фибоначчи:

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

- Для `fib(5)` дерево рекурсии:
    - `fib(5)` вызывает `fib(4)` и `fib(3)`
    - `fib(4)` вызывает `fib(3)` и `fib(2)`
    - `fib(3)` вычисляется **дважды**, `fib(2)` вычисляется **трижды**

- Это $O(2^n)$, поскольку дерево разветвляется на каждом уровне, и большинство ветвей пересчитывают одни и те же значения. Для `fib(50)` он берет на себя операции $10^{15}$ — это невозможно.

- С **мемоизацией** (DP сверху вниз):

```python
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
```

- Теперь `fib(3)` вычисляется один раз, сохраняется и просматривается при последующих вызовах. Итого: $O(n)$ время, $O(n)$ пространство.

- С **таблицей** (DP снизу вверх):

```python
def fib_tab(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
```— То же время $O(n)$, но решение строится снизу вверх без рекурсии. Может быть дополнительно оптимизирован до пространства $O(1)$, поскольку каждое значение зависит только от двух предыдущих.

### Рецепт ДП

При любой проблеме с DP выполните следующие действия:

1. **Определите состояние**: что представляет собой `dp[i]` (или `dp[i][j]`)? Это самый трудный шаг. Государство должно собирать достаточно информации для принятия оптимальных решений.

2. **Напишите повторение**: как `dp[i]` относится к более мелким подзадачам? Это формула перехода.

3. **Определите базовый вариант**: какие наименьшие подзадачи можно решить напрямую?

4. **Определите порядок итераций**: какие подзадачи необходимо решить перед какой? Снизу вверх: итерация в том порядке, который обеспечивает разрешение зависимостей. Сверху вниз: рекурсия обрабатывает это автоматически.

5. **Оптимизировать пространство** (необязательно): если `dp[i]` зависит только от предыдущей строки или нескольких предыдущих записей, вам не нужна полная таблица.

### Пример: мыслительный процесс

**Задача**: по массиву целых положительных чисел найти максимальную сумму несмежных элементов (Грабитель).

**Шаг 1. Определите состояние**: `dp[i]` = максимальная сумма с учетом элементов `nums[0..i]`.

**Шаг 2. Напишите повторение**: для элемента $i$ мы либо:
- Пропустить: `dp[i] = dp[i-1]` (лучшая сумма без элемента $i$).
- Возьмите: `dp[i] = dp[i-2] + nums[i]` (необходимо пропустить элемент $i-1$, затем добавить элемент $i$).

Итак: `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`.

**Шаг 3. Базовые варианты**: `dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`.

**Шаг 4 — Порядок итераций**: слева направо (каждое состояние зависит от двух предыдущих состояний).

**Шаг 5 — Оптимизация пространства**: нужны только два последних значения.

```python
def rob(nums):
    if len(nums) == 1:
        return nums[0]

    prev2, prev1 = nums[0], max(nums[0], nums[1])

    for i in range(2, len(nums)):
        curr = max(prev1, prev2 + nums[i])
        prev2, prev1 = prev1, curr

    return prev1
```

### Как определить проблемы DP

- Задача требует **оптимума** (минимальные затраты, максимальная прибыль, самая длинная последовательность) или **счета** (количество способов).
- В задаче есть **варианты выбора** на каждом этапе** (пропустить/пропустить, пойти влево/вправо, использовать эту монету или нет), и лучший общий ответ зависит от лучших ответов на подзадачи.
- При рисовании дерева рекурсии выявляются **повторяющиеся подзадачи**.
- Грубая сила экспоненциальна, но **отдельных состояний** гораздо меньше, чем при рекурсивных вызовах.

### Категории ДП

- **1D DP**: состояние зависит от одного индекса. Примеры: подъем по лестнице, грабитель дома, максимальный подмассив.

- **2D DP**: состояние зависит от двух индексов. Примеры: самая длинная общая подпоследовательность (`dp[i][j]` для первых символов $i$ строки 1 и первых символов $j$ строки 2), расстояние редактирования, проблемы с путями сетки.

- **Интервал DP**: состояние представляет собой диапазон `dp[i][j]`, представляющий подзадачу `arr[i..j]`. Примеры: матричное цепное умножение, лопнувшие шарики.

- **Рюкзак DP**: состояние — это индекс предмета и его вместимость. Примеры: рюкзак 0/1, размена монет, подмножество суммы.

- **Битовая маска**: состояние включает битовую маску, показывающую, какие элементы были использованы. Примеры: TSP, задача о назначениях. Пространство состояний — $O(2^n \cdot n)$, возможно для $n \leq 20$.

### Сверху вниз против снизу вверх

| | Сверху вниз (мемоизация) | Снизу вверх (таблица) |
|--|---|---|
| Реализация | Рекурсивный + кеш | Итеративный + таблица |
| Вычисляет | Только те подзадачи, которые действительно необходимы | Все подзадачи до цели |
| Риск переполнения стека | Да (глубокая рекурсия) | Нет |
| Оптимизация пространства | сложнее | Проще (используйте подвижный массив) |
| Простота кодирования | Часто более естественно (рекурсия записи, добавление кэша) | Требуется подумать о порядке итерации |

- На собеседованиях писать код сверху вниз зачастую быстрее. В производственной среде обычно предпочтительнее использовать восходящий метод для повышения производительности (отсутствие накладных расходов на рекурсию, лучшее поведение кэша).

### Распространенные ошибки| ловушка | Пример | Исправить |
|---------|---------|-----|
| Неверное определение состояния | `dp[i]` не собирает достаточно информации для принятия решений | Добавьте размеры (например, `dp[i][j]` вместо `dp[i]`) |
| Отсутствует базовый вариант | `dp[0]` неверно → все последующие значения неверны | Проверьте базовый вариант вручную |
| Неправильный порядок итерации | Вычисление `dp[i]` перед его зависимостями | Нарисуйте стрелки зависимостей и выполните итерацию соответственно |
| Неправильная инициализация `dp` | Использование 0, когда оно должно быть бесконечностью (для минимальных проблем) | `float('inf')` для минимизации, `float('-inf')` для максимизации |
| Забыли рассмотреть вариант «пропустить» | Всегда брать текущий элемент | Рецидив обычно имеет `max(take, skip)` |
| Изменяемый аргумент по умолчанию | `def f(memo={})` разделяет кэш между вызовами | `def f(memo=None): if memo is None: memo = {}` |
| С точностью до одного в 2D DP | Индексирование `text1[i]`, когда `dp` имеет 1-й индекс | `dp` имеет размер `(m+1) x (n+1)`, доступ `text1[i-1]` |

## Собираем все вместе

- Эти четыре понятия образуют прогрессию:
    1. **Big O** сообщает вам, достаточно ли быстро заход на посадку.
    2. **Рекурсия** разбивает задачу на подзадачи.
    3. **Возврат** — это рекурсия + выбор + отмена для исчерпывающего поиска.
    4. **DP** — рекурсия + кеширование для оптимизации перекрывающихся подзадач.

- Когда вы видите новую проблему:
    - Оцените входной размер $n$. Какое большое О приемлемо?
    - Если перебор экспоненциальный и задача требует перебора/нахождения конфигураций: **обратное отслеживание** (с обрезкой для большей практичности).
    - Если грубая сила экспоненциальна и задача требует оптимума или подсчета, и вы видите перекрывающиеся подзадачи: **DP**.
    - Если структура задачи сокращает пространство поиска вдвое: **бинарный поиск** или **разделяй и властвуй**.
    - Если проблема связана с последовательностями с ограничением на подмассивы: **скользящее окно** или **два указателя**.
    - Если проблема требует быстрого поиска: **хеш-карта**.
