## Triton: ядра графического процессора в Python

- **Triton** (OpenAI) — это язык на основе Python для написания ядер графических процессоров. Вместо того, чтобы рассуждать об отдельных потоках (CUDA), вы рассуждаете о **блоках** данных. Компилятор Triton автоматически обрабатывает сопоставление потоков, объединение памяти, управление общей памятью и многие другие оптимизации.

- **Почему Triton важен**: CUDA C требует глубоких знаний в области планирования деформации, конфликтов общих банков памяти, давления регистров и шаблонов объединения. Triton абстрагирует большую часть этого, делая разработку ядра графического процессора доступной для исследователей машинного обучения, которые знают Python, но не знают системное программирование.

### Ваше первое ядро Triton

```python
import triton
import triton.language as tl
import torch

@triton.jit
def add_kernel(
    x_ptr, y_ptr, output_ptr,
    n_elements,
    BLOCK_SIZE: tl.constexpr,  # compile-time constant
):
    # Each program instance processes one block of BLOCK_SIZE elements
    pid = tl.program_id(axis=0)  # which block am I?
    block_start = pid * BLOCK_SIZE

    # Offsets for this block
    offsets = block_start + tl.arange(0, BLOCK_SIZE)

    # Mask to handle the case where n_elements is not a multiple of BLOCK_SIZE
    mask = offsets < n_elements

    # Load data (masked: out-of-bounds reads return 0)
    x = tl.load(x_ptr + offsets, mask=mask)
    y = tl.load(y_ptr + offsets, mask=mask)

    # Compute
    output = x + y

    # Store result
    tl.store(output_ptr + offsets, output, mask=mask)


def add(x: torch.Tensor, y: torch.Tensor) -> torch.Tensor:
    output = torch.empty_like(x)
    n_elements = output.numel()

    # Launch: one program per block
    grid = lambda meta: (triton.cdiv(n_elements, meta['BLOCK_SIZE']),)
    add_kernel[grid](x, y, output, n_elements, BLOCK_SIZE=1024)

    return output


# Usage
x = torch.randn(1000000, device='cuda')
y = torch.randn(1000000, device='cuda')
z = add(x, y)
```

- **Ключевые отличия от CUDA**:
    - Нет явного управления потоками. Вы думаете **блоками** (программами), а не потоками.
    - `tl.arange(0, BLOCK_SIZE)` создает вектор смещений для всего блока. Все операции над этим вектором неявно векторизуются.
    - `mask` обрабатывает граничные условия (например, регистры маски AVX-512, файл 03). Никакого скалярного цикла очистки не требуется.
    - `tl.load` и `tl.store` автоматически обрабатывают объединенный доступ.
    - `@triton.jit` компилирует функцию в PTX (сборку графического процессора) при первом вызове, затем кэширует скомпилированное ядро.

### Ядро Triton Softmax

— Softmax — отличный пример Triton, поскольку он требует нескольких проходов над данными (максимум, вычитание, выражение, сумма, деление) и получает преимущества от хранения данных в SRAM (общая память) между проходами:

```python
@triton.jit
def softmax_kernel(
    output_ptr, input_ptr, input_row_stride, output_row_stride, n_cols,
    BLOCK_SIZE: tl.constexpr,
):
    # Each program handles one row
    row_idx = tl.program_id(0)
    row_start = input_ptr + row_idx * input_row_stride

    # Load the row
    col_offsets = tl.arange(0, BLOCK_SIZE)
    mask = col_offsets < n_cols
    row = tl.load(row_start + col_offsets, mask=mask, other=-float('inf'))

    # Softmax: max for numerical stability, then exp, then normalise
    row_max = tl.max(row, axis=0)
    numerator = tl.exp(row - row_max)
    denominator = tl.sum(numerator, axis=0)
    softmax_output = numerator / denominator

    # Store result
    output_start = output_ptr + row_idx * output_row_stride
    tl.store(output_start + col_offsets, softmax_output, mask=mask)
```

- В PyTorch `F.softmax(x, dim=-1)` запускает 3 отдельных ядра (макс, выражение и сумма, деление), каждое из которых читает и записывает в глобальную память. Версия Triton делает все в одном ядре, сохраняя данные в регистрах/SRAM. Благодаря этому **слиянию ядер** пользовательские ядра Triton могут работать в 2–4 раза быстрее, чем встроенные операции PyTorch.

### Тритон Автонастройка

- Triton поддерживает **автоматическую настройку**: попробуйте несколько конфигураций и выберите самую быструю:

```python

    configs=[
        triton.Config({'BLOCK_SIZE_M': 128, 'BLOCK_SIZE_N': 128, 'BLOCK_SIZE_K': 32}),

    ...
```

- Triton тестирует каждую конфигурацию на реальном оборудовании и выбирает самую быструю. Оптимальные размеры тайлов зависят от архитектуры графического процессора, размеров матрицы и расположения памяти — автонастройка находит их без ручных экспериментов.

### Triton против CUDA: когда использовать каждый

| | Тритон | КУДА С |
|--|--------|--------|
| Язык | Питон | Си/С++ |
| Абстракция | Блочный уровень | Уровень потока |

| Объединение | Автоматический | Руководство |

- **Используйте Triton** для: объединенных ядер, пользовательских шаблонов внимания, функций активации, большинства потребностей ядра для исследования машинного обучения.
- **Используйте CUDA C** для: максимальной производительности (последние 5-20%), примитивов уровня деформации, сложного параллелизма, зависящего от данных, когда Triton не может выразить ваш шаблон.

## Практический пример: мгновенное внимание

- **Flash Attention** (Дао и др., 2022 г.) — наиболее эффективное пользовательское ядро в новейшем машинном обучении. Он рассчитывает внимание с помощью памяти $O(n)$ вместо $O(n^2)$, что позволяет выполнять гораздо более длинные последовательности.

- **Проблема**: стандартное внимание вычисляет $\text{softmax}(QK^T / \sqrt{d}) \cdot V$. Матрица $QK^T$ имеет вид $n \times n$, где $n$ — длина последовательности. Для $n = 128K$ эта матрица имеет размер $128K \times 128K \times 4$ байт = 64 ГБ. Он не помещается в память графического процессора.- **Идея**: вам не нужно материализовать полную матрицу $n \times n$. Подсчитайте внимание в **тайлах**: загрузите блок $Q$, блок $K$, вычислите их частичные оценки внимания, суммируйте и перейдите к следующему блоку. Матрица $n \times n$ никогда не материализуется полностью — в SRAM одновременно существует только один тайл.

- **Онлайн-софтмакс**: самая сложная часть — это софтмакс, который требует знания максимума по всей строке (для числовой стабильности). Flash Attention использует трюк **онлайн-softmax**: поддерживает текущий максимум и изменяет масштаб ранее вычисленных значений при обнаружении нового максимума. Это позволяет вычислять softmax постепенно, по одному тайлу за раз.

- Алгоритм:

```
For each block of Q rows:
    For each block of K columns:
        1. Load Q_block from HBM to SRAM
        2. Load K_block from HBM to SRAM
        3. Compute S_block = Q_block @ K_block.T (in SRAM)
        4. Update running max, rescale previous results
        5. Compute exp(S_block - running_max)
        6. Update running sum and output accumulator
    Load V_block and compute final output
    Write output block back to HBM
```

- **Почему это быстро**: внутренний цикл полностью работает в SRAM (разделяемой памяти). Доступ к глобальной памяти (HBM) осуществляется только для загрузки блоков Q, K, V и записи окончательного результата. Коэффициент повторного использования данных пропорционален размеру SRAM, доступ к которому примерно в 100 раз быстрее, чем к HBM.

- Flash Attention реализован как в Triton, так и в CUDA C. Версия CUDA быстрее (~ на 10% эффективнее), но версия Triton гораздо более читабельна и модифицируема, что важно для исследования новых вариантов внимания.

## Архитектура ТПУ

– **TPU** (тензорные процессоры) – это специальные ускорители машинного обучения Google. Они используют радикально другой подход, чем графические процессоры:

- **Систолические массивы**: основным вычислительным блоком TPU является **Matrix Multiply Unit (MXU)**, систолический массив размером 128×128 или 256×256, который выполняет умножение матриц путем передачи данных через сетку единиц умножения-накопления. Данные поступают с краев и распространяются по массиву, при этом каждое устройство выполняет одно умножение-сложение и передает результаты следующему.

- В отличие от графических процессоров (которые планируют тысячи независимых потоков), систолический массив представляет собой единый детерминированный поток данных. Нет планирования потоков, нет расхождения в варпах, нет предсказания ветвей. Эта простота делает MXU чрезвычайно энергоэффективным при умножении матриц.

- **HBM**: TPU используют ту же высокоскоростную память, что и графические процессоры. TPU v5e имеет 16 ГБ HBM2e на чип; TPU v5p имеет 95 ГБ HBM2e.

- **ICI** (межчиповое соединение): модули TPU соединяют сотни TPU с помощью специальной высокоскоростной сети. Параллелизм данных и параллелизм моделей (глава 6) в модулях TPU изначально поддерживаются JAX.

- **BFloat16**: TPU первыми использовали bfloat16 (глава 13, файл 02). BF16 имеет тот же диапазон экспоненты, что и float32 (предотвращая переполнение во время обучения), с меньшей точностью мантиссы. Этот компромисс идеален для машинного обучения, где значения градиента охватывают широкий диапазон, но не требуют 23-битной точности.

### Программирование TPU: JAX и Pallas

- TPU программируются через **JAX** и **XLA**. Вы пишете код Python/JAX, `jax.jit` компилирует его в XLA HLO, а XLA компилирует HLO в инструкции, специфичные для TPU. Ни CUDA, ни C++.

```python
import jax
import jax.numpy as jnp

@jax.jit
def matmul(a, b):
    return jnp.dot(a, b)

# This runs on CPU, GPU, or TPU depending on the device
a = jnp.ones((1024, 1024))
b = jnp.ones((1024, 1024))
c = matmul(a, b)
```

- **Pallas** — это API разработки ядра JAX — JAX-эквивалент Triton. Он позволяет писать низкоуровневые ядра, которые XLA компилирует для графического процессора или TPU:

```python
from jax.experimental import pallas as pl
import jax.numpy as jnp

def add_kernel(x_ref, y_ref, o_ref):
    o_ref[...] = x_ref[...] + y_ref[...]

def add_pallas(x, y):
    return pl.pallas_call(
        add_kernel,
        out_shape=jax.ShapeDtypeStruct(x.shape, x.dtype),
        grid=(x.shape[0] // 128,),
        in_specs=[pl.BlockSpec((128,), lambda i: (i,)),
                  pl.BlockSpec((128,), lambda i: (i,))],
        out_specs=pl.BlockSpec((128,), lambda i: (i,)),
    )(x, y)
```

- Pallas новее и менее зрелый, чем Triton, но это единственный способ написать собственные ядра для TPU (поскольку TPU не поддерживают CUDA).

### Графический процессор против ТПУ

| | Графический процессор (NVIDIA) | ТПУ (Google) |
|--|-------------|--------------|
| Наличие | Любое облако, локально | Только Google Cloud |
| Программирование | CUDA C, Тритон, PyTorch | JAX/XLA, Паллас |
| Гибкость | Вычисления общего назначения | Оптимизирован для машинного обучения с большим количеством матриц |
| Пик матмуль ФЛОПС | Очень высокий (тензорные ядра) | Очень высокий (MXU) |
| Операции, не относящиеся к Matmul | Хорошо | Медленнее (направляется через векторный модуль, а не через MXU) |
| Многочиповое масштабирование | NVLink (8 графических процессоров), InfiniBand | ICI (тысячи ТПУ, более тесная интеграция) |
| Экономическая эффективность | Конкурентоспособный | Часто дешевле для крупномасштабного обучения |
| Экосистема | Крупнейший (PyTorch, TensorFlow, JAX) | JAX-ориентированный |

- **Используйте графические процессоры** для: большинства рабочих нагрузок машинного обучения, исследований на основе PyTorch, обработки логических выводов, рабочих нагрузок со значительными вычислениями, не относящимися к Matmul.
- **Используйте TPU** для крупномасштабного обучения JAX (тысячи чипов), экономичного обучения в Google Cloud, рабочих нагрузок, в которых преобладают матричные умножения.## Выбор правильного инструмента

| Рабочая нагрузка | Лучший инструмент | Почему |
|----------|-----------|-----|
| Обучение машинному обучению (PyTorch) | Графический процессор NVIDIA + CUDA/Тритон | Крупнейшая экосистема, лучший инструмент |
| Обучение машинному обучению (JAX, крупномасштабное) | ТПУ или графический процессор NVIDIA | TPU по цене в масштабах Google, GPU для гибкости |
| Пользовательские слитые ядра | Тритон (Python) или CUDA C | Triton за скорость разработки, CUDA за максимальную производительность |
| Пользовательские ядра JAX | Паллас | Единственный вариант для TPU, работает и с графическим процессором |
| Межплатформенный вывод | Vulkan (файл 07) или среда выполнения ONNX | Работает на любом графическом процессоре |
| Вывод о мобильных/периферийных устройствах | Металл (Apple), Вулкан (Android), ННАПИ | Ускорители для конкретных платформ |
| Вывод браузера | WebGPU (файл 07) | Единственная опция в браузере |
| Вывод только по процессору | Среда выполнения ONNX + AVX/NEON | Графический процессор не требуется, используется SIMD (файлы 02–03) |
| Новое оборудование | SDK для конкретного поставщика | У каждого акселератора есть свой набор инструментов |

1. Напишите и запустите ядро Triton для сложения векторов. Сравните его производительность со встроенным дополнением PyTorch.
```python
import triton
import triton.language as tl
import torch
import time

@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n
    x = tl.load(x_ptr + offs, mask=mask)
    y = tl.load(y_ptr + offs, mask=mask)
    tl.store(out_ptr + offs, x + y, mask=mask)

n = 10_000_000
x = torch.randn(n, device='cuda')
y = torch.randn(n, device='cuda')

# Triton
out_triton = torch.empty_like(x)
grid = lambda meta: (triton.cdiv(n, meta['BLOCK']),)
add_kernel[grid](x, y, out_triton, n, BLOCK=1024)

# PyTorch
out_torch = x + y

# Verify correctness
assert torch.allclose(out_triton, out_torch, atol=1e-5)

# Benchmark
torch.cuda.synchronize()
start = time.time()
for _ in range(1000):
    add_kernel[grid](x, y, out_triton, n, BLOCK=1024)
torch.cuda.synchronize()
triton_time = (time.time() - start) / 1000

start = time.time()
for _ in range(1000):
    out_torch = x + y
torch.cuda.synchronize()
torch_time = (time.time() - start) / 1000

print(f"Triton:  {triton_time*1000:.3f} ms")
print(f"PyTorch: {torch_time*1000:.3f} ms")
print(f"Ratio:   {torch_time/triton_time:.2f}x")
```

2. Напишите объединенное ядро Triton, которое выполняет умножение + сложение + ReLU за один проход. Сравните с тремя отдельными операциями PyTorch.
```python
import triton
import triton.language as tl
import torch
import time

@triton.jit
def fused_mul_add_relu_kernel(x_ptr, w_ptr, b_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n
    x = tl.load(x_ptr + offs, mask=mask)
    w = tl.load(w_ptr + offs, mask=mask)
    b = tl.load(b_ptr + offs, mask=mask)
    result = tl.maximum(x * w + b, 0.0)  # fused: mul + add + relu
    tl.store(out_ptr + offs, result, mask=mask)

n = 10_000_000
x = torch.randn(n, device='cuda')
w = torch.randn(n, device='cuda')
b = torch.randn(n, device='cuda')

# Fused (Triton)
out_fused = torch.empty_like(x)
grid = lambda meta: (triton.cdiv(n, meta['BLOCK']),)
fused_mul_add_relu_kernel[grid](x, w, b, out_fused, n, BLOCK=1024)

# Unfused (PyTorch)
out_unfused = torch.relu(x * w + b)

assert torch.allclose(out_fused, out_unfused, atol=1e-5)

# Benchmark
torch.cuda.synchronize()
start = time.time()
for _ in range(1000):
    fused_mul_add_relu_kernel[grid](x, w, b, out_fused, n, BLOCK=1024)
torch.cuda.synchronize()
fused_time = (time.time() - start) / 1000

start = time.time()
for _ in range(1000):
    out_unfused = torch.relu(x * w + b)
torch.cuda.synchronize()
unfused_time = (time.time() - start) / 1000

print(f"Fused (Triton):    {fused_time*1000:.3f} ms")
print(f"Unfused (PyTorch): {unfused_time*1000:.3f} ms")
print(f"Speedup:           {unfused_time/fused_time:.2f}x")
```

3. Измерьте, как компилятор JAX XLA автоматически объединяет операции. Сравните цепочку операций с jit и без него.
```python
import jax
import jax.numpy as jnp
import time

def chain_ops(x):
    x = x * 2.0
    x = x + 1.0
    x = jnp.maximum(x, 0.0)  # ReLU
    x = x / jnp.sum(x)
    return x

chain_jit = jax.jit(chain_ops)
x = jax.random.normal(jax.random.PRNGKey(0), (10000, 1000))

# Warm up
_ = chain_jit(x)
jax.block_until_ready(_)

# Eager (each op is a separate kernel launch)
start = time.time()
for _ in range(100):
    y = chain_ops(x)
jax.block_until_ready(y)
eager_time = (time.time() - start) / 100

# JIT (XLA fuses operations)
start = time.time()
for _ in range(100):
    y = chain_jit(x)
jax.block_until_ready(y)
jit_time = (time.time() - start) / 100

print(f"Eager: {eager_time*1000:.2f} ms")
print(f"JIT:   {jit_time*1000:.2f} ms")
print(f"Speedup: {eager_time/jit_time:.1f}x (XLA fuses the 4 operations into 1 kernel)")
```
