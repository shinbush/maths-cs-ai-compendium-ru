# Почему C++ и как работают платформы машинного обучения

*Каждый вызов `jnp.matmul`, каждый `torch.nn.Linear`, каждый вызов `np.dot` в этой книге выполнял приведенный ниже код C++ и CUDA. Этот файл приоткрывает завесу: почему платформы машинного обучения построены таким образом, краткие основы C++ для инженеров Python, когда писать собственные ядра C++ и как связать их с Python — мост между написанным вами кодом и оборудованием, на котором он работает.*

- Вы потратили 15 глав на написание Python. Вы импортировали JAX под названием `jax.grad`, выполнили циклы обучения и построили модели. Все это было похоже на Python. Но вот правда: **практически ни одно из реальных вычислений не происходило в Python.**

— Когда вы пишете `output = model(input)` в PyTorch или `output = jnp.matmul(W, x)` в JAX, Python почти ничего не делает. Он создает описание вычислений (график операций), а затем передает его серверной части C++/CUDA, которая выполняет реальную работу. Питон — руль; C++ — это движок.

## Почему интерфейс Python и серверная часть C++

- Эта двухязычная архитектура существует потому, что Python и C++ хороши в противоположных вещах:

| | Питон | С++ |
|--|--------|-----|
| Скорость разработки | Быстро (динамическая типизация, REPL, без компиляции) | Медленно (статическая типизация, заголовки, время компиляции) |
| Скорость выполнения | ~ в 100 раз медленнее, чем C (интерпретируется GIL) | Почти аппаратная скорость (скомпилировано, без накладных расходов) |
| Управление памятью | Автоматически (GC), без контроля макета | Ручной, точный контроль над каждым байтом |
| Доступ к оборудованию | Нет (нет SIMD, нет графического процессора, нет специальной памяти) | Полная (внутренняя реализация, CUDA, встроенная сборка) |
| Экосистема | Rich for ML (ноутбуки, визуализация, данные) | Богатый для систем (ОС, драйверы, движки) |

- Идея: **используйте каждый язык там, где он хорош**. Python обрабатывает те части, где важна производительность человека (планирование эксперимента, настройка гиперпараметров, исследование данных). C++ обрабатывает части, где важна производительность машины (умножение матриц, свертка, ядра внимания).

- Одно умножение матрицы `jnp.matmul(A, B)`, где $A$ равно $4096 \times 4096$, выполняет около 137 миллиардов операций с плавающей запятой. В чистом Python (вложенные циклы) это занимает около 30 минут. В оптимизированном C++ с SIMD AVX-512 и многопоточностью это занимает ~10 миллисекунд. Это разница в **180 000x**. Никакая изобретательность Python не закроет этот пробел.

## Как структурированы платформы машинного обучения

- Все основные платформы машинного обучения имеют одну и ту же архитектуру:

```
User code (Python)
    ↓
Python API layer (torch.nn, jax.numpy, numpy)
    ↓
Dispatch / JIT compiler (torch.compile, XLA, NumPy dispatch)
    ↓
C++ kernel library (ATen/PyTorch, XLA, BLAS/LAPACK)
    ↓
Hardware-specific backends (CUDA, cuDNN, MKL, oneDNN, Metal)
    ↓
Hardware (CPU SIMD units, GPU cores, TPU MXUs)
```

### NumPy

- Ядро NumPy написано на C. Когда вы вызываете `np.dot(A, B)`, Python вызывает функцию C, которая вызывает BLAS (базовые подпрограммы линейной алгебры), обычно Intel MKL или OpenBLAS. BLAS — это оптимизированный вручную код на C и Fortran, в котором используются инструкции SIMD, шаблоны доступа к памяти с поддержкой кэша и многопоточность. Десятилетия оптимизации ушли на то, чтобы сделать умножение матриц быстрым.

- NumPy предназначен только для процессора. Он не использует графические процессоры. Но на ЦП он работает очень быстро, поскольку делегирует лучшую доступную реализацию BLAS.

### ПиТорч

- Вычислительный механизм PyTorch — **ATen** (тензорная библиотека), написанный на C++. ATen реализует около 2000 тензорных операций (add, matmul, conv2d, softmax, ...), каждая из которых использует процессор и CUDA.

- Когда вы звоните `torch.matmul(A, B)`:
    1. Python отправляет данные функции ATen C++.
    2. ATen проверяет устройство (CPU или CUDA) и dtype.
    3. На ЦП: вызывает MKL/OpenBLAS. На графическом процессоре: вызывает cuBLAS (BLAS от NVIDIA, оптимизированный для графического процессора).
    4. Результат помещается в тензорный объект Python и возвращается.

- **torch.compile** (PyTorch 2.0+) идет дальше: он отслеживает ваш код Python, строит граф вычислений и компилирует его с использованием **Triton** (для графического процессора) или **C++/OpenMP** (для процессора). Скомпилированный код объединяет операции, устраняет накладные расходы Python и может работать в 2–5 раз быстрее, чем в режиме ожидания.

### ДЖАКС- JAX компилирует функции Python в **XLA** (ускоренная линейная алгебра), компилятор Google для рабочих нагрузок машинного обучения. Когда вы `jax.jit` выполняете функцию:
    1. JAX отслеживает функцию, фиксируя операции в виде графа вычислений XLA (HLO — High Level Operations).
    2. XLA оптимизирует граф: объединяет операции, устраняет избыточные вычисления, оптимизирует структуру памяти.
    3. XLA компилируется в целевой сервер: CPU (через LLVM), GPU (через CUDA/PTX) или TPU (с помощью инструкций, специфичных для TPU).
    4. Скомпилированный код выполняется непосредственно на оборудовании без участия Python.

— Вот почему `jax.jit` так важен: без него каждая операция представляет собой отдельный цикл Python→C++. При нем вся функция представляет собой единое скомпилированное ядро.

## Краткие основы C++ для инженеров Python

- Вам не нужно становиться экспертом по C++. Вам необходимо понимать достаточно, чтобы читать код ядра, писать простые расширения и понимать дискуссии о производительности. Вот самое необходимое.

### Типы и переменные

```cpp
// C++ requires explicit types (unlike Python)
int count = 0;           // 32-bit integer
float loss = 0.5f;       // 32-bit float
double lr = 3e-4;        // 64-bit float
bool training = true;    // boolean

// Arrays (fixed size, stack-allocated)
float weights[1024];     // 1024 floats, contiguous in memory

// Pointers: a variable that holds a memory address
float* ptr = weights;    // ptr points to the first element of weights
float val = ptr[42];     // access element 42 via pointer arithmetic
// ptr[42] is equivalent to *(ptr + 42)
```

- **Указатели** — самое большое концептуальное отличие от Python. В Python все является ссылкой, и вы никогда не думаете об адресах памяти. В C++ указатели предоставляют прямой доступ к памяти — мощное, но опасное (висячие указатели, переполнение буфера).

### Функции

```cpp
// Function declaration: return_type name(param_type param_name)
float relu(float x) {
    return x > 0.0f ? x : 0.0f;
}

// Passing by reference (avoids copying large objects)
void scale_vector(std::vector<float>& vec, float factor) {
    for (size_t i = 0; i < vec.size(); i++) {
        vec[i] *= factor;
    }
}

// const reference: read-only, no copy
float sum(const std::vector<float>& vec) {
    float total = 0.0f;
    for (float x : vec) {  // range-based for loop (like Python's for x in vec)
        total += x;
    }
    return total;
}
```

### Память: стек против кучи

```cpp
// Stack allocation: fast, automatic lifetime (freed when function returns)
float buffer[256];   // 256 floats on the stack

// Heap allocation: manual, survives beyond the function
float* data = new float[n];   // allocate n floats on the heap
// ... use data ...
delete[] data;                 // YOU must free it (no garbage collector)

// Modern C++: smart pointers (automatic cleanup, like Python references)
#include <memory>
auto data = std::make_unique<float[]>(n);  // freed automatically when out of scope
```

- **Основное правило**: стек быстрый, но ограниченный (обычно 1–8 МБ). Большие массивы (тензоры, карты объектов) должны помещаться в кучу. В Python все находится в куче, а очистку выполняет сборщик мусора. В C++ вы управляете этим самостоятельно (или используете интеллектуальные указатели).

### Шаблоны (обобщенные)

```cpp
// A function that works with any numeric type
```

## Когда писать собственные ядра C++

— Большинству инженеров ML никогда не нужно писать C++. Встроенные операции платформы охватывают 99% случаев использования. Вам следует рассматривать пользовательский C++ только в том случае, если:

1. **Ваша операция не существует в рамках**: новая функция активации, индивидуальный шаблон внимания, специализированная функция потерь, которую невозможно выразить как композицию существующих операций.

2. **Объединение операций для повышения производительности**: ваша модель поддерживает `relu(layernorm(matmul(x, W) + b))`. Каждая операция запускает отдельное ядро, читает и записывает память и синхронизируется. Объединенное ядро ​​делает все это за один проход, избегая обращения к памяти. Это может быть в 2–5 раз быстрее.

3. **Уменьшение использования памяти**: собственное ядро ​​может вычислять градиенты без сохранения всех промежуточных активаций (контрольная точка градиента на уровне ядра).

4. **Нацеленность на новое оборудование**: новый ускоритель (например, Cerebras, Groq) может не иметь поддержки платформы. Вы пишете ядра напрямую.

- Для случаев 1-2 **Triton** (глава 16, файл 05) часто бывает достаточным и намного проще, чем напрямую писать CUDA C. Переходите на CUDA C только тогда, когда Triton не может выразить то, что вам нужно.

## Как привязать C++ к Python

— Написание C++ — это половина дела. Вам также необходимо вызвать его из Python.

### pybind11 (общего назначения)

- pybind11 создает привязки Python для функций C++ с минимальным шаблоном:

```cpp
// my_ops.cpp
#include <pybind11/pybind11.h>
#include <pybind11/numpy.h>
namespace py = pybind11;

// A simple custom operation
py::array_t<float> custom_relu(py::array_t<float> input) {
    auto buf = input.request();
    float* ptr = static_cast<float*>(buf.ptr);
    size_t n = buf.size;

    auto result = py::array_t<float>(n);
    float* out = static_cast<float*>(result.request().ptr);

    for (size_t i = 0; i < n; i++) {
        out[i] = ptr[i] > 0 ? ptr[i] : 0;
    }
    return result;
}

PYBIND11_MODULE(my_ops, m) {
    m.def("custom_relu", &custom_relu, "Custom ReLU operation");
}
```

```bash
# Compile
pip install pybind11
c++ -O3 -shared -std=c++17 -fPIC $(python3 -m pybind11 --includes) my_ops.cpp -o my_ops$(python3-config --extension-suffix)
```

```python
# Use from Python
import my_ops
import numpy as np

x = np.array([-1.0, 2.0, -3.0, 4.0], dtype=np.float32)
y = my_ops.custom_relu(x)
print(y)  # [0. 2. 0. 4.]
```

### Расширения PyTorch C++

- PyTorch предоставляет упрощенный способ добавления пользовательских операций:

```cpp
// custom_op.cpp
#include <torch/extension.h>

torch::Tensor custom_gelu(torch::Tensor x) {
    return x * 0.5 * (1.0 + torch::erf(x / std::sqrt(2.0)));
}

PYBIND11_MODULE(TORCH_EXTENSION_NAME, m) {
    m.def("custom_gelu", &custom_gelu, "Custom GELU activation");
}
```

```python
# Load and compile on-the-fly
from torch.utils.cpp_extension import load

custom_ops = load(
    name="custom_ops",
    sources=["custom_op.cpp"],
    extra_cflags=["-O3"],
)

x = torch.randn(1000)
y = custom_ops.custom_gelu(x)
```

- `torch.utils.cpp_extension.load` компилирует код C++, создает общую библиотеку и загружает ее как модуль Python — и все это за один вызов. Это самый простой способ поэкспериментировать с пользовательскими операциями C++ в PyTorch.

### Пользовательские вызовы JAX

- JAX использует пользовательские вызовы XLA. Этот процесс более сложен (вы регистрируете функцию C в XLA), но концепция та же: напишите C/C++, привяжите ее, вызовите из Python.

- Для большинства пользователей JAX **Pallas** (описанный в файле 05) является лучшим выбором: он позволяет писать ядра графического процессора с синтаксисом, подобным Python, который компилируется XLA, не выходя из экосистемы JAX.

1. Напишите свою первую программу на C++. Выделите массив, заполните его, вычислите сумму и измерьте время. Здесь представлены компиляция, массивы, указатели и синхронизация.
```cpp
// task1_basics.cpp
// Compile: g++ -O3 -o task1 task1_basics.cpp
// Run: ./task1

#include <iostream>
#include <chrono>
#include <vector>

int main() {
    const int N = 10'000'000;  // C++ allows ' as digit separator
    std::vector<float> data(N);

    // Fill the array
    for (int i = 0; i < N; i++) {
        data[i] = static_cast<float>(i) * 0.001f;
    }

    // Compute sum
    auto start = std::chrono::high_resolution_clock::now();
    float sum = 0.0f;
    for (int i = 0; i < N; i++) {
        sum += data[i];
    }
    auto end = std::chrono::high_resolution_clock::now();
    double elapsed = std::chrono::duration<double, std::milli>(end - start).count();

    std::cout << "Sum: " << sum << std::endl;
    std::cout << "Time: " << elapsed << " ms" << std::endl;
    std::cout << "Elements: " << N << std::endl;
    std::cout << "Throughput: " << (N * sizeof(float)) / elapsed / 1e6 << " GB/s" << std::endl;

    return 0;
}
```

3. Напишите программу на C++, которая покажет, почему расположение памяти имеет значение. Сравните шаблоны доступа по строкам и по столбцам и измерьте разницу в производительности.
```cpp
// task3_layout.cpp
// Compile: g++ -O3 -o task3 task3_layout.cpp

#include <iostream>
#include <chrono>
#include <vector>

int main() {
    const int N = 4096;
    std::vector<float> matrix(N * N, 1.0f);

    // Row-major access: sequential memory addresses (cache-friendly)
    auto start = std::chrono::high_resolution_clock::now();
    float sum_row = 0.0f;
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++) {
            sum_row += matrix[i * N + j];  // stride-1 access
        }
    }
    auto end = std::chrono::high_resolution_clock::now();
    double row_ms = std::chrono::duration<double, std::milli>(end - start).count();

    // Column-major access: stride-N access (cache-unfriendly)
    start = std::chrono::high_resolution_clock::now();
    float sum_col = 0.0f;
    for (int j = 0; j < N; j++) {
        for (int i = 0; i < N; i++) {
            sum_col += matrix[i * N + j];  // stride-N access (cache misses!)
        }
    }
    end = std::chrono::high_resolution_clock::now();
    double col_ms = std::chrono::duration<double, std::milli>(end - start).count();

    std::cout << "Row-major (cache-friendly): " << row_ms << " ms" << std::endl;
    std::cout << "Col-major (cache-hostile):  " << col_ms << " ms" << std::endl;
    std::cout << "Slowdown: " << col_ms / row_ms << "x" << std::endl;
    std::cout << "(Both sums: " << sum_row << ", " << sum_col << ")" << std::endl;

    return 0;
}
```
