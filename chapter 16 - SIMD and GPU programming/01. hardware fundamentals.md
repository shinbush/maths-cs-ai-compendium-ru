# Основы аппаратного обеспечения

*Прежде чем писать код SIMD или GPU, вам необходимо понять аппаратное обеспечение, которое вы программируете. В этом файле рассказывается, почему параллелизм заменил тактовую частоту, как современные процессоры выполняют инструкции, что такое SIMD, основная модель для рассуждений о производительности и ландшафт архитектур чипов*.

- На протяжении десятилетий программное обеспечение становилось быстрее бесплатно: купите новый процессор с более высокой тактовой частотой, и ваша программа будет работать быстрее, не меняя ни строчки кода. Эта эпоха закончилась примерно в 2005 году. Понимание того, почему она закончилась и что пришло ей на смену, важно для всех, кто хочет писать быстрый код.

## Конец свободной производительности

- **Закон Мура** (1965) установил, что количество транзисторов на кристалле удваивается примерно каждые два года. Это продолжалось 60 лет. Больше транзисторов означало меньшие по размеру транзисторы, а это означало более высокие тактовые частоты, а это означало более быстрые программы.

- Но где-то в 2005 году тактовая частота достигла отметки ~4 ГГц. Проблема в **силе**. Мощность, потребляемая чипом, составляет примерно:

$$P \propto C \cdot V^2 \cdot f$$

- где $C$ — емкость (пропорциональная количеству транзисторов), $V$ — напряжение, а $f$ — тактовая частота. Чтобы увеличить частоту, необходимо увеличить напряжение (чтобы быстрее переключались транзисторы). Но мощность масштабируется с помощью $V^2 \cdot f$, поэтому небольшое увеличение частоты приводит к значительному увеличению мощности (и нагрева). На частоте 4 ГГц чипы уже выдавали мощность более 100 Вт. Переход на частоту 8 ГГц потребует непрактичного охлаждения.

- Решение: вместо того, чтобы делать одно ядро ​​быстрее, поместите **несколько ядер** на один и тот же чип. 4-ядерный чип с частотой 3 ГГц потребляет такую ​​же мощность, что и одноядерный процессор с частотой 4,5 ГГц, но может выполнять в 4 раза большую параллельную работу. Вот почему каждый современный процессор имеет несколько ядер и почему параллелизм (SIMD, многопоточность, вычисления на графическом процессоре) — единственный путь к повышению производительности.

- **Следствие для машинного обучения**: шаг обучения, который занимает 10 минут на одном ядре, нельзя ускорить, купив более быстрый процессор. Его можно сделать быстрее, только используя больше ядер (параллелизм данных, глава 6), более широкие блоки SIMD (эта глава) или графические процессоры (тысячи ядер).

## Как современные процессоры выполняют инструкции

— Современное ядро ЦП намного сложнее, чем простая модель «выборка-декодирование-выполнение» из главы 13. Оно использует несколько приемов для выполнения большего количества инструкций за цикл:

- **Суперскалярное выполнение**: ЦП имеет несколько исполнительных блоков (ALU, FPU, блоки загрузки/сохранения) и может одновременно выполнять несколько независимых инструкций. Современное ядро ​​могло бы выполнять 4-6 инструкций за такт, если бы они не зависели друг от друга.

- **Выполнение вне порядка (OoO)**: ЦП не выполняет инструкции в программном порядке. Он просматривает поток команд вперед, находит команды, входные данные которых готовы, и немедленно выполняет их, независимо от их положения. Это скрывает задержку: пока одна инструкция ожидает данные из памяти (более 100 циклов), ЦП выполняет другие уже готовые инструкции.

- **Прогнозирование ветвей**: условные ветки (операторы `if`, условия цикла) создают неопределенность: ЦП не знает, какой путь выбрать, пока условие не будет оценено. Вместо того, чтобы останавливаться, ЦП **предсказывает** результат и спекулятивно выполняет предсказанный путь. Если прогноз верен (>95% времени с современными предикторами), время не теряется. Если это неправильно, спекулятивная работа отменяется и выполняется правильный путь (штраф ~15 циклов).

- **Спекулятивное исполнение**: расширение предсказания ветвей. ЦП выполняет инструкции, которые *могут* не понадобиться, ставя на то, что они понадобятся. Это заполняет конвейер и сохраняет занятость исполнительных модулей.

- Все это происходит автоматически — ЦП делает это без вмешательства программиста. Но они помогают только при **параллелизме на уровне инструкций** (ILP): независимых инструкциях в одном потоке. Для **параллелизма на уровне данных** (одна и та же операция со многими элементами данных) нам нужен SIMD.

## SIMD: одна инструкция, несколько данных

- **SIMD** — это идея применения одной инструкции к нескольким элементам данных одновременно. Вместо сложения двух чисел добавьте два вектора по 4 (или 8, или 16) чисел за одну инструкцию.

- Без SIMD (скаляр):

```cpp
// Add two arrays element by element: 4 add instructions
for (int i = 0; i < 4; i++) {
    c[i] = a[i] + b[i];  // one add per iteration
}
```- С SIMD (векторизованным):

```cpp
// Add two arrays: 1 SIMD instruction does all 4 adds
#include <immintrin.h>  // x86 SIMD intrinsics

__m128 va = _mm_load_ps(a);    // load 4 floats into a 128-bit register
__m128 vb = _mm_load_ps(b);    // load 4 floats into another register
__m128 vc = _mm_add_ps(va, vb); // add all 4 pairs simultaneously
_mm_store_ps(c, vc);            // store 4 results
```

- Версия SIMD делает ту же работу в 1/4 инструкций. Это теоретическое четырехкратное ускорение, достигаемое за счет обработки 4 чисел с плавающей точкой за инструкцию вместо 1.

### Векторные регистры

- Инструкции SIMD работают с **векторными регистрами**: широкими регистрами, содержащими несколько элементов данных.

| Ширина регистра | Плавающие числа (32-разрядная версия) | Двойные (64-разрядные версии) | Имя |
|----------------|-----------------|-------------------|------|
| 128-битный | 4 | 2 | SSE (x86), НЕОН (ARM) |
| 256-битный | 8 | 4 | AVX/AVX2 (x86) |
| 512-битный | 16 | 8 | AVX-512 (x86) |
| Переменная (128-2048) | варьируется | варьируется | СВЕ/СВЕ2 (ARM) |

- Более широкие регистры = больше параллелизма. 512-битная инструкция AVX-512 обрабатывает 16 чисел с плавающей запятой одновременно, что теоретически обеспечивает 16-кратное ускорение по сравнению со скалярным кодом. На практике ускорение ниже из-за ограничений пропускной способности памяти (вы можете выполнять вычисления быстрее, чем передавать данные в ЦП).

- Для ML: матричное умножение значений float32 дает огромную выгоду от SIMD. Внутренний цикл (скалярное произведение двух векторов) напрямую отображается на инструкции умножения-накопления SIMD. Вот почему библиотеки BLAS (которые вызывают NumPy и PyTorch) так сильно оптимизированы с помощью SIMD.

## Модель крыши

- Как узнать, быстрый ли ваш код? **Модель линии крыши** представляет собой основу, характеризующую производительность с точки зрения двух аппаратных ограничений:

1. **Пиковые вычисления** (флопс): максимальное количество операций с плавающей запятой в секунду. Для процессора с частотой 4 ГГц с 256-битным AVX (8 чисел с плавающей запятой на инструкцию) и 2 модулями FMA: $4 \times 10^9 \times 8 \times 2 = 64$ GFLOPS.

2. **Пиковая пропускная способность памяти** (байт/секунда): насколько быстро данные могут быть перемещены из памяти в ЦП. Современный процессор может иметь пропускную способность памяти 50 ГБ/с.

- **Арифметическая интенсивность** вашего кода — это соотношение вычислений и доступа к памяти:

$$\text{Arithmetic Intensity} = \frac{\text{FLOPS}}{\text{Bytes transferred}}$$

- Если арифметическая интенсивность низкая (несколько операций на загруженный байт), ваш код **привязан к памяти**: большую часть времени он проводит в ожидании данных. Ускорение вычислений (шире SIMD, более высокая тактовая частота) не поможет.

- Если арифметическая интенсивность высока (много операций на байт), ваш код **зависим от вычислений**: большую часть времени он тратит на вычисления. Быстрая память не поможет.

- Линия крыши:

$$\text{Achievable FLOPS} = \min\left(\text{Peak FLOPS}, \; \text{Bandwidth} \times \text{Arithmetic Intensity}\right)$$

- **Умножение матриц** имеет высокую арифметическую интенсивность: операции $O(n^3)$ с данными $O(n^2)$, поэтому интенсивность $\approx O(n)$. Для больших матриц это связано с вычислениями. Вот почему графические процессоры (высокопроизводительные) доминируют в рабочих нагрузках машинного обучения с большим количеством матриц.

- **Поэлементные операции** (ReLU, сложение, умножение) имеют низкую арифметическую интенсивность: 1 операция на каждый загруженный элемент. Они привязаны к памяти. Увеличение скорости графического процессора не помогает; вам нужна более быстрая память (или объедините эти операции с трудоемкими операциями, чтобы избежать отдельных обращений к памяти).

- Модель крыши объясняет, почему **слияние ядер** так важно: объединение matmul с добавлением смещения и ReLU в одно ядро ​​позволяет избежать записи промежуточных результатов в память и их обратного чтения, превращая три операции, связанные с памятью, в одну операцию, связанную с вычислениями.

## Задержка и пропускная способность

- **Задержка** – это время выполнения одной операции. **Пропускная способность** – это количество операций, выполненных в единицу времени.

- Аналогия: автобус имеет большую задержку (ждёт на каждой остановке), но высокую пропускную способность (возит одновременно 50 человек). Такси имеет низкую задержку (едет прямо к месту назначения), но низкую пропускную способность (везет 1-4 человека).

- Графические процессоры представляют собой шины: высокая задержка на операцию (для выполнения каждой инструкции требуется много циклов), но огромная пропускная способность (одновременная обработка тысяч ядер). ЦП — это такси: низкая задержка (выполнение вне очереди, прогнозирование ветвей, глубокие кэши минимизируют задержки), но ограниченная пропускная способность (4–64 ядра).

— Вот почему графические процессоры лучше подходят для обучения машинному обучению (пропускная способность имеет значение: обрабатываются миллионы примеров), а центральные процессоры лучше подходят для задач ОС (задержка имеет значение: немедленно реагировать на нажатие клавиши).- **Конвейерная обработка** преобразует задержку в пропускную способность. If an instruction takes 5 cycles but the pipeline starts a new instruction every cycle, the throughput is 1 instruction per cycle (even though each takes 5 cycles to complete). Это тот же принцип, что и в конвейере ЦП из главы 13, но он применим на каждом уровне: все модули SIMD, контроллеры памяти и ядра графического процессора являются конвейерными.

## Чип Архитектура Ландшафт

- Аппаратное обеспечение, для которого вы пишете код, определяет, какие инструкции SIMD доступны:

### x86 (Intel, AMD)

- Доминирует в настольных компьютерах, ноутбуках и процессорах центров обработки данных. SIMD: SSE (128-бит), AVX/AVX2 (256-бит), AVX-512 (512-бит). Intel AMX предоставляет выделенные матричные умножители для рабочих нагрузок искусственного интеллекта.

- **Сильные стороны**: высочайшая одноядерная производительность, самый широкий SIMD, развитая экосистема программного обеспечения (MKL, oneDNN).
- **Слабые стороны**: высокое энергопотребление, сложный набор команд, высокая стоимость.

### РУКА

- Доминирует на мобильных устройствах (каждый смартфон), растет на серверах (AWS Graviton, Ampere Altra) и ноутбуках (Apple M-серии). SIMD: NEON (128-бит), SVE/SVE2 (масштабируемый, 128-2048 бит).

- **Сильные стороны**: отличная энергоэффективность (производительность на ватт), специальные ядра (Apple M4 конкурирует с Intel по одноядерной производительности при меньшей мощности).
- **Слабые стороны**: более узкий SIMD (NEON всего 128-битный, хотя SVE может быть шире), меньшая программная экосистема для HPC.

### Apple Silicon (M1/M2/M3/M4)

- На базе ARM с пользовательскими дополнениями. Включает **AMX** (Apple Matrix eXtensions) — недокументированные единицы умножения матрицы, которые платформа Accelerate использует для операций BLAS. Унифицированная архитектура памяти: ЦП и графический процессор используют одну и ту же физическую память, что устраняет узкое место при копировании ЦП↔ГП.

- **Для машинного обучения**: Neural Engine от Apple (16-ядерный выделенный ускоритель машинного обучения) и унифицированная память делают чипы серии M удивительно способными выполнять локальные логические выводы машинного обучения и мелкомасштабное обучение. Однако нет CUDA: вы должны использовать Metal (Apple GPU API) или MLX (Apple ML framework).

### RISC-V

- ISA с открытым исходным кодом. Никаких лицензионных сборов (в отличие от ARM). Развитие встроенных систем, Интернета вещей и исследований. SIMD: расширение «V» (векторное) обеспечивает масштабируемую векторную обработку, аналогичную ARM SVE.

- **Для машинного обучения**: пока не может конкурировать с рабочими нагрузками машинного обучения x86/ARM, но обратите внимание на это место. Несколько стартапов-ускорителей искусственного интеллекта используют ядра RISC-V.

### графические процессоры (NVIDIA, AMD, Intel)

- Подробно рассмотрено в файлах 04-05. Тысячи простых ядер, оптимизированных для пропускной способности. NVIDIA доминирует в машинном обучении с помощью CUDA; AMD конкурирует с ROCm; Intel выходит на рынок с графическими процессорами Arc и ускорителями Gaudi.

### ТПУ (Google)

- Пользовательский ASIC, разработанный специально для машинного обучения. Систолические массивы, оптимизированные для умножения матриц. В файле 05.

## Ограничения по температуре и мощности

- Производительность в конечном итоге ограничивается мощностью и охлаждением:

- **TDP** (Расчетная тепловая мощность): максимальная постоянная мощность, которую может потреблять чип. Процессор ноутбука может иметь TDP 15 Вт; серверный процессор мощностью 250 Вт; графический процессор для центра обработки данных мощностью 700 Вт (NVIDIA B200).

- **Темный кремний**: в любой момент значительная часть транзисторов должна быть отключена, чтобы оставаться в пределах теплового баланса. Чип теоретически может использовать все свои транзисторы одновременно, но он расплавится.

- **Энергоэффективность** (флопс/ватт) становится все более важным показателем, а не простое число флопсов. Вот почему:
    - ARM захватывает центры обработки данных (лучше FLOPS/ватт, чем x86).
    - TPU конкурируют с графическими процессорами, несмотря на более низкий пиковый FLOPS (гораздо лучший FLOPS/ватт для рабочих нагрузок ML).
    - Квантование (INT8, FP8) касается не только памяти: оно также снижает энергопотребление на операцию.

- Для масштабного машинного обучения: обучение передового LLM потребляет мегаватты энергии в течение нескольких месяцев. Стоимость электроэнергии может превышать стоимость оборудования. Энергоэффективность напрямую влияет на экономику исследований ИИ.

## Практическое: измерение производительности в C++

- Чтобы рассуждать о производительности, нужно ее измерить. Вот минимальная настройка бенчмаркинга C++:

```cpp
#include <iostream>
#include <chrono>
#include <vector>

// Scalar addition
void add_scalar(const float* a, const float* b, float* c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

int main() {
    const int N = 1 << 24;  // ~16 million elements
    std::vector<float> a(N, 1.0f), b(N, 2.0f), c(N);

    // Warm up (fill caches, trigger frequency scaling)
    add_scalar(a.data(), b.data(), c.data(), N);

    // Benchmark
    auto start = std::chrono::high_resolution_clock::now();

    for (int trial = 0; trial < 100; trial++) {
        add_scalar(a.data(), b.data(), c.data(), N);
    }

    auto end = std::chrono::high_resolution_clock::now();
    double elapsed = std::chrono::duration<double>(end - start).count();

    double total_bytes = 3.0 * N * sizeof(float) * 100;  // read a, read b, write c
    double bandwidth = total_bytes / elapsed / 1e9;        // GB/s

    std::cout << "Time: " << elapsed << " s\n";
    std::cout << "Bandwidth: " << bandwidth << " GB/s\n";

    return 0;
}
```

```bash
# Compile with optimisations
g++ -O3 -march=native -o bench bench.cpp
./bench
```- **Основные концепции C++ в этом коде**:
    - `#include <vector>`: динамический массив (`std::vector<float>`) — похож на `list` Python, но типизирован и непрерывен в памяти.
    - `a.data()`: возвращает необработанный указатель (`float*`) на базовый массив, необходимый для встроенных функций SIMD.
    - `std::chrono`: таймер высокого разрешения для сравнительного тестирования.
    - `-O3`: максимальный уровень оптимизации компилятора. Компилятор может автоматически векторизовать ваши циклы (автоматически использовать SIMD). `-march=native` включает все инструкции SIMD, которые поддерживает ваш процессор.

- **Зачем разогреваться**: первый запуск заполняет кэши и может вызвать масштабирование частоты процессора (турбоускорение). Последующие прогоны более репрезентативны.

- **Зачем измерять пропускную способность**: для операций с памятью (например, поэлементного добавления) значимым показателем является пропускная способность (ГБ/с), а не FLOPS. Если измеренная вами пропускная способность близка к аппаратному пределу (~ 50 ГБ/с для DDR5), вы ограничены в объеме памяти, и SIMD не сильно поможет (узким местом является память, а не вычисления).

import numpy as np
import time

for n in [1000, 10000, 100000, 1000000, 10000000]:
    a = np.random.randn(n).astype(np.float32)
    b = np.random.randn(n).astype(np.float32)

    # "Sequential" (Python loop)
    start = time.time()
    c = [a[i] * b[i] for i in range(min(n, 100000))]  # cap at 100K for sanity
    seq_time = time.time() - start
    if n > 100000:
        seq_time *= n / 100000  # extrapolate

    # "Parallel" (NumPy, uses SIMD + multithreading internally)
    start = time.time()
    c = a * b
    par_time = time.time() - start

    print(f"n={n:>10,}  sequential={seq_time:.4f}s  parallel={par_time:.6f}s  "
