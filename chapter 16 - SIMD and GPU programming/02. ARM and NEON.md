# АРМ и НЕОН

*Процессоры ARM используются в каждом смартфоне, большинстве планшетов, ноутбуках Apple и в растущей доле серверов центров обработки данных. В этом файле описывается архитектура ARM, программирование NEON SIMD с использованием встроенных функций C++, SVE/SVE2 для масштабируемой векторной обработки, особенности Apple Silicon и практические примеры векторизованного ядра*

- Если у вас есть iPhone, MacBook или вы используете экземпляры AWS Graviton, вы используете ARM. Энергоэффективность ARM делает его доминирующим в сфере мобильных и встраиваемых систем, а также все более конкурентоспособным в сфере серверов и машинного обучения. Понимание ARM SIMD позволяет вам писать код, который быстро работает на оборудовании, которое фактически использует большинство людей.

- Реальный пример ядра ARM SIMD в производстве см. в разделе **Cactus** — механизм искусственного интеллекта с малой задержкой для мобильных и носимых устройств: [github.com/cactus-compute/cactus](https://github.com/cactus-compute/cactus). Cactus реализует специальные ядра ARM NEON и NPU для внимания, квантования KV-кэша и фрагментированного предварительного заполнения, обеспечивая самый быстрый вывод на процессорах ARM с объемом оперативной памяти в 10 раз меньше, чем у других механизмов. Его трехуровневая архитектура (Engine → Graph → Kernels) является конкретным примером того, как концепции SIMD в этом файле используются для построения производственной инфраструктуры ML.

## Основы архитектуры ARM

- ARM представляет собой архитектуру **RISC** (компьютер с сокращенным набором команд) (глава 13). Ключевые характеристики:

    - **Архитектура загрузки-сохранения**: арифметические инструкции работают только с регистрами, а не напрямую с памятью. Чтобы сложить два числа из памяти, необходимо: (1) загрузить их в регистры, (2) сложить регистры, (3) сохранить результат обратно в память. Это проще, чем x86 (который может добавлять регистр и ячейку памяти в одной инструкции), но обеспечивает более чистую конвейерную обработку.

    - **Инструкции фиксированной ширины**: каждая инструкция ARMv8 (AArch64) имеет длину ровно 32 бита. Это делает декодирование быстрым и предсказуемым (в отличие от инструкций переменной длины x86, которые могут составлять 1–15 байт).

    - **32 регистра общего назначения** (x0–x30, каждый 64-битный), а также указатель стека (sp) и нулевой регистр (xzr). Сравните с 16 регистрами общего назначения в x86. Больше регистров = меньше обращений к памяти = более быстрый код.

    - **32 SIMD/регистра с плавающей запятой** (v0–v31, каждый по 128 бит) для NEON и операций с плавающей запятой.

```cpp
// ARM assembly (just to see the flavour -- you will use intrinsics, not assembly)
// Add two registers
add x0, x1, x2    // x0 = x1 + x2

// Load from memory
ldr x0, [x1]      // x0 = *x1 (load 64 bits from address in x1)

// NEON: add four floats
fadd v0.4s, v1.4s, v2.4s  // v0 = v1 + v2 (four 32-bit floats)
```

- Сборку писать не будешь. Вы будете использовать **intrinsics**: функции C/C++, которые сопоставляются 1:1 с конкретными инструкциями. Компилятор обрабатывает распределение регистров, планирование и другие детали низкого уровня.

## НЕОН: 128-битный SIMD

- **NEON** — это SIMD-расширение ARM. Каждый регистр NEON имеет ширину 128 бит и может содержать:

| Тип данных | Элементы в регистре | Обозначение |
|-----------|-----------------------|----------|
| поплавок32 | 4 | `float32x4_t` |
| поплавок16 | 8 | `float16x8_t` |
| int32 | 4 | `int32x4_t` |
| int16 | 8 | `int16x8_t` |
| int8 | 16 | `int8x16_t` |

- 128 бит уже, чем AVX x86 (256 бит) или AVX-512 (512 бит). Но ARM компенсирует это превосходной энергоэффективностью и широкой доступностью.

### Внутренние особенности NEON: основы

- Внутренние функции NEON следуют соглашению об именах: `v[operation][qualifier]_[type]`.

```cpp
#include <arm_neon.h>

// Load 4 floats from memory into a NEON register
float32x4_t a = vld1q_f32(ptr);        // vld1q = vector load 1, q = 128-bit (quad)

// Store 4 floats from a NEON register to memory
vst1q_f32(out_ptr, a);                   // vst1q = vector store 1, q = 128-bit

// Arithmetic
float32x4_t c = vaddq_f32(a, b);        // c = a + b (4 floats)
float32x4_t d = vmulq_f32(a, b);        // d = a * b (4 floats)
float32x4_t e = vfmaq_f32(c, a, b);     // e = c + a * b (fused multiply-add, 4 floats)

// Comparison (returns a mask: all 1s if true, all 0s if false)
uint32x4_t mask = vcgtq_f32(a, b);      // mask[i] = (a[i] > b[i]) ? 0xFFFFFFFF : 0

// Select elements based on mask (like numpy.where)
float32x4_t result = vbslq_f32(mask, a, b);  // result[i] = mask[i] ? a[i] : b[i]

// Reduce: sum all 4 elements to a scalar
float total = vaddvq_f32(a);             // total = a[0] + a[1] + a[2] + a[3]
```

- **`vfmaq_f32`** (слитое умножение-сложение) — самая важная инструкция SIMD для ML. Он вычисляет $c = c + a \times b$ за одну инструкцию с одним шагом округления (более точно, чем отдельное умножение и сложение). Скалярные произведения, матричные умножения и свертки строятся с помощью FMA.

### Практический пример: векторизованное скалярное произведение

— Скалярное произведение — это внутренний цикл умножения матриц. Давайте напишем это на скалярном C++, а затем векторизуем с помощью NEON.

```cpp
#include <arm_neon.h>

// Scalar dot product
float dot_scalar(const float* a, const float* b, int n) {
    float sum = 0.0f;
    for (int i = 0; i < n; i++) {
        sum += a[i] * b[i];
    }
    return sum;
}

// NEON-vectorised dot product
float dot_neon(const float* a, const float* b, int n) {
    float32x4_t sum_vec = vdupq_n_f32(0.0f);  // initialise 4 accumulators to 0

    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t va = vld1q_f32(a + i);     // load 4 elements from a
        float32x4_t vb = vld1q_f32(b + i);     // load 4 elements from b
        sum_vec = vfmaq_f32(sum_vec, va, vb);   // sum_vec += va * vb
    }

    // Reduce the 4 accumulators to a single scalar
    float sum = vaddvq_f32(sum_vec);

    // Handle remaining elements (if n is not a multiple of 4)
    for (; i < n; i++) {
        sum += a[i] * b[i];
    }

    return sum;
}
```

- **Основные концепции C++**:
    - `const float*`: указатель на данные с плавающей запятой, доступные только для чтения. `const` обещает, что мы не будем изменять данные с помощью этого указателя.
    - `a + i`: арифметика указателей. `a + i` указывает на $i$-й элемент массива (то же самое, что `&a[i]`).
    - «Цикл очистки» в конце обрабатывает случай, когда $n$ не кратен 4. Это универсальный шаблон в SIMD-коде: основная часть обрабатывается векторизованными фрагментами, а затем обрабатывается остаток в скалярном коде.- **Почему в `sum_vec` 4 аккумулятора**: вместо одного скалярного аккумулятора мы используем 4 независимых аккумулятора (по одному на SIMD-линию). Это позволяет избежать зависимости данных: FMA каждой итерации зависит от `sum_vec`, но благодаря 4 независимым дорожкам ЦП может конвейеризировать FMA. В конце мы сводим 4 частичные суммы к одной.

### Практический пример: векторизованный ReLU

```cpp
#include <arm_neon.h>

void relu_neon(const float* input, float* output, int n) {
    float32x4_t zero = vdupq_n_f32(0.0f);

    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t x = vld1q_f32(input + i);
        float32x4_t result = vmaxq_f32(x, zero);  // max(x, 0) = ReLU
        vst1q_f32(output + i, result);
    }

    // Scalar cleanup
    for (; i < n; i++) {
        output[i] = input[i] > 0 ? input[i] : 0;
    }
}
```

- `vmaxq_f32` вычисляет поэлементный максимум двух векторов. Поскольку в одном векторе все нули, это и есть ReLU. Никаких ветвей, никаких сравнений — только одна инструкция.

## I8MM: умножение целочисленной матрицы

- **I8MM** (Int8 Matrix Multiply) — это расширение ARMv8.6, которое добавляет специальные инструкции для умножения матриц INT8 с накоплением INT32 — именно то, что нужно для квантованного вывода ML.

- Ключевая инструкция — **`SMMLA`** (умножение-накопление знаковой матрицы): она принимает два блока 8×2 значений INT8 и накапливает результат в блок 2×2 INT32:

```cpp
#include <arm_neon.h>

// I8MM: multiply two 8-element INT8 vectors, accumulate into 4 INT32 results
// This computes a 2x2 tile of the output matrix from 2x8 x 8x2 input tiles
void matmul_i8mm_tile(const int8_t* A, const int8_t* B, int32_t* C) {
    // Load 8 bytes from A (2 rows of 4 elements, packed)
    int8x16_t va = vld1q_s8(A);   // 16 bytes = 2 rows × 8 elements
    int8x16_t vb = vld1q_s8(B);   // 16 bytes = 2 rows × 8 elements

    // Load existing accumulator (2x2 = 4 int32 values)
    int32x4_t acc = vld1q_s32(C);

    // I8MM instruction: acc += A_tile × B_tile^T
    // Computes 2×2 output from 2×8 × 8×2 inputs
    acc = vmmlaq_s32(acc, va, vb);  // THE I8MM instruction

    vst1q_s32(C, acc);
}
```

- **Почему I8MM имеет значение**: без I8MM INT8 matmul на NEON требует расширяющего множителя (`vmull`), за которым следует попарное сложение — несколько инструкций на каждый выходной элемент. При использовании I8MM аппаратное обеспечение выполняет скалярное произведение из 8 элементов (2×8×8×2 = 2×2) за одну инструкцию. Для рабочих нагрузок вывода INT8 это в 4–8 раз быстрее, чем обычный NEON.

- **Доступность**: Apple M1+ (все Apple Silicon), ARM Cortex-A510/A710/X2+ (ARMv9), AWS Graviton3+. Проверьте с помощью `#ifdef __ARM_FEATURE_MATMUL_INT8`.

- Для вывода ML: квантовые модели INT8 (глава 18), работающие на серверах ARM (Graviton) или Apple Silicon, получают огромную выгоду от I8MM. Такие платформы, как ONNX Runtime и llama.cpp, обнаруживают I8MM во время выполнения и автоматически используют оптимизированные ядра.

## SME и SME2: расширение масштабируемой матрицы

- **SME** (расширение масштабируемой матрицы) — это ответ ARM на тензорные ядра Intel AMX и NVIDIA: специальное оборудование для матричных операций. SME2 (ARMv9.2) расширяет его.

- SME вводит **регистры плиток ZA**: двумерные матрицы, хранящиеся на аппаратном уровне, размером до байтов SVL × SVL (где SVL — длина потокового вектора, обычно 128–512 бит на измерение). В отличие от NEON (1D-векторов) или даже SVE (1D-масштабируемых векторов), SME изначально работает с **2D-листами**.

- Модель программирования имеет два режима:
    - **Нормальный режим**: стандартное исполнение ARM (NEON, SVE работают как обычно).
    - **Режим потоковой передачи SVE**: вход через `smstart`, включает инструкции SME. Инструкции SVE также работают в этом режиме, но могут использовать регистры различной ширины.

```cpp
#include <arm_sme.h>

// SME2: outer product accumulation for matrix multiply
// Accumulates A_col × B_row into the ZA tile register
void sme2_matmul_outer(const float* A_col, const float* B_row, int K) {
    // Enter streaming mode
    // smstart;  // (done via compiler intrinsic or inline asm)

    // Zero the ZA tile accumulator
    svzero_za();

    for (int k = 0; k < K; k++) {
        // Load a column of A and a row of B into SVE registers
        svfloat32_t a = svld1_f32(svptrue_b32(), &A_col[k * SVL]);
        svfloat32_t b = svld1_f32(svptrue_b32(), &B_row[k * SVL]);

        // Outer product: ZA += a × b^T
        // This accumulates an SVL×SVL tile in one instruction
        svmopa_za32_f32_m(0, svptrue_b32(), svptrue_b32(), a, b);
    }

    // Store the ZA tile to memory
    // svst1_za(...);

    // Exit streaming mode
    // smstop;
}
```

- **Основные понятия**:
    - **`svmopa`** (внешнее накопление продуктов): основная инструкция SME. Он вычисляет полное внешнее произведение двух векторов и накапливает его в плитке ZA. Для SVL=512 бит (16 чисел с плавающей запятой) это внешнее произведение 16×16 — 256 операций FMA в одной инструкции.
    - **Плитка ZA**: сохраняется во всех инструкциях в режиме потоковой передачи. Вы накапливаете несколько внешних продуктов (по одному на K итерацию) в одном тайле, создавая полную матричную плитку умножения.
    - **Режим потоковой передачи**: инструкции SME работают только в потоковом режиме. Накладные расходы на вход/выход из режима потоковой передачи означают, что SME лучше всего подходит для устойчивых вычислений матрицы, а не для коротких пакетов.

- **Дополнения SME2**: многовекторные операции (обработка 2 или 4 векторов SVE одновременно), дополнительные операции с фрагментами и улучшенная интеграция с обычным режимом.

- **Наличие**: ARM Neoverse V2 (AWS Graviton4), некоторые новые мобильные чипы. Пока нет в Apple Silicon (по состоянию на 2026 год). SME все еще находится на ранней стадии — большинство сред машинного обучения еще не имеют ядра, оптимизированного для SME.

- **Прогрессия**: NEON (128-битные векторы, поэлементно) → I8MM (фрагменты матрицы INT8) → SVE (масштабируемые векторы) → SME (масштабируемые фрагменты 2D-матрицы). Каждое поколение приближается к аппаратным матричным операциям.

## SVE и SVE2: масштабируемые векторные расширения

- NEON имеет фиксированную ширину 128 бит. **SVE** (масштабируемое векторное расширение) представляет собой **программирование без учета длины вектора (VLA)**: вы пишете код один раз, и он запускается на оборудовании с любой шириной вектора (от 128 до 2048 бит). Аппаратное обеспечение определяет ширину во время выполнения.

```cpp
#include <arm_sve.h>

void add_sve(const float* a, const float* b, float* c, int n) {
    int i = 0;
    svbool_t pred = svwhilelt_b32(i, n);  // predicate: which lanes are active

    while (svptest_any(svptrue_b32(), pred)) {
        svfloat32_t va = svld1(pred, a + i);
        svfloat32_t vb = svld1(pred, b + i);
        svst1(pred, c + i, svadd_x(pred, va, vb));

        i += svcntw();  // advance by the hardware vector width (in 32-bit elements)
        pred = svwhilelt_b32(i, n);
    }
}
```— **Регистры предикатов** (`svbool_t`) заменяют скалярный цикл очистки. Каждая полоса имеет предикатный бит: активные полосы участвуют, неактивные маскируются. Инструкция `svwhilelt_b32(i, n)` создает предикат, в котором полосы, соответствующие `i, i+1, ..., n-1`, активны. Это автоматически обрабатывает хвост.

- **`svcntw()`** возвращает количество 32-битных элементов на векторный регистр во время выполнения. На процессоре с 256-битным SVE возвращается 8. На 512-битном SVE возвращается 16. Ваш код адаптируется автоматически.

- SVE доступен на ARM Neoverse V1/V2 (AWS Graviton3/4, некоторые серверные чипы). Он еще не доступен на Apple Silicon.

## Особенности Apple Silicon

- Чипы Apple серии M (M1, M2, M3, M4) основаны на ARM и имеют специальную микроархитектуру:

- **Ядра производительности и эффективности**: ядра P (Firestorm/Avalanche и т. д.) для тяжелых вычислений, ядра E (Icestorm/Blizzard и т. д.) для фоновых задач. Планировщик назначает потоки соответствующему типу ядра.

- **AMX** (Apple Matrix eXtensions): выделенные матричные умножители, отдельные от NEON. AMX недокументирован (Apple не публикует ISA), но платформа Accelerate использует его внутри для операций BLAS. Когда вы вызываете `np.dot` на Mac, он проходит через Accelerate, который использует AMX. Вы не можете программировать AMX напрямую (без реверс-инжиниринга).

- **Единая память**: ЦП и графический процессор используют одну и ту же физическую оперативную память. В других системах данные необходимо копировать из памяти ЦП в память графического процессора (через PCIe, ~32 ГБ/с). В Apple Silicon копии нет — графический процессор читает ту же память, что и процессор. Это устраняет основное узкое место для рабочих нагрузок машинного обучения.

- **Neural Engine**: 16-ядерный специальный ускоритель машинного обучения. Выполняет ~30 TOPS (триллионов операций в секунду) для вывода INT8. Используется Core ML для вывода на устройстве.

- **Для машинного обучения на Apple Silicon**: используйте MLX (платформу машинного обучения Apple), разработанную для унифицированной архитектуры памяти. PyTorch также имеет внутреннюю поддержку MPS (Metal Performance Shaders), хотя она менее развита, чем CUDA.

## Авто-векторизация

— Написание встроенных функций SIMD утомительно. Может ли **компилятор** автоматически векторизовать ваш код?

- Да, с оговорками. Современные компиляторы (GCC, Clang) могут автоматически векторизировать простые циклы:

```cpp
// The compiler CAN auto-vectorise this (with -O3 -march=native)
void add_auto(const float* a, const float* b, float* c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}
```

- **Шаблоны, помогающие выполнять автоматическую векторизацию**:
    - Простые циклы с известным количеством поездок.
    — Нет зависимости данных между итерациями (`c[i]` не зависит от `c[i-1]`).
    - Непрерывный доступ к памяти (без разброса/сбора).
    - Указатели `const` и `restrict` (сообщают, что массивы компилятора не перекрываются).

```cpp
// restrict tells the compiler: a, b, c point to non-overlapping memory
void add_restrict(const float* __restrict__ a,
                  const float* __restrict__ b,
                  float* __restrict__ c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}
```

- Без `restrict` компилятор должен предполагать, что `c` может перекрываться с `a` или `b` (запись в `c[i]` может изменить `a[i+1]`), предотвращая векторизацию.

- **Шаблоны, предотвращающие автоматическую векторизацию**:
    — Зависимости данных: `a[i] = a[i-1] + b[i]` (каждая итерация зависит от предыдущей).
    — Сложный поток управления: операторы `if` внутри цикла (если только компилятор не может преобразовать их в предикацию).
    - Вызовы функций внутри цикла (если функция не встроена).
    — Совмещение указателей (массивы могут перекрываться, без `restrict`).

- **Проверка автоматической векторизации**: используйте флаги компилятора, чтобы увидеть, что было векторизовано:

```bash
# GCC: show vectorisation decisions
g++ -O3 -march=native -fopt-info-vec-optimized code.cpp

# Clang: show vectorisation report
clang++ -O3 -march=native -Rpass=loop-vectorize code.cpp
```

- **Когда использовать встроенные функции или автоматическую векторизацию**: начните с чистого C++ и оптимизации компилятора. Если компилятор векторизует ваш цикл, отлично. Если производительность по-прежнему недостаточна, проверьте отчет о векторизации компилятора, чтобы понять, почему, и только затем напишите встроенные функции для критического внутреннего цикла. Преждевременные встроенные функции делают код нечитаемым без гарантированной выгоды.

1. Напишите скалярное скалярное произведение и векторизованное скалярное произведение NEON. Проверьте оба и измерьте ускорение.
```cpp
// task1_neon_dot.cpp
// Compile (Mac/ARM Linux): clang++ -O3 -o task1 task1_neon_dot.cpp
// Note: NEON is enabled by default on AArch64, no special flags needed

#include <iostream>
#include <chrono>
#include <vector>
#include <arm_neon.h>

float dot_scalar(const float* a, const float* b, int n) {
    float sum = 0.0f;
    for (int i = 0; i < n; i++) {
        sum += a[i] * b[i];
    }
    return sum;
}

float dot_neon(const float* a, const float* b, int n) {
    float32x4_t sum_vec = vdupq_n_f32(0.0f);
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t va = vld1q_f32(a + i);
        float32x4_t vb = vld1q_f32(b + i);
        sum_vec = vfmaq_f32(sum_vec, va, vb);
    }
    float sum = vaddvq_f32(sum_vec);
    for (; i < n; i++) sum += a[i] * b[i];
    return sum;
}

int main() {
    const int N = 10'000'000;
    std::vector<float> a(N, 1.0f), b(N, 2.0f);

    // Warm up
    volatile float s1 = dot_scalar(a.data(), b.data(), N);
    volatile float s2 = dot_neon(a.data(), b.data(), N);

    // Benchmark scalar
    auto start = std::chrono::high_resolution_clock::now();
    for (int t = 0; t < 100; t++) {
        s1 = dot_scalar(a.data(), b.data(), N);
    }
    auto end = std::chrono::high_resolution_clock::now();
    double scalar_ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;

    // Benchmark NEON
    start = std::chrono::high_resolution_clock::now();
    for (int t = 0; t < 100; t++) {
        s2 = dot_neon(a.data(), b.data(), N);
    }
    end = std::chrono::high_resolution_clock::now();
    double neon_ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;

    std::cout << "Scalar: " << scalar_ms << " ms (result: " << s1 << ")\n";
    std::cout << "NEON:   " << neon_ms << " ms (result: " << s2 << ")\n";
    std::cout << "Speedup: " << scalar_ms / neon_ms << "x\n";
    return 0;
}

2. Внедрить NEON ReLU и softmax-max-finding. Попрактикуйтесь в использовании шаблона «загрузка→вычисление→сохранение» с различными операциями.
```cpp
// task2_neon_ops.cpp
// Compile: clang++ -O3 -o task2 task2_neon_ops.cpp

#include <iostream>
#include <vector>
#include <cmath>
#include <arm_neon.h>

void relu_neon(const float* in, float* out, int n) {
    float32x4_t zero = vdupq_n_f32(0.0f);
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t x = vld1q_f32(in + i);
        vst1q_f32(out + i, vmaxq_f32(x, zero));
    }
    for (; i < n; i++) out[i] = in[i] > 0 ? in[i] : 0;
}

float max_neon(const float* data, int n) {
    float32x4_t max_vec = vdupq_n_f32(-INFINITY);
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        max_vec = vmaxq_f32(max_vec, vld1q_f32(data + i));
    }
    float result = vmaxvq_f32(max_vec);
    for (; i < n; i++) result = result > data[i] ? result : data[i];
    return result;
}

int main() {
    std::vector<float> data = {-3, 1, -1, 4, 2, -5, 0, 7, -2, 3};
    std::vector<float> out(data.size());

    relu_neon(data.data(), out.data(), data.size());
    std::cout << "ReLU: ";
    for (float x : out) std::cout << x << " ";
    std::cout << "\n";

    float mx = max_neon(data.data(), data.size());
    std::cout << "Max: " << mx << " (expected: 7)\n";
    return 0;
}

// task3_auto_vs_manual.cpp
// Compile: clang++ -O3 -Rpass=loop-vectorize -o task3 task3_auto_vs_manual.cpp
//    (or): g++ -O3 -fopt-info-vec-optimized -o task3 task3_auto_vs_manual.cpp

#include <iostream>
#include <chrono>
#include <vector>
#include <arm_neon.h>

// Let the compiler auto-vectorise
void add_auto(const float* __restrict__ a, const float* __restrict__ b,
              float* __restrict__ c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

// Hand-written NEON
void add_neon(const float* a, const float* b, float* c, int n) {
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        vst1q_f32(c + i, vaddq_f32(vld1q_f32(a + i), vld1q_f32(b + i)));
    }
    for (; i < n; i++) c[i] = a[i] + b[i];
}

int main() {
    const int N = 10'000'000;
    std::vector<float> a(N, 1.0f), b(N, 2.0f), c(N);

    auto bench = [&](auto fn, const char* name) {
        fn(a.data(), b.data(), c.data(), N);  // warm up
        auto start = std::chrono::high_resolution_clock::now();
        for (int t = 0; t < 100; t++) fn(a.data(), b.data(), c.data(), N);
        auto end = std::chrono::high_resolution_clock::now();
        double ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;
        std::cout << name << ": " << ms << " ms\n";
    };

    bench(add_auto, "Auto-vectorised");
    bench(add_neon, "Hand-written NEON");
    // They should be very close — the compiler auto-vectorises this simple loop well
    return 0;
}
