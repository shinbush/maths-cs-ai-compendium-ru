# RISC-V и встроенные системы

*RISC-V — это архитектура набора команд с открытым исходным кодом, которая меняет индустрию микросхем. В этом файле описаны философия RISC-V, расширение V-вектора, встроенный вывод машинного обучения, TinyML в микроконтроллерах, RISC-V в ускорителях искусственного интеллекта и ограничения периферийного развертывания*.

- Для каждой рассмотренной нами архитектуры чипа (x86, ARM) требуется **лицензия**. Intel и AMD платят за x86. Apple, Qualcomm и все производители смартфонов платят ARM миллиарды в год. **RISC-V** отличается: это открытый стандарт. Любой может разрабатывать, производить и продавать чипы RISC-V, не выплачивая никому роялти. Это меняет экономику проектирования чипов, особенно для искусственного интеллекта.

## Философия RISC-V

- RISC-V (произносится как «риск пять») был создан в Калифорнийском университете в Беркли в 2010 году как чистый, современный набор инструкций RISC. Ключевые принципы:

    - **Открытый стандарт**: спецификация ISA находится в свободном доступе. Вы можете создать процессор RISC-V без лицензионных отчислений, соглашений о неразглашении или юридических соглашений. Это похоже на то, как Linux относится к операционным системам — каждый может использовать, модифицировать и развивать его.

    - **Модульная конструкция**: базовая ISA (RV32I или RV64I) минимальна — всего 47 инструкций. Все остальное является необязательным **расширением**: M (умножение/деление), A (атомарные операции), F/D (с плавающей запятой), C (сжатые инструкции), V (векторная обработка). Вы выбираете только то, что вам нужно, сохраняя небольшой размер и эффективность чипа.

    - **Нет устаревшего багажа**: x86 имеет 45-летнюю обратную совместимость. ARM имеет 35-летний юбилей. RISC-V начинается с чистого листа, включающего уроки, извлеченные из обоих. Никаких непонятных инструкций, существующих только для совместимости с ПО 1980-х годов.

- **Кто использует RISC-V**: SiFive (ядра общего назначения), Alibaba (серверные ядра Xuantie), Western Digital (контроллеры хранения данных, поставленные миллиарды), Espressif (ESP32-C3, популярный чип IoT) и десятки стартапов-ускорителей искусственного интеллекта, которые используют RISC-V в качестве управляющего процессора, управляющего своими собственными вычислительными блоками.

## Базовая архитектура RISC-V

- Базовое целое число ISA (RV64I для 64-разрядной версии) имеет:
    - **32 регистра общего назначения** (x0-x31, каждый 64-битный). x0 жестко привязан к нулю (полезно для реализации общих шаблонов без специальных инструкций).
    - **Фиксированная 32-битная ширина инструкций** (с расширением C, добавляющим 16-битные сжатые инструкции для плотности кода).
    - **Архитектура загрузки-сохранения**: как и в ARM, арифметика работает только с регистрами. Доступ к памяти осуществляется посредством явных инструкций загрузки/сохранения.

```
# RISC-V assembly (for flavour — you will use C/C++)
add  x3, x1, x2      # x3 = x1 + x2
lw   x4, 0(x5)       # load word from address in x5
sw   x4, 8(x5)       # store word to address x5 + 8
beq  x1, x2, label   # branch if x1 == x2
```

- Простота ISA делает ядра RISC-V небольшими и энергоэффективными. Минимальное ядро ​​RV32I может быть реализовано примерно в 10 000 вентилей (для ARM Cortex-M0 — около 12 000). Это важно для встраиваемых систем, где важен каждый милливатт и каждый квадратный миллиметр кремния.

## Расширение V: векторная обработка RISC-V

- Расширение **V** (RVV) добавляет к RISC-V масштабируемую векторную обработку, аналогичную ARM SVE. Векторные регистры имеют настраиваемую длину (VLEN), определяемую аппаратным обеспечением (от 128 до 65 536 бит). Код написан **независимо от длины вектора**: он работает на любой VLEN без перекомпиляции.

```c
#include <riscv_vector.h>

// Vector addition using RVV intrinsics
void vadd_rvv(const float* a, const float* b, float* c, int n) {
    while (n > 0) {
        // vsetvl: set vector length — processes min(n, hardware_max) elements
        size_t vl = __riscv_vsetvl_e32m1(n);

        // Load vl elements
        vfloat32m1_t va = __riscv_vle32_v_f32m1(a, vl);
        vfloat32m1_t vb = __riscv_vle32_v_f32m1(b, vl);

        // Add
        vfloat32m1_t vc = __riscv_vfadd_vv_f32m1(va, vb, vl);

        // Store
        __riscv_vse32_v_f32m1(c, vc, vl);

        // Advance pointers
        a += vl; b += vl; c += vl; n -= vl;
    }
}
```

- **`vsetvl`** — ключевая инструкция. Он сообщает оборудованию: «Я хочу обработать такое количество элементов», а оборудование отвечает: «Я могу обработать такое количество» (ограничено VLEN). Цикл автоматически адаптируется к любой ширине вектора без необходимости скалярной очистки (последняя итерация просто обрабатывает меньше элементов).

- **LMUL** (множитель длины): RVV может группировать несколько векторных регистров вместе (m1, m2, m4, m8) для обработки большего количества элементов за команду за счет меньшего количества доступных регистров. `m1` использует один регистр для каждого векторного операнда; `m8` использует восемь, обрабатывая в 8 раз больше элементов, но оставляет доступными только 4 группы регистров.

- По сравнению с x86 AVX (фиксированная 256/512-битная версия) и ARM NEON (фиксированная 128-битная версия) масштабируемость RVV является основным преимуществом для разнообразного оборудования: один и тот же код выполняется на крошечном встроенном ядре (VLEN=128) и высокопроизводительном серверном ядре (VLEN=1024+).

## Встроенное машинное обучение: TinyML- **TinyML** — это машинное обучение на микроконтроллерах — устройствах с килобайтами оперативной памяти, процессорами мегагерцового класса и бюджетом мощности в милливаттах. Подумайте: датчик, распознающий ключевые слова («Привет, Siri»), акселерометр, классифицирующий жесты, или камера, подсчитывающая людей, — все это работает на чипе стоимостью 0,50 доллара и без подключения к Интернету.

- Ограничения экстремальны:

| Ресурс | Серверный графический процессор | Смартфон | Микроконтроллер |
|----------|-----------|------------|-----------------|
| ОЗУ | 80 ГБ | 6 ГБ | 256 КБ |
| Хранение | туберкулез | 128 ГБ | 1 МБ |
| Вычислить | 1000 терафлопс | 10 терафлопс | 0,001 Тфлопс |
| Мощность | 700 Вт | 5 Вт | 0,001 Вт |
| Стоимость | $30,000 | $500 | 1 доллар |

- Модель, подходящая для серверного графического процессора (параметры $O(10^{10})$), не подойдет для микроконтроллера. Модели TinyML имеют параметры $O(10^4)$ – $O(10^6)$ и используют квантование INT8 или даже INT4.

### TensorFlow Lite Micro (TFLM)

- **TFLM** — это платформа вывода Google для микроконтроллеров. Он запускает квантованные модели TensorFlow Lite без динамического выделения памяти, без операционной системы и с двоичным размером ~ 20 КБ.

```cpp
// TinyML inference on a microcontroller (simplified)
#include "tensorflow/lite/micro/micro_interpreter.h"
#include "tensorflow/lite/micro/micro_mutable_op_resolver.h"

// Model is compiled into a C array (const unsigned char model_data[])
const tflite::Model* model = tflite::GetModel(model_data);

// Allocate a fixed memory arena (no malloc!)
constexpr int kArenaSize = 10 * 1024;  // 10 KB
uint8_t tensor_arena[kArenaSize];

// Set up interpreter
tflite::MicroInterpreter interpreter(model, resolver, tensor_arena, kArenaSize);
interpreter.AllocateTensors();

// Set input
float* input = interpreter.input(0)->data.f;
input[0] = sensor_reading;

// Run inference
interpreter.Invoke();

// Read output
float* output = interpreter.output(0)->data.f;
if (output[0] > 0.8f) {
    trigger_alert();
}
```

- **Основные ограничения в этом коде**:
    — `tensor_arena` выделен статически — ни `malloc`, ни кучи. Встроенные системы часто не имеют динамического распределителя памяти.
    - Модель представляет собой байтовый массив `const`, хранящийся во флэш-памяти (ПЗУ), не загружаемый из файловой системы.
    — Весь фреймворк+модель+рантайм умещается в несколько десятков КБ.

### Оптимизация модели для Edge

- Для запуска модели на микроконтроллере требуется агрессивная оптимизация:

    - **Квантование** (глава 18): преобразование весов float32 в INT8 (в 4 раза меньше, в 2–4 раза быстрее на аппаратном обеспечении, работающем только с целыми числами). Квантование после обучения простое; Обучение с учетом квантования сохраняет большую точность.

    - **Сокращение**: удаление весов, близких к нулю. Структурированное сокращение (удаление целых каналов/головок) более удобно для аппаратного обеспечения, чем неструктурированное сокращение (случайные нули), поскольку оно сокращает фактические вычисления, а не только объем памяти.

    - **Дистилляция знаний** (глава 6): обучите маленькую модель «ученика» имитировать большую модель «учителя». Учащийся достигает более высокой точности, чем обучение с нуля, поскольку он учится на мягких прогнозах учителя.

    - **Поиск нейронной архитектуры (NAS)**: автоматический поиск эффективных архитектур, соответствующих аппаратному бюджету (задержка, память, мощность). **MicroNets** и **MCUNet** находят архитектуры, оптимизированные для конкретных микроконтроллеров.

    - **Слияние операторов**: объедините conv + пакетную норму + ReLU в одну объединенную операцию, исключая промежуточные записи в память (тот же принцип, что и слияние ядра графического процессора, но еще более важно, если у вас 256 КБ ОЗУ).

## RISC-V в ускорителях искусственного интеллекта

- Многие стартапы-ускорители искусственного интеллекта используют RISC-V не для непосредственного запуска моделей машинного обучения, а в качестве **управляющего процессора**, который управляет пользовательскими вычислительными блоками:

```
┌─────────────────────────────────────────┐
│              AI Accelerator             │
│                                         │
│  ┌──────────┐    ┌──────────────────┐   │
│  │  RISC-V  │───→│  Custom Matrix   │   │
│  │  Control │    │  Multiply Unit   │   │
│  │  Core    │    │  (systolic array,│   │
│  │          │    │  custom dataflow)│   │
│  └──────────┘    └──────────────────┘   │
│       │                    │            │
│       ▼                    ▼            │
│  ┌──────────┐    ┌──────────────────┐   │
│  │  Memory  │    │  On-chip SRAM    │   │
│  │  Control │    │  (activation     │   │
│  │          │    │   buffer)        │   │
│  └──────────┘    └──────────────────┘   │
└─────────────────────────────────────────┘
```

- Ядро RISC-V обеспечивает загрузку весов модели из внешней памяти, планирование выполнения уровней, управление потоком данных между вычислительными блоками и связь с хостом (через PCIe, USB или SPI). Тяжелые вычисления (умножение матриц, свертки) выполняются специальным оборудованием, а не ядром RISC-V.

- **Почему RISC-V для управления**: отсутствие затрат на лицензирование (критически важно для стартапов), возможность настройки (добавление специфичных для предметной области инструкций), небольшой размер (ядро управления не требует сложности x86), а открытая экосистема позволяет быстро создавать прототипы.

- **Примеры**: Esperanto Technologies (более 1000 ядер RISC-V для ML), Tenstorrent (управление RISC-V + специальные ядра tensix), SiFive (ядра RISC-V с векторными расширениями для Edge ML).

## Ограничения периферийного развертывания

- Развертывание машинного обучения на периферии (на устройстве, а не в облаке) накладывает ограничения, с которыми не сталкивается облачное развертывание:

- **Мощность**: общий бюджет устройства с батарейным питанием может составлять 100 мВт. Запуск модели, потребляющей 50 мВт, оставляет только 50 мВт для остальной части системы (датчики, радио, дисплей). Логический вывод с учетом энергопотребления планирует вычисления, чтобы избежать теплового регулирования и продлить срок службы батареи.- **Задержка**: вывод границ часто должен осуществляться в реальном времени. Детектор слов пробуждения («Привет, Siri») должен среагировать в течение примерно 200 мс. Система восприятия автономного вождения (глава 11) должна обрабатывать кадры в течение ~30 мс. Обратный путь по сети в облако (50–200 мс) слишком медленный для этих случаев использования.

- **Конфиденциальность**: обработка данных на устройстве означает, что конфиденциальные данные (медицинские изображения, записи голоса, личные фотографии) никогда не покидают устройство. Это требование закона в некоторых юрисдикциях (GDPR) и требование доверия пользователей повсюду.

- **Подключение**: периферийные устройства могут иметь прерывистое подключение к Интернету или вообще отсутствовать. Модель, работающая на марсоходе (глава 11), подводной лодке или датчике на сельской ферме, должна работать полностью в автономном режиме.

- **Цена при масштабировании**: развертывание машинного обучения на миллиарде смартфонов стоит 0 долларов США за устройство (оборудование уже существует). Развертывание на миллиарде датчиков Интернета вещей означает, что аппаратный бюджет ML каждого датчика составляет копейки. Нулевая стоимость лицензирования RISC-V имеет огромное значение в этом масштабе.

1. Напишите программу на C, которая имитирует конвейер вывода TinyML: статически выделите буфер модели, запустите имитацию прямого прохода и измерьте использование ресурсов. Это учит встроенным ограничениям (без malloc, арена с фиксированной памятью).
```cpp
// task1_tinyml_sim.cpp
// Compile: g++ -O2 -o task1 task1_tinyml_sim.cpp

#include <iostream>
#include <chrono>
#include <cmath>
#include <cstring>

// Simulate a microcontroller: fixed memory arena, no dynamic allocation
static constexpr int ARENA_SIZE = 32 * 1024;  // 32 KB total RAM budget
static uint8_t arena[ARENA_SIZE];

// Simple 2-layer MLP: 784 -> 64 -> 10 (MNIST-like, INT8 weights)
struct TinyModel {
    int8_t w1[784 * 64];      // layer 1 weights: 50,176 bytes
    int8_t b1[64];             // layer 1 biases
    int8_t w2[64 * 10];       // layer 2 weights: 640 bytes
    int8_t b2[10];             // layer 2 biases
    // Total: ~51 KB → must go in flash (ROM), not RAM
};

// Check if model fits in flash
void check_model_fit(int flash_kb) {
    int model_bytes = sizeof(TinyModel);
    std::cout << "Model size: " << model_bytes << " bytes ("
              << model_bytes / 1024 << " KB)\n";
    std::cout << "Flash: " << flash_kb << " KB → "
              << (model_bytes <= flash_kb * 1024 ? "FITS" : "TOO LARGE") << "\n";
}

// Mock inference using the fixed arena for activations
void mock_inference(const int8_t* input, int8_t* output) {
    // Activations go in the arena (RAM), not allocated dynamically
    int8_t* act1 = (int8_t*)arena;            // 64 bytes for layer 1 output
    int8_t* act2 = (int8_t*)(arena + 64);     // 10 bytes for layer 2 output

    // Layer 1: simplified matmul (not real quantised matmul, just structure demo)
    for (int j = 0; j < 64; j++) {
        int32_t sum = 0;  // accumulate in int32 to avoid overflow
        for (int i = 0; i < 784; i++) {
            sum += (int32_t)input[i] * 1;  // mock: weight = 1
        }
        act1[j] = (int8_t)std::max(-128, std::min(127, sum / 784));  // quantise back
        act1[j] = act1[j] > 0 ? act1[j] : 0;  // ReLU
    }

    // Layer 2
    for (int j = 0; j < 10; j++) {
        int32_t sum = 0;
        for (int i = 0; i < 64; i++) {
            sum += (int32_t)act1[i] * 1;
        }
        act2[j] = (int8_t)std::max(-128, std::min(127, sum / 64));
    }

    std::memcpy(output, act2, 10);
}

int main() {
    std::cout << "=== TinyML Resource Budget ===\n";
    std::cout << "Arena (RAM): " << ARENA_SIZE << " bytes ("
              << ARENA_SIZE / 1024 << " KB)\n";
    check_model_fit(256);  // typical MCU flash

    // Activation memory used
    int activation_bytes = 64 + 10;  // layer 1 + layer 2 outputs
    std::cout << "Activation memory: " << activation_bytes
              << " bytes / " << ARENA_SIZE << " available\n\n";

    // Benchmark inference
    int8_t input[784];
    int8_t output[10];
    std::memset(input, 1, 784);

    auto start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < 10000; i++) {
        mock_inference(input, output);
    }
    auto end = std::chrono::high_resolution_clock::now();
    double us = std::chrono::duration<double, std::micro>(end - start).count() / 10000;

    std::cout << "Inference latency: " << us << " us\n";
    std::cout << "At 160 MHz MCU (~6.25 ns/cycle): ~"
              << (int)(us * 160) << " cycles\n";

    std::cout << "Output logits: ";
    for (int i = 0; i < 10; i++) std::cout << (int)output[i] << " ";
    std::cout << "\n";

    return 0;
}
```

2. Напишите программу на C++, которая квантует веса float32 до INT8 и измеряет степень сжатия и ошибку квантования.
```cpp
// task2_quantise.cpp
// Compile: g++ -O3 -o task2 task2_quantise.cpp

#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>
#include <numeric>

// Symmetric quantisation: map float range [-max, +max] to [-127, +127]
void quantise_symmetric(const float* input, int8_t* output, int n, float& scale) {
    float max_val = 0.0f;
    for (int i = 0; i < n; i++) {
        max_val = std::max(max_val, std::abs(input[i]));
    }
    scale = max_val / 127.0f;
    for (int i = 0; i < n; i++) {
        float scaled = input[i] / scale;
        output[i] = (int8_t)std::max(-127.0f, std::min(127.0f, std::round(scaled)));
    }
}

// Dequantise: INT8 back to float
void dequantise(const int8_t* input, float* output, int n, float scale) {
    for (int i = 0; i < n; i++) {
        output[i] = (float)input[i] * scale;
    }
}

int main() {
    const int N = 100000;

    // Simulate random weights (roughly normal distribution)
    std::vector<float> weights(N);
    for (int i = 0; i < N; i++) {
        // Simple pseudo-random normal-ish values
        float u1 = (float)(i * 7 % 997 + 1) / 998.0f;
        float u2 = (float)(i * 13 % 991 + 1) / 992.0f;
        weights[i] = std::sqrt(-2.0f * std::log(u1)) * std::cos(6.2832f * u2) * 0.1f;
    }

    // Quantise
    std::vector<int8_t> quantised(N);
    float scale;
    quantise_symmetric(weights.data(), quantised.data(), N, scale);

    // Dequantise and measure error
    std::vector<float> reconstructed(N);
    dequantise(quantised.data(), reconstructed.data(), N, scale);

    float max_error = 0.0f, total_error = 0.0f;
    for (int i = 0; i < N; i++) {
        float err = std::abs(weights[i] - reconstructed[i]);
        max_error = std::max(max_error, err);
        total_error += err;
    }

    std::cout << "=== Quantisation Results ===\n";
    std::cout << "Original:    " << N * 4 << " bytes (float32)\n";
    std::cout << "Quantised:   " << N * 1 << " bytes (int8) + 4 bytes (scale)\n";
    std::cout << "Compression: " << 4.0f << "x\n";
    std::cout << "Scale factor: " << scale << "\n";
    std::cout << "Mean abs error: " << total_error / N << "\n";
    std::cout << "Max abs error:  " << max_error << "\n";
    std::cout << "Max abs error / scale: " << max_error / scale
              << " (should be <= 0.5 quantisation levels)\n";

    return 0;
}
```

3. Напишите программу на C++, которая выполняет умножение матрицы INT8 с накоплением INT32 — фактические вычисления, выполняемые на встроенных ускорителях машинного обучения.
```cpp
// task3_int8_matmul.cpp
// Compile: g++ -O3 -o task3 task3_int8_matmul.cpp

#include <iostream>
#include <chrono>
#include <vector>
#include <cstdint>

// INT8 matmul with INT32 accumulation (what Tensor Cores and MCU accelerators do)
void matmul_int8(const int8_t* A, const int8_t* B, int32_t* C,
                 int M, int N, int K) {
    for (int i = 0; i < M; i++) {
        for (int j = 0; j < N; j++) {
            int32_t sum = 0;
            for (int k = 0; k < K; k++) {
                sum += (int32_t)A[i * K + k] * (int32_t)B[k * N + j];
            }
            C[i * N + j] = sum;
        }
    }
}

// Float32 matmul for comparison
void matmul_f32(const float* A, const float* B, float* C,
                int M, int N, int K) {
    for (int i = 0; i < M; i++) {
        for (int j = 0; j < N; j++) {
            float sum = 0.0f;
            for (int k = 0; k < K; k++) {
                sum += A[i * K + k] * B[k * N + j];
            }
            C[i * N + j] = sum;
        }
    }
}

int main() {
    const int M = 128, N = 128, K = 128;

    std::vector<int8_t> A_i8(M * K, 1), B_i8(K * N, 1);
    std::vector<int32_t> C_i32(M * N);

    std::vector<float> A_f32(M * K, 1.0f), B_f32(K * N, 1.0f);
    std::vector<float> C_f32(M * N);

    // Benchmark INT8
    auto start = std::chrono::high_resolution_clock::now();
    for (int t = 0; t < 100; t++) {
        matmul_int8(A_i8.data(), B_i8.data(), C_i32.data(), M, N, K);
    }
    auto end = std::chrono::high_resolution_clock::now();
    double i8_ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;

    // Benchmark FP32
    start = std::chrono::high_resolution_clock::now();
    for (int t = 0; t < 100; t++) {
        matmul_f32(A_f32.data(), B_f32.data(), C_f32.data(), M, N, K);
    }
    end = std::chrono::high_resolution_clock::now();
    double f32_ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;

    double gflops_i8 = 2.0 * M * N * K / i8_ms / 1e6;
    double gflops_f32 = 2.0 * M * N * K / f32_ms / 1e6;

    std::cout << "INT8 matmul:  " << i8_ms << " ms (" << gflops_i8 << " GOPS)\n";
    std::cout << "FP32 matmul:  " << f32_ms << " ms (" << gflops_f32 << " GFLOPS)\n";
    std::cout << "INT8 speedup: " << f32_ms / i8_ms << "x\n";
    std::cout << "Memory: INT8 = " << M*K + K*N << " bytes vs FP32 = "
              << (M*K + K*N) * 4 << " bytes (4x less)\n";

    return 0;
}
```
