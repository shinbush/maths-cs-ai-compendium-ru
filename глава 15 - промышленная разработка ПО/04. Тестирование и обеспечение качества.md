# Тестирование и обеспечение качества

*Тестирование — это то, как вы узнаете, что ваш код работает, не только сейчас, но и после каждого изменения. В этом файле описана пирамида тестирования, модульные тесты с помощью pytest, макетирование, тестирование кода, специфичного для машинного обучения, конвейеры CI/CD, анализ, форматирование и проверка кода, а также методы выявления ошибок до того, как они попадут в рабочую среду.*

- Код ML, как известно, недостаточно протестирован. «Он тренируется, следовательно, он работает» — преобладающая установка. Это приводит к скрытым ошибкам: загрузчик данных, который перетасовывает неправильно, функция потерь с ошибкой знака, этап предварительной обработки, который отбрасывает 5% данных. Эти ошибки не приводят к сбою вашей программы. Они просто ухудшают вашу модель, и вы тратите недели на отладку показателей, которые «должны быть выше».

- Тестирование не является накладным. Это самый быстрый способ быстро передвигаться, не ломая вещей.

## Пирамида испытаний

- Тесты организованы по слоям: от быстрого и узкого до медленного и широкого:

    - **Модульные тесты** (базовый): тестируйте отдельные функции и классы изолированно. Быстрые (миллисекунды), многочисленные (от сотен до тысяч). «Выдает ли `normalise_image` значения в [0, 1]?»

    - **Интеграционные тесты** (в центре): проверка совместной работы компонентов. Медленнее (секунды). «Создает ли загрузчик данных пакеты в формате, ожидаемом моделью?»

    - **Сквозные тесты** (вверху): протестируйте весь конвейер от входа до выхода. Медленно (минуты). «Завершается ли `python train.py --config test.yaml` без ошибок и создает ли действительную контрольную точку?»

- Форма пирамиды означает: напишите много модульных тестов, меньше интеграционных тестов и несколько сквозных тестов. Модульные тесты выявляют большинство ошибок и выполняются за считанные секунды. Сквозные тесты выявляют проблемы интеграции, но они медленны и нестабильны.

## Юнит-тесты с pytest

- **pytest** — это стандартная среда тестирования Python. Тест — это функция, начинающаяся с `test_` в файле, начинающемся с `test_`:

```python
# tests/test_utils.py

def test_normalise_image():
    import numpy as np
    image = np.array([0, 128, 255], dtype=np.uint8)
    result = normalise_image(image, mean=128, std=128)
    assert result.min() >= -1.0
    assert result.max() <= 1.0
    assert abs(result[1]) < 1e-6  # 128 normalised by mean=128 should be ~0

def test_normalise_empty():
    import numpy as np
    image = np.array([], dtype=np.uint8)
    result = normalise_image(image, mean=128, std=128)
    assert len(result) == 0
```

```bash
pytest tests/                     # run all tests
pytest tests/test_utils.py        # run one file
pytest -v                         # verbose output
pytest -x                         # stop on first failure
pytest -k "normalise"             # run tests matching name pattern
pytest --tb=short                 # shorter tracebacks
```

### Светильники

- **Фикстуры** обеспечивают возможность многократного использования для тестов. Вместо повторения кода настройки в каждом тесте определите его один раз:

```python
import pytest

@pytest.fixture
def sample_dataset():
    """Create a small dataset for testing."""
    return {
        "inputs": torch.randn(10, 3, 32, 32),
        "labels": torch.randint(0, 10, (10,))
    }

@pytest.fixture
def trained_model():
    """Load a small pretrained model."""
    model = SmallModel()
    model.load_state_dict(torch.load("tests/fixtures/small_model.pt"))
    return model

def test_model_output_shape(trained_model, sample_dataset):
    output = trained_model(sample_dataset["inputs"])
    assert output.shape == (10, 10)  # batch_size x num_classes
```

- Фикстуры могут иметь **области**: `scope="function"` (по умолчанию, обновляются для каждого теста), `scope="module"` (один раз для каждого файла), `scope="session"` (один раз для каждого теста). Используйте `scope="session"` для дорогостоящей настройки, например загрузки модели.

### Параметризованные тесты

- Протестируйте одну и ту же функцию с несколькими входами без дублирования кода:

```python
@pytest.mark.parametrize("input,expected", [
    ([1, 2, 3], 6),
    ([], 0),
    ([-1, 1], 0),
    ([1000000, 1000000], 2000000),
])
def test_sum(input, expected):
    assert sum(input) == expected
```

## Издевательство и исправление

- **Mocking** заменяет реальную зависимость фальшивой во время тестирования. Это позволяет тестировать функцию изолированно, без необходимости использования базы данных, API или графического процессора.

```python
from unittest.mock import patch, MagicMock

def test_training_logs_metrics():
    mock_logger = MagicMock()

    with patch("my_project.training.trainer.wandb") as mock_wandb:
        trainer = Trainer(logger=mock_logger)
        trainer.train_one_epoch()

        # verify that the trainer logged metrics
        mock_logger.log.assert_called()
        # verify it logged a loss value
        call_args = mock_logger.log.call_args
        assert "loss" in call_args[1]
```

- **Когда имитировать**: внешние сервисы (API, базы данных, облачное хранилище), дорогостоящие операции (вычисления на графическом процессоре, ввод-вывод больших файлов) и недетерминированное поведение (генераторы случайных чисел, временные метки).

- **Когда НЕ издеваться**: свой собственный код. Если вы имитируете все, ваши тесты проверяют, что макеты ведут себя должным образом, а не работает ли ваш код. Издевайтесь над границами, проверяйте свою логику напрямую.

## Тестирование кода машинного обучения

- Код ML сталкивается с уникальными проблемами тестирования: выходные данные являются вероятностными, обучение происходит медленно, а «правильный» — нечетким.

### Детерминированные семена

- Установите случайные начальные числа повсюду, чтобы сделать тесты воспроизводимыми:

```python
import random
import numpy as np
import torch

def set_seed(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    if torch.cuda.is_available():
        torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
```

### Числовые допуски

- Сравнения с плавающей запятой требуют допусков (глава 13, IEEE 754):

```python
# BAD: exact comparison fails due to floating point
assert model_output == 0.5

# GOOD: approximate comparison
import numpy as np
assert np.isclose(model_output, 0.5, atol=1e-5)

# For tensors
assert torch.allclose(output, expected, atol=1e-4)
```

### Что тестировать в машинном обучении

– **Тесты формы**: убедитесь, что выходные данные имеют ожидаемые размеры.

```python
def test_model_output_shape():
    model = MyModel(d_model=256, n_classes=10)
    x = torch.randn(8, 32, 256)  # batch=8, seq=32, dim=256
    output = model(x)
    assert output.shape == (8, 10)
```

- **Градиентный поток**: убедитесь, что градиенты не равны нулю для обучаемых параметров.

```python
def test_gradients_flow():
    model = MyModel()
    x = torch.randn(4, 3, 32, 32)
    y = torch.randint(0, 10, (4,))

    output = model(x)
    loss = F.cross_entropy(output, y)
    loss.backward()

    for name, param in model.named_parameters():
        assert param.grad is not None, f"No gradient for {name}"
        assert param.grad.abs().sum() > 0, f"Zero gradient for {name}"
```

- **Переобучение одной партии**: модель должна иметь возможность запомнить одну партию. Если не может, значит, что-то в корне неправильно.

```python
def test_overfit_one_batch():
    model = MyModel()
    optimiser = torch.optim.Adam(model.parameters(), lr=1e-3)
    x, y = get_single_batch()

    for _ in range(100):
        loss = F.cross_entropy(model(x), y)
        loss.backward()
        optimiser.step()
        optimiser.zero_grad()

    assert loss.item() < 0.01, f"Cannot overfit one batch: loss={loss.item()}"
```

- **Проверка данных**: убедитесь, что загрузка данных дает действительные выходные данные.

```python
def test_dataset_basics():
    dataset = MyDataset("tests/fixtures/small_data.csv")
    assert len(dataset) > 0
    x, y = dataset[0]
    assert x.shape == (3, 224, 224)
    assert 0 <= y < 10
    assert not torch.isnan(x).any()
    assert not torch.isinf(x).any()
```

- **Детерминизм**: те же входные данные + то же начальное значение → тот же выход.

```python
def test_determinism():
    set_seed(42)
    output1 = model(input_data)
    set_seed(42)
    output2 = model(input_data)
    assert torch.allclose(output1, output2)
```

## Конвейеры CI/CD

- **Непрерывная интеграция (CI)**: автоматический запуск тестов при каждом коммите или PR. Если тесты не пройдены, PR не может быть объединен. Это предотвращает попадание сломанного кода в `main`.

- Пример **Действий GitHub** (`.github/workflows/ci.yml`):

```yaml
name: CI
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install -e ".[dev]"
      - run: ruff check src/
      - run: mypy src/
      - run: pytest tests/ -v --tb=short
```- **Перехватчики перед фиксацией**: запускайте проверки перед каждой фиксацией (локально), выявляя проблемы до того, как они достигнут CI:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.3.0
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.5.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
```

```bash
pip install pre-commit
pre-commit install    # now hooks run on every git commit
```

## Линтинг и форматирование

- **Линтинг** выявляет ошибки и проблемы со стилем без запуска кода. **Форматирование** автоматически обеспечивает единообразный стиль.

- **Ruff**: быстрый линтер и форматтер Python (заменяет flake8, isort и black в одном инструменте):

```bash
ruff check src/          # lint
ruff check --fix src/    # lint and auto-fix
ruff format src/         # format
```

- **mypy**: средство проверки статического типа для Python. Перехватывает ошибки типа перед выполнением:

```bash
mypy src/
# src/model.py:42: error: Argument 1 to "forward" has incompatible type "int"; expected "Tensor"
```

- Подсказки по типам позволяют коду самодокументироваться и выявлять ошибки:

```python
def train(
    model: nn.Module,
    dataloader: DataLoader,
    optimiser: torch.optim.Optimizer,
    num_epochs: int = 10,
) -> float:
    """Train model and return final loss."""
    ...
```

## Лучшие практики проверки кода

- **Для автора**:
    - Прежде чем запрашивать проверку, просмотрите разницу самостоятельно. Вы обнаружите очевидные проблемы.
    - Делайте PR небольшими и целенаправленными. Одна проблема на PR.
    — Напишите четкое описание: что, почему, как тестировать.
    - Отвечайте на каждый комментарий (даже если просто «готово»).

- **Для рецензента**:
    - Будьте добры. Критикуйте код, а не человека. «Это могло бы быть яснее», а не «это сбивает с толку».
    - Отличать вопросы блокировки (ошибки, безопасность) от предложений (стиль, именование). Используйте метки: «nit:», «suggestion:», «blocking:».
    - Задавайте вопросы вместо того, чтобы требовать. «Что произойдет, если этот список пуст?» более полезно, чем «обработать пустой ящик».
    - Одобряем срочно. Дни ожидания PR для рассмотрения блокируют автора и поощряют большие пакетные PR (которые труднее проверить).
