# Расширенная генерация текста

*Расширенная генерация текста выходит за рамки стандартного авторегрессионного декодирования и повышает качество, управляемость и скорость. В этом файле описаны модели распространения текста (D3PM, MDLM), OCR, RLHF и DPO для выравнивания, методы длинного контекста (масштабирование RoPE, кольцевое внимание), генерация с расширенным поиском и спекулятивное декодирование для более быстрого вывода.*

- Стандартная авторегрессионная генерация (файл 04) создает текст по одному токену, слева направо. Это просто и эффективно, но по своей сути является последовательным, не допускает глобального планирования и дает ограниченный контроль над результатами. В этом файле описаны методы, выходящие за рамки обычного авторегрессионного декодирования: диффузионные модели для текста, оптическое распознавание символов, управляемая генерация посредством обратной связи с человеком, обработка длинных контекстов, генерация с расширенным поиском и спекулятивное декодирование для более быстрого вывода.

- **Модели распространения текста** применяют структуру распространения (представленную для изображений в главе 08) к дискретному тексту. Основная проблема заключается в том, что текст дискретен: вы не можете добавлять непрерывный гауссовский шум к лексемам так же, как вы добавляете шум к пикселям. Несколько подходов решают эту проблему.

- **D3PM** (Вероятностные модели диффузии с дискретным шумоподавлением, Остин и др., 2021 г.) определяет процесс прямого повреждения непосредственно над дискретными токенами с использованием матриц перехода. На каждом шаге вперед токен имеет некоторую вероятность быть замененным другим токеном (равномерный шум), замаскирован (поглощающее состояние) или остаться прежним. Обратный процесс учится шумоподавлению, предсказывая чистый токен от поврежденного. Матрица перехода $Q_t$ на этапе $t$ контролирует повреждение:

$$q(x_t \mid x_{t-1}) = \text{Cat}(x_t ; \, x_{t-1} Q_t)$$

- где $\text{Cat}$ обозначает категориальное распределение, а $x$ - вектор горячего распределения. Многошаговый прямой процесс $q(x_t \mid x_0)$ имеет замкнутую форму: $q(x_t \mid x_0) = \text{Cat}(x_t ; \, x_0 \bar{Q}_t)$, где $\bar{Q}_t = Q_1 Q_2 \cdots Q_t$ — произведение всех матриц перехода до шага $t$. Обучение минимизирует вариационную нижнюю границу (ELBO), которая разлагается по временным шагам, аналогично непрерывному случаю (глава 08):

$$\mathcal{L}_{\text{D3PM}} = D_{\text{KL}}(q(x_T \mid x_0) \| p(x_T)) + \sum_{t=2}^{T} D_{\text{KL}}(q(x_{t-1} \mid x_t, x_0) \| p_\theta(x_{t-1} \mid x_t)) - \log p_\theta(x_0 \mid x_1)$$

- Первый член гарантирует, что полностью поврежденное распределение соответствует предыдущему (равномерному или полной маске). Сумма членов KL обучает модель обращать каждый шаг искажения: истинное обратное апостериорное значение $q(x_{t-1} \mid x_t, x_0)$ можно вычислить в закрытой форме с использованием правила Байеса и известных матриц перехода, а модель $p_\theta(x_{t-1} \mid x_t)$ обучается для сопоставления с ним. 

- Поскольку оба распределения категориальны, расхождение KL представляет собой простую сумму по словарным статьям. Последний термин измеряет качество восстановления наименее коррумпированного государства.

- **MDLM** (языковые модели маскированной диффузии, Sahoo et al., 2024) упрощает D3PM, используя маскирование как единственную операцию повреждения: прямой процесс постепенно заменяет токены на токен [MASK], а обратный процесс прогнозирует исходные токены. Это связывает распространение текста с моделированием языка в масках (BERT, файл 04), при этом временной шаг распространения определяет, какая часть токенов маскируется. На $t = 0$ текст полностью чистый; по адресу $t = T$ он полностью замаскирован.

- **Непрерывное распространение текста** обходит дискретную проблему, работая в непрерывном пространстве встраивания. Токены сначала сопоставляются с их векторами внедрения (глава 06), в это непрерывное пространство добавляется шум, а модель шумоподавления (обычно Transformer) учится обращать процесс вспять. Во время генерации модель создает непрерывные векторы, которые преобразуются обратно в дискретные токены путем поиска ближайшего вложения. Проблема заключается в том, что небольшие ошибки в непрерывном пространстве могут соответствовать совершенно неправильным токенам, поэтому необходимы осторожные округления и ограничения.

— Привлекательность распространения текста заключается в том, что он генерирует все токены одновременно посредством итеративного уточнения, а не слева направо. Это обеспечивает глобальную согласованность и простоту заполнения (генерацию недостающего текста в середине отрывка), но текущие модели распространения текста по-прежнему отстают от моделей авторегрессии по качеству генерации длинного текста.- **Text OCR** ​​(оптическое распознавание символов) — задача извлечения текста из изображений. Хотя современные системы оптического распознавания текста традиционно не связаны с генерацией языка, они глубоко интегрированы с НЛП и все чаще используют компоненты языковой модели.

- **Обнаружение текста сцены** находит текстовые области на естественных изображениях (дорожные знаки, этикетки продуктов, номерные знаки). Это сложно, потому что текст в естественной среде появляется под произвольными углами, масштабами, шрифтами и на загроможденном фоне. Методы обнаружения обычно используют магистрали CNN или Transformer для создания ограничивающих рамок или масок сегментации вокруг текстовых областей.

- **CRNN** (Сверточная рекуррентная нейронная сеть, Ши и др., 2017) — это классическая архитектура распознавания текста. CNN извлекает визуальные признаки из текстового изображения, карта признаков разбивается на последовательность столбцов (по одному на каждую горизонтальную позицию), а двунаправленный LSTM считывает эту последовательность для моделирования контекста. Выходные данные декодируются с использованием **CTC** (временной классификации коннекционистов), которая обеспечивает выравнивание между входными столбцами и выходными символами без необходимости явной сегментации.

- Фундаментальная проблема, которую решает CTC: модель создает выходные распределения $T$ (по одному на входной столбец), но целевой текст содержит символы $L \leq T$. 

— Мы не знаем, какие столбцы каким символам соответствуют. CTC представляет **пустой токен** $\epsilon$ и определяет сопоставление «многие к одному» $\mathcal{B}$, которое сворачивает повторяющиеся символы и удаляет пробелы: $\mathcal{B}(\text{"HH-ee-ll-ll-oo"}) = \text{"Hello"}$ (где «-» — это пробел). 

- Вероятность целевой последовательности $y$ представляет собой сумму всех входных выравниваний, которые схлопываются до $y$:

$$P(y \mid x) = \sum_{\pi \in \mathcal{B}^{-1}(y)} \prod_{t=1}^{T} P(\pi_t \mid x)$$

- где $\pi$ — путь выравнивания длиной $T$ (одна метка на столбец, включая пробелы). Наивное суммирование по всем путям является экспоненциальным, но **прямой алгоритм** (глава 05 HMM) эффективно вычисляет эту сумму за время $O(T \cdot L)$ с использованием динамического программирования. 

- Пустой токен необходим: без него повторяющиеся символы, такие как «ll» в «Hello», будут неотличимы от одиночного «l». Обучение максимизирует $\log P(y \mid x)$, и во время вывода лучший путь находится путем поиска луча или жадного декодирования на выходе CTC.

- **Document OCR** ​​обрабатывает структурированные документы (счета-фактуры, формы, научные статьи) и должен понимать макет в дополнение к распознаванию символов. Современные системы, такие как LayoutLM, сочетают распознавание текста с функциями пространственного положения: каждый токен получает как встраивание текста, так и позиционное встраивание, кодирующее его координаты $(x, y)$ на странице. Это позволяет модели понять, что число под надписью «Итого:» — это общая сумма.

![CRNN OCR Pipeline](../images/crnn_ocr_pipeline.svg)

- **Модели оптического распознавания символов на языке Vision**, такие как TrOCR, рассматривают распознавание текста как преобразование изображения в текст: кодировщик Vision Transformer обрабатывает изображение, а декодер языковой модели генерирует текст посимвольно. Это использует возможности предварительно обученных визуальных и языковых моделей и обрабатывает разнообразные сценарии, шрифты и макеты без ручного проектирования функций.

- **Управляемая генерация** – это задача управления языковой моделью для получения результатов с желаемыми свойствами: определенным стилем, темой, настроением, уровнем безопасности или фактической точностью. Модель должна следовать инструкциям, оставаясь при этом беглой и связной.

- **Руководство без классификаторов (CFG)** для текста адаптирует метод создания изображений. Во время обучения обуславливающий сигнал (например, подсказка) некоторое время отбрасывается случайным образом, обучая как условную, так и безусловную модель одновременно. При выводе выходные логиты интерполируются:

$$\text{logits}_{\text{guided}} = (1 + w) \cdot \text{logits}_{\text{conditional}} - w \cdot \text{logits}_{\text{unconditional}}$$

- где $w > 0$ усиливает влияние состояния. Более высокое значение $w$ приводит к тому, что выходные данные более точно соответствуют подсказке, но уменьшает разнообразие.

- **RLHF** (Reinforcement Learning from Human Feedback, Ouyang et al., 2022) — доминирующий метод согласования языковых моделей с человеческими предпочтениями. Процесс имеет три этапа:– Во-первых, **контролируемая точная настройка (SFT)**: точная настройка модели базового языка на наборе данных высококачественных написанных человеком ответов на подсказки.

- Во-вторых, **обучение модели вознаграждения**: соберите сравнения между людьми (с учетом подсказки $x$ и двух ответов $y_1, y_2$, что лучше?) и обучите модель вознаграждения $r_\phi(x, y)$ для прогнозирования предпочтений человека. Модель вознаграждения обучается с парной потерей рейтинга:

$$\mathcal{L}_{\text{RM}} = -\log \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))$$

- где $y_w$ — предпочтительный ответ, а $y_l$ — непредпочтительный.

- В-третьих, **тонкая настройка RL**: оптимизируйте языковую модель, чтобы максимизировать вознаграждение, оставаясь при этом близким к модели SFT (чтобы предотвратить коллапс режима). При этом используется PPO (оптимизация проксимальной политики, из главы 06) со штрафом KL:

$$\mathcal{L}_{\text{RL}} = -\mathbb{E}\left[r_\phi(x, y) - \beta \, D_{\text{KL}}(\pi_\theta \| \pi_{\text{SFT}})\right]$$

- Термин KL не позволяет модели слишком далеко отклоняться от базовой модели и использовать особенности модели вознаграждения («взлом вознаграждения»).

![RLHF Pipeline](../images/rlhf_pipeline.svg)

- **DPO** (Прямая оптимизация предпочтений, Рафаилов и др., 2023) упрощает RLHF, полностью исключая модель вознаграждения. Ключевая математическая идея заключается в том, что описанная выше цель RL с ограничениями KL имеет оптимальную политику в замкнутой форме:

$$\pi^\ast(y \mid x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y \mid x) \exp\!\left(\frac{r(x, y)}{\beta}\right)$$

- где $Z(x)$ - нормализующая функция разделения. Перестановка этого для получения награды дает $r(x, y) = \beta \log \frac{\pi^\ast(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)$. Подстановка этого неявного вознаграждения в модель предпочтений Брэдли-Терри $P(y_w \succ y_l) = \sigma(r(x, y_w) - r(x, y_l))$ приводит к отмене трудноразрешимых условий $Z(x)$, что приводит к прямым потерям DPO:

$$\mathcal{L}_{\text{DPO}} = -\log \sigma\!\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right)$$

- Это математически эквивалентно RLHF, но объединяет модель вознаграждения и обучение RL в один контролируемый шаг. 

- Выражение внутри сигмовидной кишки можно прочитать как: «увеличьте относительную вероятность предпочтительного ответа и уменьшите относительную вероятность непредпочтительного ответа, измеренную по сравнению с эталонной моделью». 

- Параметр $\beta$ определяет, насколько политика может отклоняться от эталона. На практике DPO проще реализовать (просто вычислить логарифмические вероятности для текущей и эталонной моделей для обоих заканчиваний) и позволяет избежать нестабильности обучения PPO.

- **Конституционный ИИ** (Бай и др., 2022) автоматизирует часть процесса согласования. Вместо сбора человеческих сравнений он использует саму языковую модель для критики и пересмотра собственных результатов в соответствии с набором принципов («конституцией»), таких как «выбрать менее вредный ответ». Сравнения, созданные искусственным интеллектом, затем используются для обучения предпочтениям (RLAIF: RL из обратной связи AI).

- **Методы с длинным контекстом** обращаются к памяти $O(n^2)$ и вычисляют стоимость стандартного самообслуживания, что ограничивает длину последовательности. Поскольку $n$ вырастает до десятков или сотен тысяч токенов, стандартное внимание становится невозможным.

- **Разреженное внимание** заменяет плотную матрицу внимания $n \times n$ разреженным шаблоном, в котором каждый токен обрабатывает только подмножество других токенов. Общие шаблоны включают **локальное внимание** (каждый токен обращается к окну соседей фиксированного размера), **ступенчатое внимание** (обращение к каждому $k$-му токену) и **случайное внимание** (обращение к случайному подмножеству). Комбинации этих шаблонов (используемые в BigBird, Longformer) достигают сложности $O(n)$ или $O(n \sqrt{n})$, сохраняя при этом возможность захвата как локальных, так и глобальных зависимостей.

![Sparse Attention Patterns](../images/sparse_attention_patterns.svg)

- **Внимание к скользящему окну** ограничивает доступ каждого токена только к предыдущим токенам $w$ (его локальному окну). Это $O(nw)$, а не $O(n^2)$, но информация на большие расстояния должна распространяться через перекрывающиеся окна между слоями. При использовании слоев $L$ и размера окна $w$ эффективным восприимчивым полем являются токены $L \times w$.- **Внимание к кольцу** распределяет длинные последовательности между несколькими устройствами, располагая их в кольцевой топологии. Каждое устройство хранит фрагмент последовательности и вычисляет внимание для своего фрагмента, одновременно отправляя блоки «ключ-значение» следующему устройству в кольце. Это перекрывает вычисления с передачей данных и позволяет использовать последовательности произвольной длины, ограниченные только общим объемом памяти всех устройств, а не памятью какого-либо отдельного устройства.

- **Модели с расширенной памятью** расширяют контекст, оснащая Трансформер внешним банком памяти. На каждом уровне модель может читать и записывать в эту память, используя внимание. Запоминание Трансформаторы кэшируют пары ключ-значение из предыдущих фрагментов и обрабатывают их в последующих фрагментах, эффективно расширяя контекст за пределы окна обучения. Извлечение является приблизительным (с использованием $k$-ближайших соседей по кэшированным ключам), чтобы обеспечить его эффективность.

- Вышеуказанные методы являются **архитектурными** решениями для длинного контекста. Не менее важно то, как модели **обучаются** эффективному использованию длинных контекстов.

- **Прогрессивное расширение контекста** — стандартный подход. Обучение на очень длинных последовательностях с самого начала непомерно дорого (стоимость внимания $O(n^2)$), поэтому модели предварительно обучаются на короткой длине контекста (обычно токены 4–8 КБ), а затем **продолжающееся предварительное обучение** поэтапно расширяется до целевой длины. 

- Llama 3.1 расширен с 8 до 128 КБ на 800 байт токенов с постепенным увеличением длины последовательности. DeepSeek-V3 обучается на 4К, затем расширяется до 32К, а затем до 128К. 

- На каждом этапе используется скромное количество токенов (относительно полного бюджета предварительного обучения), поскольку модели нужно только научиться использовать более длинные позиции, а не заново изучать язык.

- Кодирование положения должно быть скорректировано во время расширения. **Интерполяция RoPE** уменьшает индексы положения, чтобы модель видела те же углы поворота, на которых она обучалась, только распределенные по более длинной последовательности. Если модель была обучена длиной $L$ и вы хотите расширить ее до $L' = 4L$, вы делите все индексы позиций на 4. 

- Это означает, что модель никогда не видит угла поворота, с которым она не столкнулась, но эффективное разрешение между соседними позициями падает. 

- **Экстраполяция RoPE** сохраняет исходные индексы положения неизменными и просто применяет RoPE к позициям за пределами $L$, полагаясь на обобщение модели на невидимые углы. 

- Интерполяция намного стабильнее; экстраполяция быстро ухудшается без регулировки базовой частоты (ABF).

- **YaRN** (еще одно расширение RoPE) улучшает наивную интерполяцию, признавая, что не все измерения RoPE следует рассматривать одинаково. 

- Высокочастотные измерения (маленькие $i$ в $\theta_i = \theta_{\text{base}}^{-2i/d}$) вращаются много раз в пределах длины тренировки и могут хорошо экстраполироваться. 

- Низкочастотные размеры (большие $i$) вращаются медленно и более чувствительны к удлинению длины. 

- ЯРН интерполирует только низкочастотные измерения, экстраполирует высокочастотные и применяет к логитам внимания температурное масштабирование $t$ для компенсации сдвига распределения:

$$\text{score}'_{ij} = \frac{q_i^T k_j}{t \sqrt{d_k}}$$

- где $t > 1$ выравнивает распределение внимания, не позволяя модели слишком резко обращать внимание на близлежащие токены, когда сигналы положения сжимаются.

- **Курирование данных в длительном контексте** – это важная задача, которую часто недооценивают. Большинство корпусов подготовки к обучению состоят из коротких документов (новостных статей, веб-страниц, сообщений в социальных сетях). 

- Для обучения с длинным контекстом требуется набор данных, который фактически реализует все контекстное окно: книги, репозитории кода, длинные научные статьи, многоэтапные журналы разговоров и объединенные тематически связанные документы. 

- Если модель обучается только на коротких документах, дополненных или упакованных для заполнения контекстного окна, она учится игнорировать удаленные токены, поскольку они никогда не имеют значения.

- **Упаковка последовательностей** – это метод повышения эффективности обучения: несколько документов объединяются в одну обучающую последовательность, чтобы избежать ненужных заполнений, а маски внимания предотвращают перекрестное внимание к документам.- Для обучения с длинным контекстом стратегия упаковки имеет значение: упаковка большого количества несвязанных коротких документов учит модель тому, что удаленные токены являются шумом, а упаковка меньшего количества действительно длинных документов учит ее использовать весь контекст.

- Известным типом сбоя является феномен **"потеряны посередине"** (Liu et al., 2023): языковые модели имеют тенденцию эффективно использовать информацию в начале и конце контекстного окна, но испытывают трудности с информацией, расположенной в середине. 

- Это напоминает эффект серийной позиции в человеческой памяти (первичность и новизна). 

- Частично это возникает из-за распределения обучающих данных (важная информация часто находится в начале или в конце документов), а частично из-за моделей внимания, которые концентрируются на соседних и начальных токенах. 

- Длительное обучение с различным размещением ключевой информации смягчает, но не решает проблему полностью.

- Оценка **Иголка в стоге сена** проверяет, может ли модель извлечь конкретный факт («иголку»), помещенный в различные позиции в длинном контексте отвлекающего фактора («стог сена»). 

- Модель с настоящей способностью работать с длинным контекстом должна обеспечивать почти идеальный поиск независимо от того, где находится игла. 

- Этот тест четко выявляет эффект «потерянного посередине» и используется для оценки методов расширения контекста.

- **Длинная контекстная точная настройка** после предварительного обучения использует целевые данные SFT: длинные многоэтапные диалоги, документирование контроля качества с доказательствами, разбросанными по тысячам токенов, подробное обобщение и понимание кода на уровне репозитория. 

- На этом этапе Qwen3 использует **двойное внимание к фрагментам (DCA)**, которое обрабатывает длинные последовательности как пары фрагментов, где внимание внутри фрагментов заполнено, а внимание между фрагментами эффективно, достигая в 4 раза большей эффективной емкости последовательности во время точной настройки.

- **Модели пространства состояний (SSM)** предлагают принципиально иной подход к моделированию длинных последовательностей. Вместо того, чтобы модифицировать внимание, они полностью заменяют его линейной динамической системой, вдохновленной теорией управления в непрерывном времени. 

- SSM сопоставляет входную последовательность $u(t)$ с выходной $y(t)$ через скрытое состояние $x(t) \in \mathbb{R}^N$, управляемое:

$$x'(t) = Ax(t) + Bu(t), \quad y(t) = Cx(t) + Du(t)$$

- где $A \in \mathbb{R}^{N \times N}$ - матрица перехода состояний, $B \in \mathbb{R}^{N \times 1}$ - входная проекция, $C \in \mathbb{R}^{1 \times N}$ - выходная проекция, а $D$ - пропускное соединение. 

- Чтобы применить это к дискретным последовательностям (токенам), непрерывная система **дискретизируется** с использованием размера шага $\Delta$. Дискретизация удержания нулевого порядка дает:

$$\bar{A} = \exp(\Delta A), \quad \bar{B} = (\Delta A)^{-1}(\exp(\Delta A) - I) \cdot \Delta B$$

- Тогда дискретное повторение становится $x_k = \bar{A} x_{k-1} + \bar{B} u_k$, $y_k = C x_k + D u_k$, которое выглядит как RNN: обработка одного токена за раз со скрытым состоянием. 

- В отличие от RNN, это повторение также можно развернуть как **глобальную свертку**: поскольку система линейна, на выходе будет $y = \bar{K} \ast u$, где ядро ​​$\bar{K} = (C\bar{B}, \, C\bar{A}\bar{B}, \, C\bar{A}^2\bar{B}, \ldots)$ зависит только от фиксированных параметров. 

- Это **двойное представление** — повторение для эффективного авторегрессионного вывода ($O(1)$ на шаг) и свертка для эффективного параллельного обучения ($O(n \log n)$ посредством БПФ) — является центральным принципом SSM.

![SSM Dual View: recurrence for inference, convolution for training, and Mamba's selective extension](../images/ssm_dual_view.svg)

- **S4** (Пространства структурированных состояний для моделирования последовательностей, Гу и др., 2022) сделали SSM практичными, решив ключевую числовую задачу: матрица состояний $A$ должна фиксировать долгосрочные зависимости, но ее наивная параметризация приводит к исчезновению или взрыву динамики (та же проблема, что и у ванильных RNN). 

- S4 инициализирует $A$ с использованием матрицы **HiPPO** (операторы полиномиального проецирования высокого порядка), которая получена из теории оптимальной полиномиальной аппроксимации непрерывных сигналов. Матрица HiPPO имеет особую структуру, которая позволяет состоянию поддерживать сжатое представление всей истории ввода с плавным затуханием:

```math
A_{nk} = -\begin{cases} (2n+1)^{1/2}(2k+1)^{1/2} & \text{if } n > k \\ n+1 & \text{if } n = k \\ 0 & \text{if } n < k \end{cases}
```- Эта нижнетреугольная структура гарантирует, что состояние действует как онлайн-аппроксимация входного сигнала с использованием полиномов Лежандра. Вычисление $\bar{A}^k$ для длинных ядер требует больших затрат, поэтому S4 использует тот факт, что матрица HiPPO может быть разложена как сумма членов низкого ранга и диагональных членов, что позволяет выполнять вычисления ядра $O(n \log n)$.

- **Мамба** (Гу и Дао, 2023) представляет важное нововведение **выборочных пространств состояний**: делает параметры SSM зависимыми от входных данных. В S4 матрицы $A$, $B$, $C$ и размер шага $\Delta$ фиксированы — одна и та же динамика применяется к каждому токену независимо от его содержимого. Mamba создает функции ввода $B$, $C$ и $\Delta$:

$$B_k = \text{Linear}(u_k), \quad C_k = \text{Linear}(u_k), \quad \Delta_k = \text{softplus}(\text{Linear}(u_k))$$

— Такая избирательность позволяет модели в каждой позиции решать, какую информацию хранить в состоянии, а какую игнорировать — аналогично тому, как внимание выбирает соответствующие токены, но без квадратичной стоимости. Размер шага $\Delta_k$ управляет «воротами»: большой $\Delta$ заставляет состояние сильно интегрировать текущий вход (непрерывная динамика продвигается на большой шаг, эффективно сбрасывая состояние), тогда как маленький $\Delta$ сохраняет существующее состояние и игнорирует текущий вход.

- Компромисс заключается в том, что параметры, зависящие от входных данных, нарушают представление свертки (ядро больше не фиксировано), поэтому Mamba не может использовать обучение на основе БПФ. Вместо этого он использует **алгоритм параллельного сканирования с учетом аппаратного обеспечения**, который использует ассоциативность повторения: обновление состояния $(x_k, u_k) \mapsto x_{k+1}$ может быть выражено как последовательность ассоциативных операций и распараллелено с использованием суммы префиксов (сканирование), аналогично параллельному добавлению префиксов в аппаратном обеспечении. Это выполняется за время $O(n)$ с глубиной $O(\log n)$ на графическом процессоре, что почти соответствует эффективности свертки.

- Mamba обеспечивает вывод, который действительно $O(1)$ для каждого токена (просто обновляет состояние фиксированного размера, без KV-кеша, который растет с контекстом), что делает его существенно более эффективным с точки зрения использования памяти, чем Transformers при длинных последовательностях. Размер состояния $N$ (обычно 16) намного меньше, чем KV-кэш Transformer, в котором хранятся значения $O(n \cdot d)$. На практике Mamba соответствует или превосходит качество Transformer при том же количестве параметров в тестах языкового моделирования, обеспечивая значительно более быстрый вывод на длинных последовательностях.

- **Гибридные архитектуры** объединяют уровни SSM с уровнями внимания, используя SSM для большинства слоев (эффективное распространение на большие расстояния) и добавляя несколько уровней внимания (точное извлечение на основе контента). Такие модели, как Jamba и Zamba, чередуют блоки Mamba и Transformer, обеспечивая лучшее качество, чем чистые SSM, сохраняя при этом большую часть преимущества эффективности вывода. Это говорит о том, что внимание и SSM обладают взаимодополняющими возможностями: SSM превосходно справляются с плавным распространением состояний на большие расстояния, а внимание превосходно выполняет точный, зависящий от содержимого поиск.

- **Поисковая дополненная генерация (RAG)** устраняет ограничения знаний языковых моделей, предоставляя им доступ к внешней базе знаний во время вывода. Вместо того, чтобы во время обучения полагаться исключительно на знания, закодированные в параметрах модели, RAG извлекает соответствующие документы и генерирует на их основе условия.

- Классическая **архитектура чтения-считывания** состоит из двух компонентов. **Retriever** принимает запрос и извлекает из корпуса наиболее релевантные отрывки-$k$. **Читатель** (языковая модель) генерирует ответ, обусловленный как запросом, так и полученными отрывками. Средство извлечения может использовать разреженные методы (BM25, который расширяет TF-IDF из файла 02) или плотные методы.- **Плотный поиск отрывков (DPR)** использует архитектуру с двумя кодировщиками: один кодировщик отображает вопросы в векторы, другой отображает отрывки в векторы. Оба обычно основаны на BERT. Во время индексации все отрывки кодируются и сохраняются. Во время запроса вопрос кодируется, и ближайшие отрывки находятся с помощью приблизительного поиска ближайшего соседа (например, FAISS). Метрика сходства — это скалярное произведение векторов вопросов и отрывков.

- **Стратегии разделения** существенно влияют на качество поиска. Документы должны быть разделены на отрывки, достаточно маленькие, чтобы их мог обрабатывать искатель, но достаточно большие, чтобы содержать полные идеи. Разбиение на фрагменты фиксированного размера (например, 256 токенов с перекрытием по 50 токенов) является простым, но может привести к неудобному разделению предложений. Семантическое разбиение на блоки разделяется на границах абзацев или разделов. Иерархическое разбиение на блоки создает дерево сводок с разной степенью детализации.

![RAG Architecture](../images/rag_architecture.svg)

- RAG дает несколько преимуществ: базу знаний можно обновлять без переобучения модели, модель может ссылаться на источники, а галлюцинации уменьшаются, поскольку модель может основывать свои ответы на полученном тексте. Основными проблемами являются качество поиска (если извлекаются неправильные отрывки, модель может уверенно давать неправильные ответы) и задержка (извлечение добавляет шаг к выводу).

- **Спекулятивное декодирование** ускоряет генерацию авторегрессии за счет использования небольшой и быстрой **черновой модели** для параллельного предложения нескольких токенов, которые затем проверяются большой **целевой моделью** за один прямой проход.

— Алгоритм работает следующим образом: черновая модель генерирует токены-кандидаты $k$ авторегрессионно (это быстро, поскольку черновая модель небольшая). 

- Затем целевая модель оценивает все токены $k$ одновременно за один прямой проход (это эффективно, поскольку работа выполняется пакетно). 

- Для каждого токена-кандидата $t$, выбранного из черновой раздачи $p_d(t)$, он принимается с вероятностью $\min(1, \, p_{\text{target}}(t) / p_d(t))$. В случае отклонения исправленный токен повторно выбирается из **скорректированного распределения** $p_{\text{adj}}(t) = \max(0, \, p_{\text{target}}(t) - p_d(t))$, нормализованного.

- Эта схема принятия-отклонения гарантирует, что выходное распределение идентично только целевой модели. 

- Чтобы понять почему, рассмотрим эффективную вероятность выпуска токена $t$. Его можно принять напрямую (вероятность $p_d(t) \cdot \min(1, p_{\text{target}}(t)/p_d(t))$) или произвести путем повторной выборки. 

- Для токенов, где $p_{\text{target}}(t) \leq p_d(t)$, прямой прием вносит $p_{\text{target}}(t)$. Для токенов, где $p_{\text{target}}(t) > p_d(t)$, прямое принятие вносит вклад $p_d(t)$, а повторная выборка вносит остаток $p_{\text{target}}(t) - p_d(t)$ (после учета вероятности отклонения). 

- В обоих случаях общая вероятность выдачи $t$ равна $p_{\text{target}}(t)$. Черновой вариант модели влияет только на скорость, а не на качество.

![Speculative Decoding](../images/speculative_decoding.svg)

- Ускорение зависит от скорости принятия: если черновая модель хорошо согласована с целевой моделью, принимается большинство токенов, а время на настенных часах примерно соответствует черновому варианту модели. Типичное ускорение составляет 2-3 раза без ухудшения качества.

- **Medusa** (Cai et al., 2024) использует другой подход: вместо отдельной черновой модели она добавляет несколько облегченных прогнозных головок к самой целевой модели. Каждая голова одновременно предсказывает различную будущую позицию токена ($k = 1, 2, 3, \ldots$ на шаг впереди). На каждом этапе Medusa предлагает несколько вариантов продолжения, используя древовидную структуру, а один прямой проход через уровни внимания целевой модели проверяет, какие кандидаты последовательны. Это полностью исключает необходимость создания отдельного проекта модели.- Методы **параллельной генерации** в более широком смысле направлены на устранение узкого места последовательного авторегрессионного декодирования. Декодирование Якоби инициализирует все позиции с помощью предположений и параллельно итеративно уточняет их до сходимости, рассматривая генерацию как итерацию с фиксированной точкой. Неавторегрессионные модели (NAT) генерируют все токены одновременно за один прямой проход, но обычно страдают от ухудшения качества и требуют таких методов, как итеративное уточнение, потеря CTC или дистилляция знаний от авторегрессионных учителей, чтобы устранить разрыв.

- Вышеупомянутые методы — выравнивание, длинный контекст, извлечение, эффективное декодирование, модели пространства состояний — объединяются в современных производственных LLM.

- **Внимание по групповым запросам (GQA)** — наиболее широко распространенный метод повышения эффективности внимания. Стандартное многоголовочное внимание (MHA) поддерживает отдельные проекции ключа и значения для каждой головы, требуя кэширования значений $n_{\text{heads}} \times d_{\text{head}}$ для каждого токена. GQA группирует несколько заголовков запроса, чтобы использовать один заголовок «ключ-значение». 

- Благодаря 64 головкам запросов и 8 головкам KV (обычная конфигурация в Llama 3, Qwen, Gemma) каждая головка KV используется совместно 8 головками запросов, что сокращает кэш KV в 8 раз по сравнению с MHA. 

- Качество вывода почти идентично MHA, поскольку запросы по-прежнему могут обрабатывать разные шаблоны, просто они используют одно и то же подпространство «ключ-значение». Внимание к нескольким запросам (MQA) — это крайний случай, когда для всех запросов используется одна головка KV, но GQA обеспечивает лучший компромисс между качеством и эффективностью.

- **Multi-head Latent Attention (MLA)**, представленный в DeepSeek-V2, обеспечивает еще более агрессивное сжатие кэша KV. Вместо кэширования полных проекций значений ключа (даже с помощью GQA), MLA преобразует скрытое состояние в **скрытый вектор** низкого ранга $c_t \in \mathbb{R}^{d_c}$ с помощью $d_c \ll n_{\text{heads}} \times d_{\text{head}}$:

$$c_t = W_{\text{down}} \, h_t$$

- Кэшируется только этот сжатый вектор. Во время внимания полные представления ключей и значений восстанавливаются посредством восходящей проекции: $k_t = W_{\text{up}}^K c_t$, $v_t = W_{\text{up}}^V c_t$. В DeepSeek-V3 (всего 671 байт параметров, 37 байт активных) размерность сжатия равна $d_c = 512$ по сравнению с $128 \times 128 = 16{,}384$ для полного MHA, что означает сокращение кэша KV на 93%. 

— Тонкость: стандартный RoPE зависит от позиции и несовместим с общим сжатием, поэтому MLA использует **отделенный RoPE**: небольшой отдельный поток запроса и ключа (64 измерения на голову) передает информацию о позиции через RoPE, в то время как основная часть представления проходит через сжатый скрытый путь.

- **Кодирование положения в масштабе** значительно отличается от исходной синусоидальной схемы. Во всех пограничных моделях используется **RoPE** (файл 04), но с ключевыми изменениями для длинного контекста. Базовая частота $\theta_{\text{base}}$ в исходной формуле RPE $\theta_i = \theta_{\text{base}}^{-2i/d}$ обычно равна 10 000, что ограничивает экстраполяцию за пределы длины обучения. 

- **Скорректированная базовая частота (ABF)** просто увеличивает $\theta_{\text{base}}$ до 500 000 (Llama 3) или 1 000 000 (Qwen3, Gemma 3), растягивая периоды вращения, чтобы модель совершала меньше полных оборотов во время обучения и могла экстраполировать дальше. 

- **YaRN** (еще одно расширение RoPE) применяет частотно-зависимую интерполяцию: низкочастотные измерения интерполируются (уменьшаются), высокочастотные измерения экстраполируются, а температурный фактор регулирует распределение внимания. DeepSeek-V3, Qwen и Kimi K2 используют расширение на основе YaRN для получения контекста 128 КБ из моделей, предварительно обученных в 4K–8K.

- **iRoPE** (чередующийся RoPE), представленный в Llama 4, использует более радикальный подход: каждый четвертый уровень внимания не использует **вообще позиционное кодирование** (NoPE), в то время как другие уровни используют стандартный RoPE с фрагментированным вниманием. 

- Слои NoPE могут обрабатывать все позиции без какого-либо позиционного смещения, а слои RoPE обеспечивают локальный порядок. В сочетании с температурным масштабированием при выводе это обеспечивает контекстное окно Llama 4 Scout с 10 миллионами токенов — на порядки величины превосходя любой чистый подход RoPE.- **Масштабная смесь экспертов** стала доминирующей архитектурой для передовых моделей (в файле 04 представлены основные принципы MoE). Ключевыми решениями при проектировании являются количество экспертов, разреженность маршрутизации и балансировка нагрузки.

- **Разреженность маршрутизации** существенно различается: DeepSeek-V3 использует 256 экспертов с топ-8 маршрутизацией (разреженность 32x), Qwen3 использует 128 экспертов с топ-8 (разреженность 16x), Mixtral использует 8 экспертов с топ-2 (разреженность 4x), а Llama 4 Maverick использует 128 экспертов с топ-1 плюс общий эксперт (разреженность 128x). 

- Более высокая разреженность означает большее количество общих параметров для тех же активных вычислений, но требует более тщательной балансировки нагрузки и инфраструктуры связи.

- **Балансировка нагрузки без вспомогательных потерь** (DeepSeek-V3) заменяет традиционные потери балансировки нагрузки (файл 04), которые, как было обнаружено, ухудшают качество модели. Вместо этого каждый эксперт поддерживает динамическое смещение, корректируемое на каждом этапе обучения: у перегруженных экспертов смещение уменьшается (получают меньше жетонов), у недогруженных экспертов смещение увеличивается. Это обеспечивает сбалансированную маршрутизацию без каких-либо вспомогательных потерь, загрязняющих основной обучающий сигнал.

- **Общие эксперты** присутствуют в большинстве проектов MoE: один или несколько экспертных FFN, которые обрабатывают каждый токен независимо от маршрутизации. Они обрабатывают общие шаблоны, необходимые всем токенам (базовый синтаксис, функциональные слова), освобождая маршрутизируемых экспертов для специализации. Llama 4 использует 1 общего эксперта плюс 1 маршрутизируемого эксперта на каждый токен (очень редко); DeepSeek-V3 использует 1 общий и 8 маршрутизируемых.

- **Чередование плотных слоев и слоев MoE** обеспечивает еще одну ось дизайна. Gemma 2 и 3 чередуют локальный и глобальный уровни внимания (соотношение 5:1 в Gemma 3, где локальные уровни используют скользящее окно из 1024 токенов и только глобальные уровни кэшируют полный контекст размером 128 КБ). 

- Llama 4 Maverick чередует плотные слои FFN со слоями MoE. Kimi K2 использует слои гибридной разреженности (один плотный слой, вкрапленный среди экспертных слоев). Эта гетерогенная конструкция позволяет различным слоям выполнять разные функции.

- **Прогнозирование нескольких токенов (MTP)**, используемое в DeepSeek-V3, обучает модель прогнозировать не только следующий токен, но и токен, следующий за ним. В каждой позиции вторичный модуль прогнозирования (совместно использующий вложения основной модели) прогнозирует один дополнительный будущий токен. Потери MTP оцениваются в 0,1–0,3 относительно основной потери следующего токена. Помимо улучшения качества представления во время обучения, головы MTP могут служить черновыми головками для спекулятивного декодирования во время вывода, обеспечивая бесплатное ускорение.

- **Дистилляция знаний** – это стратегия обучения, при которой результаты большой модели "учителя" направляют обучение меньшей модели "ученика". Джемма 2 и 3 широко используют дистилляцию: меньшие модели (2B, 4B) обучаются на 50-кратном объеме данных, оптимальном для вычислений, с распределениями вероятностей учителя в качестве мягких целей. Вот почему Gemma 3-4B по качеству соответствует Gemma 2-27B. 

- Потери при перегонке заменяют или дополняют стандартную перекрестную энтропию: ученик минимизирует расхождение KL между своим распределением продукции и распределением учителя:

$$\mathcal{L}_{\text{distill}} = D_{\text{KL}}(p_{\text{teacher}}(\cdot \mid x) \| p_{\text{student}}(\cdot \mid x))$$

- DeepSeek-R1 превратил свою модель рассуждений 671B в плотные модели размером всего 1,5B, используя 800 тысяч тщательно отобранных образцов цепочки мыслей, создавая небольшие модели с непропорционально сильными рассуждениями.

- **Рассуждение с помощью обучения с подкреплением** представляет собой наиболее значительный прогресс в области LLM за последнее время. DeepSeek-R1 продемонстрировал, что чистое обучение с подкреплением на базовой модели (без контролируемой точной настройки) может вызвать цепочку мыслей, самопроверку и исправление ошибок — поведение, которое возникает спонтанно, когда модель вознаграждается за правильные окончательные ответы.

- DeepSeek-R1 использует **GRPO** (оптимизацию групповой относительной политики), которая исключает сеть создания ценности, необходимую для PPO. Для каждого запроса GRPO выбирает группу выходных данных $G$, вычисляет их вознаграждения и нормализует преимущества внутри группы:

$$A_i = \frac{r_i - \text{mean}(r_1, \ldots, r_G)}{\text{std}(r_1, \ldots, r_G)}$$

- Градиент политики затем использует эти групповые преимущества с урезанной целью (аналогично усечению PPO). 

- Устранение сети критиков вдвое снижает требования к памяти и вычислениям для обучения RL, что делает практичным обучение моделей с параметрами 671B с помощью RL.- Важный выбор при проектировании: DeepSeek-R1 использует **вознаграждение на основе правил** (проверка математических ответов на достоверность, выполнение тестовых примеров кода), а не нейронные модели вознаграждения, поскольку было обнаружено, что нейронные модели вознаграждения восприимчивы к взлому вознаграждения в таком масштабе.

- **Гибридный режим мышления Qwen3** объединяет рассуждения (с тегами `<think>` для пошаговой цепочки мыслей) и быстрый прямой ответ в единой модели, позволяя пользователям контролировать «бюджет мышления», который меняет задержку на глубину рассуждений. 

- Это достигается путем обучения как на мысленных, так и на немыслящих данных, а не с помощью отдельных контрольных точек модели.

- **Масштабная стабилизация обучения** требует новых методов, выходящих за рамки стандартных практик. **Мягкое ограничение Logit** (Gemma 2) передает оценки внимания через $s \cdot \tanh(\text{logits} / s)$ с мягким ограничением $s$ (обычно 30–50), чтобы предотвратить неограниченный рост. 

- **QK-Norm** (Qwen3) применяет RMSNorm к запросам и ключевым векторам перед вычислением оценок внимания, заменяя необходимость смещения QKV. **QK-Clip** (оптимизатор MuonClip от Kimi K2) отслеживает логит максимального внимания во время обучения и изменяет масштаб матриц весов ключей запроса, когда они превышают пороговое значение, обеспечивая стабильное предварительное обучение моделей с 1T-параметрами с нулевыми событиями нестабильности.

- **Обучение смешанной точности FP8** (DeepSeek-V3) использует 8-битную плавающую запятую для ресурсоемких умножений матриц в прямом и обратном проходах, сохраняя при этом основные веса с более высокой точностью. 

- Это примерно удваивает пропускную способность по сравнению с обучением BF16/FP16 с незначительной потерей качества. DeepSeek-V3 обучал свою модель с параметрами 671B всего за 2,8 миллиона графических часов H800 — часть сопоставимых моделей — во многом благодаря этой и другим инженерным оптимизациям.

1. Реализуйте простой конвейер генерации с расширенным поиском с нуля. Индексируйте набор документов с помощью TF-IDF (файл 02), извлекайте наиболее релевантный отрывок для запроса и добавляйте его к подсказке.
```python
import jax.numpy as jnp
import math
from collections import Counter

# Knowledge base: a set of short passages
knowledge_base = [
    "The Eiffel Tower is a wrought-iron lattice tower in Paris, France. It was constructed from 1887 to 1889 as the centerpiece of the 1889 World's Fair.",
    "The Great Wall of China is a series of fortifications built along the northern borders of China. Construction began in the 7th century BC.",
    "Photosynthesis is the process by which plants convert sunlight, water, and carbon dioxide into glucose and oxygen using chlorophyll.",
    "The theory of general relativity, published by Albert Einstein in 1915, describes gravity as the curvature of spacetime caused by mass and energy.",
    "Python is a high-level programming language known for its simple syntax and readability. It was created by Guido van Rossum and released in 1991.",
    "The mitochondria are organelles found in eukaryotic cells. They generate most of the cell's supply of ATP, used as a source of chemical energy.",
]

# Build TF-IDF index (reusing concepts from file 02)
def tokenise(text):
    return text.lower().split()

vocab = sorted(set(w for doc in knowledge_base for w in tokenise(doc)))
word2idx = {w: i for i, w in enumerate(vocab)}
V = len(vocab)
N = len(knowledge_base)

# Document frequencies
doc_freq = Counter()
for doc in knowledge_base:
    for w in set(tokenise(doc)):
        doc_freq[w] += 1

def tfidf_vector(text):
    words = tokenise(text)
    counts = Counter(words)
    vec = jnp.zeros(V)
    for w, c in counts.items():
        if w in word2idx:
            tf = 1 + math.log(c)
            idf = math.log(N / (doc_freq.get(w, 0) + 1))
            vec = vec.at[word2idx[w]].set(tf * idf)
    return vec

# Index all documents
doc_vectors = jnp.stack([tfidf_vector(doc) for doc in knowledge_base])

def cosine_sim(a, b):
    return jnp.dot(a, b) / (jnp.linalg.norm(a) * jnp.linalg.norm(b) + 1e-8)

def retrieve(query, top_k=2):
    """Retrieve top-k most relevant passages for a query."""
    q_vec = tfidf_vector(query)
    sims = jnp.array([cosine_sim(q_vec, doc_vectors[i]) for i in range(N)])
    top_indices = jnp.argsort(-sims)[:top_k]
    return [(int(i), float(sims[i]), knowledge_base[int(i)]) for i in top_indices]

# Test retrieval
queries = [
    "Who built the Eiffel Tower?",
    "How do plants make food?",
    "What did Einstein discover?",
]

for query in queries:
    results = retrieve(query, top_k=1)
    print(f"\nQuery: '{query}'")
    for idx, sim, passage in results:
        print(f"  Retrieved (sim={sim:.3f}): '{passage[:80]}...'")

    # RAG-style prompt construction
    context = results[0][2]
    rag_prompt = f"Context: {context}\n\nQuestion: {query}\nAnswer:"
    print(f"  RAG prompt:\n    {rag_prompt[:120]}...")
```

2. Реализуйте спекулятивное декодирование с помощью игрушечного проекта и целевой модели. Покажите, что принятый результат соответствует распределению целевой модели.
```python
import jax
import jax.numpy as jnp

# Simulate a draft model (fast, less accurate) and target model (slow, accurate)
vocab_size = 8
seq_len = 5

key = jax.random.PRNGKey(42)

# Target model: returns logits given a sequence
def target_model(seq, key):
    """Simulated target model: produces token logits (expensive)."""
    # In practice this would be a large Transformer forward pass
    k1, k2 = jax.random.split(key)
    logits = jax.random.normal(k1, (len(seq), vocab_size)) * 2
    # Make it somewhat predictable: bias toward token (seq[-1] + 1) % vocab_size
    for i in range(len(seq)):
        logits = logits.at[i, (seq[i] + 1) % vocab_size].add(3.0)
    return logits

def draft_model(seq, key):
    """Simulated draft model: similar but noisier (cheap)."""
    k1, k2 = jax.random.split(key)
    logits = jax.random.normal(k1, (len(seq), vocab_size))
    for i in range(len(seq)):
        logits = logits.at[i, (seq[i] + 1) % vocab_size].add(2.0)
    return logits

def sample_token(logits, key):
    return jax.random.categorical(key, logits)

def speculative_decode(prefix, draft_steps=3, key=jax.random.PRNGKey(0)):
    """Speculative decoding: draft proposes, target verifies."""
    seq = list(prefix)
    total_accepted = 0
    total_proposed = 0

    for _ in range(4):  # generate 4 rounds
        key, *subkeys = jax.random.split(key, draft_steps + 3)

        # Draft model proposes draft_steps tokens
        draft_tokens = []
        draft_probs = []
        draft_seq = list(seq)
        for i in range(draft_steps):
            d_logits = draft_model(jnp.array(draft_seq), subkeys[i])
            d_probs = jax.nn.softmax(d_logits[-1])
            tok = sample_token(d_logits[-1], subkeys[i])
            draft_tokens.append(int(tok))
            draft_probs.append(d_probs)
            draft_seq.append(int(tok))

        # Target model scores all draft tokens in one pass
        target_logits = target_model(jnp.array(draft_seq), subkeys[draft_steps])
        target_start = len(seq) - 1  # position of last prefix token

        # Accept/reject each draft token
        accepted = 0
        for i in range(draft_steps):
            t_probs = jax.nn.softmax(target_logits[target_start + i])
            d_prob = draft_probs[i][draft_tokens[i]]
            t_prob = t_probs[draft_tokens[i]]

            # Accept with probability min(1, target_prob / draft_prob)
            accept_prob = jnp.minimum(1.0, t_prob / (d_prob + 1e-10))
            key, accept_key = jax.random.split(key)
            if jax.random.uniform(accept_key) < accept_prob:
                seq.append(draft_tokens[i])
                accepted += 1
            else:
                # Reject: sample from adjusted distribution
                key, resample_key = jax.random.split(key)
                adjusted = jnp.maximum(0, t_probs - draft_probs[i])
                adjusted = adjusted / (adjusted.sum() + 1e-10)
                new_tok = jax.random.categorical(resample_key, jnp.log(adjusted + 1e-10))
                seq.append(int(new_tok))
                break

        total_accepted += accepted
        total_proposed += draft_steps

    return seq, total_accepted, total_proposed

# Run speculative decoding
prefix = [0, 1]
result_seq, accepted, proposed = speculative_decode(prefix)
acceptance_rate = accepted / proposed if proposed > 0 else 0

print(f"Prefix: {prefix}")
print(f"Generated sequence: {result_seq}")
print(f"Draft proposals: {proposed}")
print(f"Accepted: {accepted}")
print(f"Acceptance rate: {acceptance_rate:.1%}")
print(f"Speedup potential: {(accepted + proposed) / proposed:.2f}x")
```

3. Создайте простой цикл обучения DPO. Учитывая пары предпочтительных и непредпочтительных завершений, обновите небольшую модель, используя потерю DPO.
```python
import jax
import jax.numpy as jnp

# Tiny language model: linear projection from one-hot to logits
vocab_size = 10
seq_len = 4

key = jax.random.PRNGKey(42)
k1, k2 = jax.random.split(key)

# Current policy parameters (trainable)
theta = jax.random.normal(k1, (vocab_size, vocab_size)) * 0.1
# Reference policy parameters (frozen copy of initial theta)
theta_ref = theta.copy()

def log_prob_sequence(params, sequence):
    """Compute log P(sequence) under a simple autoregressive model."""
    total = 0.0
    for t in range(1, len(sequence)):
        # Simple: logits at position t depend on token at t-1
        logits = params[sequence[t-1]]
        log_probs = jax.nn.log_softmax(logits)
        total += log_probs[sequence[t]]
    return total

def dpo_loss(theta, theta_ref, preferred, dispreferred, beta=0.1):
    """Direct Preference Optimisation loss for one pair."""
    log_pi_w = log_prob_sequence(theta, preferred)
    log_pi_l = log_prob_sequence(theta, dispreferred)
    log_ref_w = log_prob_sequence(theta_ref, preferred)
    log_ref_l = log_prob_sequence(theta_ref, dispreferred)

    # DPO objective
    return -jax.nn.log_sigmoid(
        beta * ((log_pi_w - log_ref_w) - (log_pi_l - log_ref_l))
    )

# Preference dataset: (prompt_prefix, preferred_completion, dispreferred_completion)
preferences = [
    (jnp.array([1, 3, 5, 7]), jnp.array([1, 3, 5, 2])),  # prefer 7 over 2 at end
    (jnp.array([0, 2, 4, 6]), jnp.array([0, 2, 4, 9])),  # prefer 6 over 9
    (jnp.array([3, 3, 3, 3]), jnp.array([3, 3, 3, 0])),  # prefer repeating over 0
    (jnp.array([5, 6, 7, 8]), jnp.array([5, 6, 7, 1])),  # prefer 8 over 1
]

grad_fn = jax.jit(jax.grad(dpo_loss))
lr = 0.05

print("Training DPO...")
for epoch in range(100):
    total_loss = 0.0
    for preferred, dispreferred in preferences:
        loss = dpo_loss(theta, theta_ref, preferred, dispreferred)
        grads = grad_fn(theta, theta_ref, preferred, dispreferred)
        theta = theta - lr * grads
        total_loss += loss
    if (epoch + 1) % 20 == 0:
        avg_loss = total_loss / len(preferences)
        print(f"  Epoch {epoch+1}: avg DPO loss = {avg_loss:.4f}")

# Check: the model should now prefer the preferred completions
print("\nPreference check after DPO training:")
for preferred, dispreferred in preferences:
    lp_w = log_prob_sequence(theta, preferred)
    lp_l = log_prob_sequence(theta, dispreferred)
    print(f"  Preferred {list(preferred.astype(int))}: logP={lp_w:.3f}  "
          f"Dispreferred {list(dispreferred.astype(int))}: logP={lp_l:.3f}  "
          f"{'correct' if lp_w > lp_l else 'WRONG'}")
