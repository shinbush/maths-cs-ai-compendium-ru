# Linux и командная строка

*Командная строка является основным интерфейсом для проектирования машинного обучения: задания по обучению, управление серверами, конвейеры данных и администрирование кластера выполняются через терминал. В этом файле описаны оболочка, файловая система, разрешения, управление процессами, менеджеры пакетов, переменные среды, SSH и основные команды, которые каждый инженер ML использует ежедневно.*

- Графические интерфейсы удобны для просмотра веб-страниц. Они ужасно подходят для выполнения обучающего задания на удаленном кластере графических процессоров в 2 часа ночи. **Командная строка** (или терминал, или оболочка) — это инструмент, который масштабируется: он работает на любом компьютере, может быть написан по сценарию, компонуется и одинаков на вашем ноутбуке, облачной виртуальной машине и кластере HPC.

- Если вы инженер машинного обучения, который использует только блокноты Jupyter и кнопки VS Code, вы теряете огромную производительность. Каждая производственная система ML развертывается, отслеживается и отлаживается с помощью командной строки.

## Оболочка

- **Оболочка** — это программа, которая читает от вас команды и выполняет их. Это посредник между вами и операционной системой (глава 13). Наиболее распространенными оболочками являются **bash** (по умолчанию в большинстве систем Linux) и **zsh** (по умолчанию в macOS).

- Команда имеет вид: `command [options] [arguments]`.

```bash
ls -la /home/user    # command=ls, options=-la, argument=/home/user
```

- Опции изменяют поведение (обычно с префиксом `-` для короткой формы или `--` для длинной формы). `ls -l` отображает списки в длинном формате, `ls --all` показывает скрытые файлы. Многие параметры можно комбинировать: `ls -la` означает `-l` и `-a` вместе.

### Основная навигация

```bash
pwd                 # print working directory (where am I?)
ls                  # list files in current directory
ls -la              # list all files (including hidden) with details
cd /path/to/dir     # change directory
cd ..               # go up one level
cd ~                # go to home directory
cd -                # go back to previous directory
```

### Операции с файлами

```bash
cp source dest      # copy file
cp -r dir1 dir2     # copy directory recursively
mv old new          # move/rename file
rm file             # delete file (no recycle bin — gone forever)
rm -rf dir          # delete directory recursively (DANGEROUS — no confirmation)
mkdir -p a/b/c      # create nested directories
touch file.txt      # create empty file (or update timestamp)
cat file.txt        # print file contents
head -n 20 file     # first 20 lines
tail -f logfile     # follow a log file in real-time (invaluable for monitoring training)
```

- **Подводный камень**: `rm -rf` — самая опасная команда в вычислительной технике. Отмена невозможна. Трижды проверьте путь, прежде чем нажимать Enter. Никогда не запускайте `rm -rf /` или `rm -rf ~`.

### Каналы и перенаправление

- Отличительной особенностью оболочки является **компонуемость**: небольшие команды, объединенные вместе, выполняют сложные задачи.

- **Pipe** (`|`): отправляет выходные данные одной команды в качестве входных данных для следующей.

```bash
cat training.log | grep "loss" | tail -5    # last 5 lines containing "loss"
ps aux | grep python                        # find running Python processes
history | grep "docker"                     # find previous docker commands
```

- **Перенаправление**: отправка вывода в файл, а не на экран.

```bash
python train.py > output.log 2>&1    # stdout AND stderr to file
python train.py >> output.log        # append (don't overwrite)
echo "data" > file.txt               # overwrite file
echo "more" >> file.txt              # append to file
```

- `2>&1` перенаправляет stderr (дескриптор файла 2) на стандартный вывод (дескриптор файла 1). Без этого сообщения об ошибках по-прежнему появляются на экране, тогда как в файл поступает только обычный вывод.

### Обработка текста

```bash
grep "error" logfile.txt             # find lines containing "error"
grep -r "import torch" src/          # search recursively in directory
grep -i "warning" log.txt            # case-insensitive search
grep -c "epoch" train.log            # count matching lines

wc -l file.txt                       # count lines
wc -w file.txt                       # count words

sort data.txt                        # sort lines alphabetically
sort -n numbers.txt                  # sort numerically
sort -u data.txt                     # sort and remove duplicates
uniq -c sorted.txt                   # count consecutive duplicates

cut -d',' -f2,3 data.csv            # extract columns 2 and 3 from CSV
awk '{print $1, $3}' data.txt       # print 1st and 3rd whitespace-separated fields
sed 's/old/new/g' file.txt          # replace all occurrences of "old" with "new"
```

- Прекрасно сочиняют:

```bash
# Find the 10 most common error types in a log file
grep "ERROR" app.log | awk -F': ' '{print $2}' | sort | uniq -c | sort -rn | head -10
```

### Поиск файлов

```bash
find . -name "*.py"                  # find all Python files
find . -name "*.pyc" -delete         # find and delete compiled Python files
find /data -size +100M               # files larger than 100 MB
find . -mtime -1                     # files modified in the last 24 hours

which python                        # where is the python executable?
locate filename                      # fast file search (uses pre-built index)
```

## Иерархия файловой системы

- Linux организует все в одном дереве с корнем `/`:

| Каталог | Цель |
|-----------|---------|
| `/` | Корень всей файловой системы |
| `/home/user` | Ваши личные файлы, конфиги, проекты |
| `/etc` | Общесистемные файлы конфигурации |
| `/usr` | Пользовательские программы, библиотеки, документация |
| `/usr/local` | Локально установленное программное обеспечение (не из менеджера пакетов) |
| `/var` | Переменные данные: логи (`/var/log`), базы данных, кэши |
| `/tmp` | Временные файлы (очищаются при перезагрузке) |
| `/opt` | Дополнительное стороннее программное обеспечение |
| `/proc` | Виртуальная файловая система, предоставляющая информацию о ядре и процессах |
| `/dev` | Файлы устройств (здесь отображаются диски, графические процессоры) |

- Для машинного обучения: данные обучения обычно находятся в `/data` или `/home/user/data`, модели — в `/home/user/models`, а CUDA — в `/usr/local/cuda`. Устройства графического процессора отображаются как `/dev/nvidia0`, `/dev/nvidia1` и т. д.

## Разрешения для файлов

- Каждый файл и каталог имеет три типа разрешений для трех классов пользователей:

| Разрешение | Файл | Каталог |
|------------|------|-----------|
| **р** (читать) | Посмотреть содержимое | Содержание списка |
| **w** (писать) | Изменить содержимое | Создание/удаление файлов внутри |
| **x** (выполнить) | Запустить как программу | Войдите (перейдите в) каталог |

- Три класса пользователей: **владелец** (u), **группа** (g), **другие** (o).

```bash
ls -l script.py
# -rwxr-xr-- 1 henry ml_team 2048 Mar 28 script.py
#  ^^^         owner permissions: rwx (read, write, execute)
#     ^^^      group permissions: r-x (read, execute, no write)
#        ^^^   others permissions: r-- (read only)
```

```bash
chmod 755 script.py       # owner=rwx, group=rx, others=rx
chmod +x script.py        # add execute permission for everyone
chmod u+w,g-w file.txt    # add write for owner, remove write for group
chown henry:ml_team file  # change owner and group
```- **Подводная ошибка**: скрипт Python с `#!/usr/bin/env python3` вверху требует разрешения на выполнение (`chmod +x`) для запуска от имени `./script.py`. Без него необходимо использовать `python3 script.py`.

## Управление процессами

- **процесс** — это работающая программа (глава 13). Оболочка предоставляет вам инструменты для управления ими:

```bash
ps aux                    # list all running processes
ps aux | grep python      # find Python processes
top                       # real-time process monitor (CPU, memory)
htop                      # better version of top (install separately)
nvidia-smi                # GPU usage (essential for ML)
watch -n 1 nvidia-smi     # refresh nvidia-smi every second

kill PID                  # gracefully terminate process
kill -9 PID               # force kill (use when graceful fails)
killall python            # kill all Python processes

# Run in background
python train.py &                    # run in background
nohup python train.py > log.txt &    # run in background, survive logout
```

- **`nohup`** имеет решающее значение для обучения машинному обучению: без него закрытие SSH-соединения приведет к прекращению обучения. `nohup` отключает процесс от терминала.

- **`screen`** и **`tmux`** — это терминальные мультиплексоры, создающие постоянные сеансы. Вы можете запустить задание обучения в сеансе tmux, отключиться от SSH, повторно подключиться позже, и сеанс (и обучение) все еще продолжается.

```bash
tmux new -s training          # create named session
# ... start training ...
# Ctrl+B, then D              # detach from session
tmux attach -t training       # reattach later (even after SSH reconnect)
tmux ls                       # list sessions
```

## Менеджеры пакетов

- **Системные пакеты** (программное обеспечение на уровне ОС):

```bash
# Debian/Ubuntu
sudo apt update               # refresh package list
sudo apt install htop         # install a package
sudo apt upgrade              # upgrade all packages

# macOS
brew install wget             # install via Homebrew
```

- **Пакеты Python**:

```bash
pip install torch             # install from PyPI
pip install -e .              # install current project in editable mode
pip install -r requirements.txt  # install from requirements file
pip freeze > requirements.txt    # export installed packages

# Conda (for complex dependencies like CUDA)
conda create -n myenv python=3.11
conda activate myenv
conda install pytorch torchvision cudatoolkit=12.1 -c pytorch
```

- **Подводная ошибка**: никогда не используйте `pip install` в системном Python. Всегда используйте виртуальную среду (`python -m venv env`, `conda create` или `uv venv`). Системный Python используется инструментами ОС; его нарушение может сломать вашу систему.

## Переменные среды

- **Переменные среды** — это пары ключ-значение, доступные всем программам. Они настраивают поведение без изменения кода.

```bash
export CUDA_VISIBLE_DEVICES=0,1    # use only GPUs 0 and 1
export PYTHONPATH=/home/user/src   # add to Python's import path
export WANDB_API_KEY=abc123        # API key for Weights & Biases

echo $PATH                         # see current PATH
export PATH=$PATH:/usr/local/cuda/bin  # add CUDA to PATH
```

- **`.bashrc`** (или `.zshrc`): команды выполняются каждый раз, когда вы открываете оболочку. Поместите сюда свои утверждения `export`, чтобы они сохранились.

- **Файлы `.env`**: переменные, специфичные для проекта, загружаемые такими инструментами, как `python-dotenv`. Храните секреты (ключи API, пароли базы данных) в `.env` и добавляйте `.env` в `.gitignore`. Никогда не передавайте секреты в git.

## SSH (безопасная оболочка)

- **SSH** соединяет вас с удаленными компьютерами по зашифрованному каналу. Таким образом вы получаете доступ к облачным виртуальным машинам, серверам графических процессоров и кластерам HPC.

```bash
ssh user@hostname              # connect to remote machine
ssh -i ~/.ssh/key.pem user@ip  # connect with specific key
ssh -L 8888:localhost:8888 user@server  # port forwarding (Jupyter on remote)
```

- **Ключи SSH** (пара открытого/закрытого ключей) заменяют пароли:

```bash
ssh-keygen -t ed25519          # generate key pair
ssh-copy-id user@server        # copy public key to server
# now you can SSH without typing a password
```

- **Конфигурация SSH** (`~/.ssh/config`) сохраняет сведения о соединении:

```
Host gpu-server
    HostName 10.0.1.42
    User henry
    IdentityFile ~/.ssh/gpu_key
    LocalForward 8888 localhost:8888
```

- Теперь `ssh gpu-server` автоматически подключается со всеми этими настройками.

- **`scp`** и **`rsync`** переносят файлы между компьютерами:

```bash
scp model.pt user@server:/data/models/     # copy file to remote
scp -r user@server:/data/results/ ./       # copy directory from remote
rsync -avz --progress data/ user@server:/data/  # sync with progress (smarter than scp)
```

## Памятка по основным командам машинного обучения

```bash
# GPU monitoring
nvidia-smi                                   # GPU usage snapshot
watch -n 1 nvidia-smi                        # live monitoring
gpustat                                      # cleaner GPU overview (pip install gpustat)

# Training management
nohup python train.py > train.log 2>&1 &     # background training that survives logout
tail -f train.log                            # monitor training output
kill %1                                      # kill last background job

# Disk usage (datasets are huge)
df -h                                        # disk space on all mounts
du -sh /data/*                               # size of each item in /data
du -sh --max-depth=1 .                       # size of subdirectories

# Memory
free -h                                      # RAM usage
cat /proc/meminfo                            # detailed memory info

# Network
curl -O https://example.com/dataset.tar.gz   # download file
wget https://example.com/model.bin           # alternative downloader
curl -X POST http://localhost:8080/predict \
    -H "Content-Type: application/json" \
    -d '{"text": "hello"}'                   # test a model serving endpoint

# Archives
tar -czf archive.tar.gz directory/           # compress
tar -xzf archive.tar.gz                      # extract
zip -r archive.zip directory/                # zip
unzip archive.zip                            # unzip

# Quick data inspection
head -5 data.csv                             # first 5 lines of CSV
wc -l data.csv                               # count rows
cut -d',' -f1 data.csv | sort -u | wc -l    # count unique values in column 1
```
